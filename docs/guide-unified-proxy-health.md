# 统一代理健康巡检

入口：**代理 → 代理健康巡检 → 配置健康巡检**。原设置页提供跳转，不再启动或配置另一套自动清理器。旧 HTTP 设置字段仍是兼容别名。

## 两层、一个处置模式

- **基础网络巡检**无需账号，动态覆盖全部启用代理。新增／订阅补充的代理自动纳入后续轮次；检查主模型、备用模型和计费域的站点可达性、防护拦截及耗时。
- **模型巡检**自动覆盖全部启用线路，并按近期可靠性从合格账号中自动挑选；周期配置不再要求选择目标、参考或专用账号。基础网络层开启时，真实模型派发前先确认网络；缺账号时模型保持待检，不停止基础维护。
- **仅观察**同时约束两层；从 `v2.10.14-go` 起还约束断流、登录失败清理和业务严格归因等新故障自动删除，不因这些删除连带改派。**自动处置**仍须满足各自判据和节点保护；网络使用二次复核，模型使用已有 405 严格对照。

网络与模型周期可分别设置为 1–1440 分钟，默认 30 分钟。网络默认等待 10 秒后复核，可设 1–300 秒；模型原有十分钟对照窗口和账号冷却不随网络复核时间缩短。

## 计费异常与默认出口保护（v2.10.14-go）

- 余额查询、套餐领取和资格预览的超时、传输失败、代理认证失败及领取可疑请求，只保留原错误并报告观测结果，不再直接删除共享节点或改派业务账号。成功额度快照、领取成功记录与既有冷却继续保留。
- 基础网络层开启时，有效请求身份的异常会请求一次独立网络复核。每节点合并通知、两次消费至少间隔五分钟；通知十分钟过期，最多保留 1,024 个节点，不跨重启续用，也不把计费失败计作网络首轮证据。网络层关闭时仅记录，不擅自开启巡检或真实模型请求。
- 首轮网络检查、延迟复核与健康参考仍须重新执行。网络通过只能说明无凭据探测可达，不能把计费错误说成已经恢复，也不证明模型业务成功；额度恢复以实际额度查询成功为准。
- 当前新号策略选择的默认业务代理，以及仍被托管任务引用的默认出口自动受保护；同路由别名也受保护。临时关闭新号策略不解除已选默认出口的保护。已有默认节点升级后无需重新勾选。
- 代理新增／编辑页提供「禁止自动删除」。当前页面新增手工节点默认勾选，既有普通节点保持原设置。保护字段为 `auto_delete_protected`；旧 API 新增省略时沿用未保护语义，更新省略时保留原值。列表的 `auto_delete_protection` 展示有效原因。
- 受保护节点仍可检查和显示异常；确认异常后显示「网络异常，受保护未删除」，不冒充健康。该补丁不自动停用受保护节点，也不强迫固定出口账号直连；管理员仍可显式停用、编辑或删除。
- 只有普通节点解除手工保护后才可能自动删除；默认／托管默认出口须先调整对应策略或解除托管。修改手工保护会废弃旧线路代次证据。
- 观察模式和保护只阻止新自动删除决定；已持久化的严格退役恢复事务继续完成，不复活历史删除、不解除账号冷却。历史上已被删除的家庭节点仍需管理员重新添加并配置默认出口。

计费结果中的 `proxy_failure_action` 区分 `recheck_pending`（等待复核）、`observed`（仅记录）、`rate_limited`（等待最短重查间隔）、`stale_snapshot`（旧身份不采用）、`initializing` 和 `ignored`。服务中的统一管理器消费运行期通知；独立 CLI 不自行启动后台巡检，也不承诺退出后续跑。

## 全节点主动巡检与账号自动择优（v2.10.12-go）

- **目标**：动态覆盖全部启用且未严格退役的线路，可用排除名单剔除个别模型目标。默认 200 次/24h、30 分钟间隔时每批最多 4 条，每30分钟推进下一批，完整轮转长度不再重复用作分批间隔。实际目标请求完成才更新复测时间，未出站任务保留待检。业务405提示单列优先诊断，仍受总预算与原诊断限制。
- **账号**：取得执行槽后才从全部合格 JWT 账号（未托管、额度已知且可用、不在冷却或风控静默期）中择优；先过滤预算耗尽、业务在途或其他巡检占用，再按近期可靠性与最久未被选中排序。账号留在业务池、持久绑定不被改写；初始化与固定出口托管账号不可借用。开始对照后冻结主体，不拼接不同凭据代次的证据。
- **统计**：业务与探测各保留最近20条、24小时内结果；业务的完整成功、限流、鉴权、平台错误与传输中断均纳入明确的原始分母，取消单列。排序结合六小时半衰期和样本平滑，线路／平台类错误不一律惩罚账号，探测坏节点的风控不污染业务成功率。更换凭据后旧窗口不再影响新凭据排名。
- **覆盖**：近30分钟业务成功仅作旁证，不代替主动请求。摘要独立显示主动覆盖、业务旁证、等待资源和网络异常；覆盖是参考轮转周期内实际检查过的目标数，不等于健康节点数。成功记录过期不会继续显示正常。
- **代价**：探测会消耗所选账号的少量额度；收到 405/3012 时该账号仍按现有规则进入冷却。单账号 24 小时请求预算（默认 100 次）封顶。
- **参考**：自动从其余启用线路中挑选独立参考（别名与已声明同出口组不互证）。**自动退役仍要求目标与参考都有出口组声明且不同组**，否则该目标只观察、不删除；合格账号不足两个时同样不删除。出口组在高级设置的“声明线路拓扑”中配置。
- **排除**：高级设置的排除名单只影响模型目标，网络巡检仍覆盖这些启用线路，它们也仍可作为参考。停用节点始终不参与。
- **迁移**：策略版本3将旧手工目标／专用账号转换为自动模式，解除旧专用角色，保留开关、预算、已用请求计数、显式排除、冷却与处置权限；旧管理客户端的手工模式仍作为兼容能力保留。

全部参与不等于每个节点都能按基础间隔完成一次。例如30个节点每30分钟全测一次，至少需要1440次/日，尚未包含复核；默认200次预算下需分批轮转。面板的周期是基础筛查的参考值，账号等待、异常对照与日预算会延后实际完成；系统不会用入队、跳过或业务旁证冒充主动检查完成。

## 网络异常如何处理

1. 首轮发现网络错误或防护拦截，只记录“等待复核”，不删除。
2. 等待指定间隔，再独立请求同一线路。
3. 恢复正常则保留；仍异常则刷新其他线路参考，缺少合格成功参考时检查无凭据直连。已知同出口组不得互相提供独立证明。
4. 目标两次异常、参考正常，才按观察／自动模式处置；参考也失败则保留，不清空代理池。

无凭据直连仅用于网络核查，不发送 Authorization、Cookie 或模型 Token；它不等于允许业务账号或固定出口账号走直连。网络探测不扣模型请求预算。

大池按最多 48 条分批、最多 8 路并发推进，避免单批长时间占用。每批网络执行预算五分钟，另加明确配置的复核等待时间；未完成或被取消的批次不提交删除。进程重启废弃半轮证据，不在启动瞬间清理全池。

模型出现连接失败／超时，可以触发网络复核，但**网络复核成功不会自动重放失败的模型请求**。只有管理员明确点击“立即健康检查”，网络通过后才可按原模型资格和预算接续模型检查；自动轮次不会绕过模型周期。

## 处置、记录与兼容

- 网络故障使用现有原子代理删除／改派机制，不冒记为永久 3012 禁止。模型 405 仍使用独立严格退役记录。
- 普通自动账号按原规则改派；固定业务代理的托管账号仍等待，不回到取额池或直连。已有业务流不因配置删除重放。
- 网络表格可查看首轮、复核、参考明细和处理记录；配置／线路代次改变后显示旧记录失效，不把旧成功当成新线路健康。
- 原单条／全部“网络测试”继续只读。新“立即健康检查”会执行当前处置策略，两者按钮含义不同。

### 升级迁移

- 原来仅有网络自动巡检：保留其启用状态、周期和自动处置，但增加强制复核；不会自动打开模型请求。
- 原来模型仅观察、网络却自动清理：保守合并成两层仅观察，面板显示迁移提示，需要管理员重新确认统一策略。
- 原模型自动处置保持其模式；不创建账号、不重置模型预算或冷却。
- v2.10.12-go策略版本3将旧手工配置升级为自动覆盖／自动选号，原专用角色释放回业务池；会扩大已启用模型巡检的候选范围，但不打开此前关闭的模型请求，也不额外授予自动退役或直连权限。迁移通知明确展示此变化。
- `proxy_health_enabled`、`proxy_health_interval` 仍可通过旧管理入口读写，但更新同一策略代次；旧轮次不能在修改之后删除代理。

统一管理端点沿用管理员鉴权：

- `GET /admin/api/proxies/health`：网络记录与模型摘要。
- `GET/PUT /admin/api/proxies/health/settings`：统一配置；旧模型配置路径兼容。
- `POST /admin/api/proxies/{profile_id}/health-check`：加入统一检查队列。

同一次 HTTP 成功只证明该次检查结果，网络可达不等于模型业务成功；这些检测均不证明供应商保证某个住宅出口永久可用。
