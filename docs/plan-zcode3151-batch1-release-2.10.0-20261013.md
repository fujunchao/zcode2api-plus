# 第一批 ZCode 3.15.1 兼容修补与 v2.10.0-go 发布计划

## 目标与基线

- 用户已确认实施第一批，并推送、发布 2.10.0；沿用仓库命名，应用版本及标签分别为 `2.10.0-go`、`v2.10.0-go`。
- 起点：`origin/go-rewrite` 的 `0fa31476d22636e993c762ef7021a2b4bae107e8`（v2.9.19-go）。
- 使用独立工作树，分支 `codex/zcode3151-release-2.10.0`。原工作区未跟踪资料不复制、不提交、不覆盖。
- GitHub CLI 显式指定 `--repo fujunchao/zcode2api-plus`；只推 origin，不修改 upstream。
- 现有源码调用链已经完成静态定位；本次不重复扩展逆向范围，以真实 HTTP 回归的远端红灯锁定缺口后修复。

## 一、接口契约

以下请求头属于账号/权益绑定材料，目前网关没有完整的订阅、高速卡与团队执行上下文：

- `X-Highspeed-Card-ID`
- `X-Bigmodel-Authorization`
- `Bigmodel-Target-Type`
- `Bigmodel-Organization`
- `Bigmodel-Project`

处理规则：

1. 鉴权仍优先；只有已通过网关鉴权的请求进入后续校验。
2. 三个同步推理入口发现任一上述请求头后返回 HTTP 400，`error.type=unsupported_account_context`，在选号、验证码、出站和账号状态修改之前结束。
3. 判断头名大小写不敏感，按字段是否存在而非非空值判断；多个值或空值不能绕过。
4. 错误只给出规范头名和功能未支持的说明，不回显令牌、卡 ID、组织或项目值。
5. 异步入口虽原本不会转发这些头，也在建票前按相同契约拒绝，避免把调用者以为的权益请求悄悄当普通计费请求执行；不带这些头的异步行为保持。
6. 上游请求构造器再校验一次，形成纵深保护；该类客户端错误不得被误判为池内账号凭据失效。
7. 普通 trace/session/query、Anthropic beta 和合法自定义头保持原有语义；不新增 HighSpeed 路由、签名或隐式降级。

## 二、版本范围

- `ZcodeClientVersion` 默认由 3.14.5 同步为 3.15.1，相关测试、注释、README 与环境样例同源更新。
- 保留显式 `ZCODE_CLIENT_VERSION`、`UPSTREAM_USER_AGENT` 覆盖。
- 保留 provider-utils 4.0.27、现有 Node 声明与固定提示词；不根据未运行核实的环境推断新值。
- 应用版本更新为 2.10.0-go，新增对应发布说明。
- 不改变风控静默、重试预算、并发、账号状态、额度业务和数据库格式。

## 三、已约定的回归边界

所有测试仅使用隔离目录、合成凭据和 httptest 环回服务，不读取 data/。

| 边界 | 断言 |
|---|---|
| POST /v1/messages | 卡上下文返回明确 400；零上游请求；普通请求照常成功 |
| POST /v1/chat/completions 与 /v1/responses | 与原生入口同一拒绝语义；JSON/SSE 请求均在出站前拒绝 |
| POST /async/v1/messages | 拒绝时不建票、不输出 ticket、不消耗上游；合法异步完整结束 |
| 换号与同号重试的真实 HTTP 出站 | 普通归因/允许头仍保留，主凭据按所选号重建；不把拒绝请求引入重试 |
| 请求构造公开接口 | 五类头大小写、空值及多头覆盖；拒绝结果不携带可用 URL/认证，也不修改输入 |
| 版本配置与来源头 | 默认 3.15.1，显式环境覆盖有效，模型/非模型 UA 保持既有分工 |

采用小步反馈：先加入一条原生 HTTP 卡头拒绝回归并推送，读取 GitHub Actions 的实际红灯日志；再修复这一公共边界，补其他入口和合法重试的对照，不在本机运行测试。

## 四、实施与发布顺序

1. 提交本计划和第一条回归，推工作分支；以远端失败日志确认当前确会接受不支持的卡上下文。
2. 实现统一校验、同步入口早拒绝、请求构造防线及异步建票前拒绝；补公开接口回归。
3. 同步 3.15.1 客户端标识、2.10.0-go 应用版本与升级说明；完成格式化和差异检查。
4. 推工作分支，使用 gh run watch 等待该提交完整 ci.yml，通过后才进入发布。
5. 确认 origin 默认分支没有未合入的新提交；仅快进已验证代码，不强推。若远端推进，先整合并重新验证。
6. 同一发布提交的分支 CI 通过后推 v2.10.0-go；发布仍必须经过 release.yml 复用的完整 ci.yml。
7. 发布结束核对五个二进制附件、发布说明、版本标签对应提交，以及 GHCR 的版本/latest 标签和 linux/amd64、linux/arm64 清单。

遇到失败先读对应日志，修复并重新验证，不删除测试、不跳过断言、不降低门禁。测试首个红灯不是发布验收结果；验收以最终提交的完整 CI 和实际发布状态为准。

## 五、本批明确不做

- 不接入随机 HighSpeed 卡、订阅双凭据、团队或完整回退状态机。
- 不修复第二批 SSE 多行用量/异步转发与 API Key 兑换业务 401 归因。
- 不复制桌面 Gen UI/MCP App、工作流、浏览器权限或飞书功能。
- 不声明修复供应商所有 405 风控，不调整现有风控静默策略。
- 不读取运行账号、向 CI 提交真实密钥或在本机执行自动化测试。
