# 新账号领取后刷新与双次空额度代理检测

## 目标与范围

- 保留新账号入池后的第一次额度查询；激活上报并完成可领取套餐处理后，再实际查询一次额度。
- 只允许本次真正新建的 JWT 账号触发检测：后台 OAuth 首次登录、粘贴 Token、批量新增共用规则。
- 已有账号重新登录、重复新增、手动领取、每日领取、历史账号和备份导入不触发本项代理淘汰。
- 第二次查询结束后，不循环更换代理、重新领取或继续淘汰；下一次常规额度监控使用改派后的线路。

## 判定与保护

1. 两次额度响应都必须是完整的 HTTP 200、业务码成功响应。网络失败、鉴权失败、取消、缺少必要字段、405 幂等回包和缓存命中不算两次空额度证据。
2. 按用户确认的保守口径：无套餐且没有已分配/已使用额度才属于未获初始配额；已有套餐但耗尽不等于代理异常。
3. 第二次查询必须在领取流程结束后启动，绕过 15 秒缓存；若已有查询在途，等待其完成后发起新请求，不复用领取前的请求。
4. 两次查询和领取使用的账号 ID、凭据与代理必须一致；期间有改派、修改代理地址、换令牌、成功使用、停用、归档或删除时放弃淘汰。
5. 领取成功、失败或没有可领套餐后均补查；不把领取失败本身当作代理问题。自动领取关闭、取消或账号已不适合自动领取时不执行淘汰。
6. 仅删除两次证据所指向的命名代理；直连和手工 URL 不进入代理池删除逻辑。
7. 复用现有原子事务及“空闲优先、否则绑定最少、同数按列表顺序”的改派策略，排除原 URL，无替代线路时明确记录直连回退。共享线路的所有关联账号一并改派，账号领取冷却与其他状态保持不变。

## 实施步骤

1. 补充端到端回归：领取后有额度、两次空额度、第一次有额度、老账号空额度、批量任务排队。
2. 推送工作分支，读取当前提交的 GitHub Actions 失败日志，确认现有缺口。
3. 增加强制额度查询及独立查询证据，接入新账号领取收尾；将旧的单次空额度风控删除改为新账号双次检测。
4. 补齐并发、缓存、旧账号、失败响应、关闭开关、取消、换线/换令牌、事务回滚、无可用代理等边界测试。
5. 本地只格式化与检查差异，全部构建、静态检查和自动化测试由 Ubuntu CI 执行。
6. 完整 CI 通过后合入当前默认分支；版本更新为 `2.9.6-go` 并提交发布说明。以最终提交的完整分支 CI 为门禁，推送 `v2.9.6-go` 标签。
7. 等待发布工作流复用完整 CI 并完成二进制、镜像发布；核对 5 个附件、amd64/arm64 镜像和远端标签。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 首次无额度，领取后有额度 | 两次真实查询；额度及时落库，不删除代理 |
| 首次有额度，领取后为空 | 不删除代理 |
| 首次、领取后都确认为未获初始配额 | 原子删除原代理并改派，保留领取状态 |
| 任一次失败、缺字段或返回未知值 | 不删除代理 |
| 同一账号已有查询/15 秒内缓存 | 第二次等待旧请求后重新出站，不复用旧结果 |
| 多个新账号同时添加 | 领取串行等待，每个符合条件的账号均完成收尾 |
| 老账号重登、手动/定时领取、重复添加、备份导入 | 不触发本项代理淘汰 |
| 期间改派、换令牌、使用、停用、归档、删除 | 不使用迟到证据删除代理 |
| 存储事务失败/并发重复淘汰 | 不发布半套状态；原代理至多删除一次 |
| 无替代代理/原地址别名 | 不选原 URL；必要时清除绑定并回退直连 |
| 服务停止或自动领取关闭 | 不误记失败、不误删代理，等待任务可取消 |
