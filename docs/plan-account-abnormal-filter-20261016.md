# 账号池异常分组实施计划

基线：`fb52634`（`v2.10.12-go`）。工作分支：`codex/account-abnormal-filter`。
目标补丁版本：`v2.10.13-go`，发布前重新核对远端版本。

## 范围与交互

- 顶部分组调整为「全部｜初始化｜用完｜异常（数量）｜停用」，沿用现有胶囊按钮、字号、间距和选中样式，不新增视觉体系。
- 「异常」使用已有 `invalid` 状态，不另建手工分组或持久化字段。风控失效、凭据失效及其他当前失效原因均纳入；已停用但仍保持 `invalid` 的账号也保留在异常组。
- 计数和列表继续共用现有状态口径：排除已归档账号，初始化阻塞优先归入初始化；临时冷却、本地隔离和仅保留历史错误的正常账号不视作异常。
- 与现有错误类型筛选取交集；选择「风控拦截」后仅展示风控失效账号。顶部分组数量仍表示全池非归档账号的该状态数量，不随错误类型筛选变化。
- 复用现有勾选和批量恢复／停用／删除。切换任一筛选清空勾选；批量操作只提交当前可见的选中账号，恢复仍由服务端逐条判定，凭据异常不得被当作风控失效恢复。
- 查询刷新后，恢复或进入冷却的账号自动退出异常列表；全池额度汇总不随筛选改变。
- 空列表提示「暂无符合筛选条件的异常账号」，不误导用户新增账号；分组按钮提供可访问的选中状态。

## 实施顺序

1. 补充前端行为回归并推送工作分支，在 GitHub Actions 确认缺少异常入口导致的失败。
2. 添加分组入口，保持后端风控、冷却、启停和恢复规则不变；依据远端日志修正实现或测试夹具，不降低断言。
3. 更新版本常量、README 和发布说明；本机只生成必须提交的 `frontend/dist`，自动化测试、类型检查和静态检查全部交给远端。
4. 等待最终提交的完整分支 CI 成功，再快进推送默认分支并发布版本标签。发布工作流必须再次通过同一套完整 CI。
5. 核对标签提交、Release 五个平台二进制、GHCR 版本／latest 镜像及双架构清单后报告完成。

## 验收边界

- 异常计数、零数量入口、归档隔离、初始化优先级和历史错误排除。
- 异常与风控错误筛选组合、切换筛选清空勾选、全池额度保持不变。
- 批量停用／删除只处理当前筛选集合，删除必须经过确认。
- 混合恢复如实展示逐条失败，列表和数量随查询刷新更新。
- 只使用合成账号和接口响应，不读取 `data/` 或真实账号；不提交既有 `.gitignore` 改动与无关未跟踪文档。
