# 按模型独立汇总额度

日期：2026-10-02；目标版本：`v2.9.3-go`。

## 分析结论

- 支持模型由 `internal/gateway/classify.go` 的 `AvailableModels` 定义：`glm-5.3-flash`、`GLM-5.3`。
- `internal/quota/quota.go` 已把上游套餐余额保存为按模型、套餐区分的 `Account.Quota`；数值包含 `total`、`used`、`remaining`。
- `Account.QuotaEntriesForModel`、`ModelAvailability` 和存储选号逻辑已经按模型匹配、隔离耗尽状态，不需要重写计费或调度。
- 问题位于仪表板：遍历所有账号的所有额度项目，跨模型累加 `remaining`，只呈现一张“剩余额度”卡片。
- `/status` 的 `quota_pool` 是提供商的可用账号数量，不是额度，不能改字段含义。

## 实施方案与统计口径

1. 在 model 模块提供只读汇总函数 `SummarizeModelQuotas`，复用现有精确模型匹配；不要用前缀匹配把 Flash 计入主模型。
2. `/admin/api/status` 增加 `model_quotas` 数组，保持旧字段不变。一次取得全池独立快照，同时计算账号数量与模型额度；不额外请求上游。
3. 数组按支持模型清单排序，每个模型包含 `model`、`total`、`used`、`remaining`、`accounts`、`items`、`partial`。
4. 同一模型跨账号、跨套餐累加，账号数按该模型去重，额度项目数按套餐记录计数。优先取额度记录的 `model`，缺失时兼容旧快照的键名；大小写、下划线、空格按现有规则归一化。
5. 排除归档账号；保留其他账号的账面快照，包括停用、冷却、失效及禁用/耗尽模型。**账面剩余不等于当前可调度额度**，页面明确说明。没有快照的账号不虚构余额，未知模型不分摊给两个已知模型。
6. 数值允许合法数字字符串；缺失、负数、非数字、NaN/Infinity 及累加溢出忽略并标记 `partial`。某字段没有任何有效数据时返回 `null`，有效零保留 `0`。不通过减法猜测缺失数据。
7. 仪表板去掉混合额度卡，在原有指标下方放两张独立模型卡：突出剩余，旁列总额和已用，展示账号/项目数量。无快照提示刷新；部分数据注明仅汇总已知数值，不展示不可靠百分比。保留 10 秒轮询及手动刷新。

## 设计与兼容性

- 沿用现有白底、中性色卡片和系统字体；模型名用等宽字体、数字用等宽数字，余额进度使用既有绿色/琥珀色语义。
- 桌面并排比较两个模型，窄屏堆叠；不引入图表依赖、图片或无关动效。
- 不改变数据库表、账号 JSON、实际请求 Token 统计、上游客户端版本、额度查询与调度规则。
- 这是快照汇总，不新增本地自定义硬限额，不把真实请求用量从上游余额再次扣除。
- 不修改或提交工作区原有 `.zcode/`、`.zcodeignore`、`docs/analysis-flash-30min-stream-cut.md`。
