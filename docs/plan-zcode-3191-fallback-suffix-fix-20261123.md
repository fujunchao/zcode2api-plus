# ZCode 3.19.1 回退模板与块内后缀修复方案

日期：2026-11-23。基线：`dce8ff1`，产品版本 `2.14.3-go`。目标版本：`2.14.4-go`。

## 问题与目标

关闭 `ZCODE_PRESERVE_CLIENT_CONTEXT` 后，3.18.2 客户端第三块若为“3180 官方底座 + 两个换行 + 自定义指令”，升级后的回退逻辑只能识别完整静态块或旧式 Environment 包裹结构。当前底座已经是 3191，因此旧底座连同后缀一起并入新第三块，重复加入约 1.6 KB 文本并带回旧版 `<total_tokens>` 提示。

修复后应输出“当前官方第三块 + 自定义后缀”，保留后续独立指令的顺序和内容，且重复规范化不会继续叠加模板。

## 实现

1. 在已知模板的一次性解析中，单独登记各档案静态第三块的完整文本，覆盖 3180 与 3191；旧档案的运行时 Environment 识别继续复用现有逻辑。
2. 仅在 `stripOfficialSystemPrefix` 已确认首两块为已知官方前缀和身份段后，尝试完整静态底座的字节前缀匹配。多个底座都匹配时取最长匹配，不按标题、关键词或版本区间删除。
3. 精确切除底座和至多一个用于拼接的双换行，保留后缀的其余空白、后续独立块及调用者原对象。
4. 产品版本更新为 `2.14.4-go`，默认客户端声明继续为 `3.19.1`；在 README 与发布说明记录修复行为。

## 回归范围

- 将既有“自定义后缀”用例更名为“独立自定义块”，新增真正的第三块内后缀用例。
- 覆盖 3.18.0、3.18.2、3.19.1 的双向版本切换和同版本回退，检查后缀、独立块、缓存布局、输入不被修改及重复重建的幂等性。
- 首两块非官方时保留完整调用者文本；仅有相同标题的自定义指令保持原样。
- 在 `NormalizeBody` 层验证开启保留时原样透传、关闭保留时只留新版底座和调用者后缀，以及 JSON 往返后重复规范化不改变结果。

## 验证与发布

1. 本地只读代码、编辑、格式化及检查差异，不执行自动化测试、Go 构建或静态检查。
2. 先推送回归用例至 `codex/zcode-3191-fallback-suffix-fix`，读取准确提交对应的 GitHub Actions 失败日志，确认旧模板重复问题。
3. 实现修复并推送，等待最终提交的完整 `ci.yml` 通过；不使用旧提交或单个任务的成功结果替代。

## 回退

本次没有数据迁移。需要回退修复行为时使用 `2.14.3-go` 镜像；只调整 `ZCODE_CLIENT_VERSION` 会切换文案档案，但仍使用新的精确剥离逻辑。
