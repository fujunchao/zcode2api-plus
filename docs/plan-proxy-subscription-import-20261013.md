## 2. 目标、范围与非目标

### 2.1 完整闭环

```text
proxy-checker（独立进程或容器）
  代理源获取 → 规范化去重 → ZCode 专项检测 → 周期复测 → 合格代理仓库
                                                               │
                                                         JSON 订阅
                                                               ↓
zcode2api-plus
  定时读取 → 字段/时效过滤 → 去重/重入保护 → 小批量复检 → 原子入库
                                                               ↓
                                            现有代理分配、巡检与故障处置
```

### 2.2 第一版范围

- 一个可配置的 proxy-checker JSON 订阅来源。
- 手动预览、手动导入、定时导入、取消任务、同步历史。
- 结果新鲜度检查、按本项目用途复检、增量去重、自动来源容量限制。
- 来源标记、人工操作保护、淘汰线路的暂缓重入记录。
- 现有“代理设置”页增加订阅区域，不另建一套管理站。

### 2.3 明确不做

- 不搬入公开代理源爬虫、多供应商检测档位、浏览器自动化、网页挑战求解。
- 不支持任意 TXT、Clash、V2Ray 等订阅格式，不开发通用订阅转换平台。
- 不对大量未知代理携带账号 JWT、管理密钥或网关密钥发起请求。
- 不通过模型对话、套餐领取、额度查询验证候选，不额外消耗真实账号额度。
- 不实现订阅与现有线路表的全量镜像；来源缺项、空订阅或失败均不触发删除。
- 不主动改派已有账号，不改变 405 冷却、静默隔离、失败历史和重放防护规则。
- 不保证筛出的代理不会触发 405，也不将“配置入口复检通过”表述为“模型业务成功”。
- 方案制定阶段不提交或推送；实施阶段只提交工作分支并推送 origin 验证，不更新版本、不创建标签、不发布。

## 4. proxy-checker 的配置与部署约定

### 4.1 初始配置建议

| 项目 | 建议 |
| --- | --- |
| 检测档位 | `target_profile=zai` |
| 复测方式 | `detect_mode=force`，不能长期跳过已检测代理 |
| 入库策略 | `target_only`，以目标门槛通过为依据 |
| 配置入口探测 | `ZAI_AUX_DEEP=1` |
| 单次任务内检测轮次 | 2，从全局设置或对应环境变量配置 |
| 批量检测并发 | 初始 10～20，依据业务服务器资源调整 |
| 自动任务间隔 | 初始 1 小时；实际单轮耗时过长时增大间隔，不叠加任务 |
| 真实浏览器检测 | 不启用 |

当前 `normalize_auto_config` 会从全局设置取得轮次和并发，不能假定仅修改某个自动任务记录就会生效。Docker Compose 中显式设置的环境变量也可能覆盖页面保存值，应统一配置来源。

`ZAI_AUX_DEEP` 必须传入容器的 `environment`；只写入宿主机 `.env` 而未被 Compose 引用，不等于已启用。该参数在进程启动时读取，修改后需要重启检测端。

### 4.2 订阅约定

使用现有路径，下面只给路径示例，不包含实际主机或 token：

```text
/api/repo/<token>.json?usable=1&stable=1&limit=500
```

- `usable=1`：在外部先过滤不符合对应检测档位门槛的记录。
- `stable=1`：当前实现要求 `pass_streak >= 2`，不是单个任务内 `rounds=2` 就达标；需要连续复测结果入库。
- `limit=500`：限制供应端返回数量；本项目仍自行校验大小、条目数量并限制实际复检数量。
- 第一次启用稳定过滤时，订阅为空可能只是连续通过记录不足，不能因此报“代理源失效”。
- `grade` 和 `ip_type` 只作辅助信息，不作为“低 405 风险”的凭证。
- 第一版不依赖订阅端的档位/时效过滤，也不假定 `limit` 返回的是质量最好的若干条；接收端自行过滤排序。
- 共享出口在接收端识别并提示。第一版不默认使用 `exclude_shared_ip=1`，避免将某个共享出口的全部候选一并过滤。

### 4.3 网络与信任关系

- 建议与业务网关同机、分进程或分容器部署；同机仍共享 CPU、网络与文件描述符资源，应单独限制检测端资源。
- 两个容器共用指定私有网络时用检测端的网络别名访问；网关运行在宿主机时可通过检测端绑定的本机端口访问。不能在两个独立容器之间误用 `localhost`。
- 订阅采取本项目主动拉取，不让检测端持有本项目管理密钥，不共享两边数据库或运行数据目录。
- 当前订阅路径使用 token 标识仓库，管理页面密码不等于给该订阅路径加了鉴权。优先私有网络；跨机器时使用 HTTPS 和受控访问策略。
- 第一版不修改检测端源码。以后若需要按档位、时效或任务批次导出，再单独制定兼容性改动。

## 5. 接收数据契约与过滤规则

### 5.1 接受的格式

只接受 JSON 数组，每条记录使用以下字段：

| 字段 | 用途/规则 |
| --- | --- |
| `proxy` | 必填，含显式协议、代理 IP 与端口 |
| `target_profile` | 必须严格等于 `zai` |
| `usable` | 必须为布尔值 `true`，不接受字符串等隐式转换 |
| `aux_reachable.zcode` | 必须为布尔值 `true` |
| `pass_streak` | 整数且至少为 2 |
| `fail_count` | 缺省视为 0；大于 0 时不接收 |
| `last_ok` | 必须为有效 Unix 毫秒时间戳，用于新鲜度检查 |
| `ip`、`ip_shared` | 出口观测和共享出口提示；缺失表示未知，不虚构出口 |
| `latency`、`country`、`ip_type`、`grade` | 可选展示/排序信息，不决定业务成功 |
| `added`、`updated` | 仅供辅助诊断，不代替 `last_ok` |

- 时间缺失、超出有效期或明显在未来的条目跳过；未来时间只允许最多 5 分钟时钟偏差。
- 不能把秒时间戳猜测转换成毫秒，不能用接收时间替代上游成功时间。
- 容忍未知字段，拒绝结构错误、非数组、截断 JSON 和超出硬上限的响应；局部字段错误逐条跳过并计数。
- 未认识的新格式不能回退为“不校验直接导入”。

### 5.2 代理地址与身份

- 第一期只导入无认证的公网 IP 字面量代理端点，支持 HTTP、HTTPS、SOCKS4、SOCKS5、SOCKS5H；私人代理仍走现有手工管理入口。
- 地址需显式有效端口；拒绝 userinfo、查询参数、片段、非空业务路径及本机/内网/链路本地/多播/保留地址，包括 IPv4 映射 IPv6 的等价形式。
- 协议、IP 表示和端口做规范化；**保留 `socks5` 与 `socks5h` 的不同 DNS 语义，不把协议不同的端点合并**。
- 去重键为规范化完整端点的哈希，不使用线路名称，不沿用检测端仅按 IP:port 合并的假设。
- 与已有手工线路比较时使用同一规范化规则；已有不兼容的历史值不自动重写。
- 出口 IP 相同不等于端点重复，更不证明上游实际看到了同一 IP。可按有效且新鲜的出口观测优先选不同出口，不能修改账号级风控结论。

## 6. 同步任务与入库流程

### 6.1 任务状态

```text
queued → fetching → filtering → probing → committing → completed
                   └──────── 失败/取消 ────────→ failed / canceled
重启前未结束的任务 → interrupted
```

- 预览与导入运行同一过滤、复检流程；预览跳过正式入库，只保存脱敏的任务摘要。
- 后台任务不依赖浏览器连接；刷新页面后通过 `run_id` 查询进度。
- 手动与自动任务共用全局单任务闸门；忙时返回已有任务信息，不再排出多个重复任务。
- 调度器使用服务生命周期 context，支持停止与取消；重启不补跑积压计划，不恢复未完成的提交。
- 保存订阅 URL 或门槛配置产生新 revision，取消旧 revision 任务；提交前必须再次核对 revision。
- 关闭自动同步取消在途自动任务并停止后续排期；手动操作仍可显式执行。

### 6.2 分步处理

1. 读取配置、容量和既有线路快照，创建任务；网络请求全部在 Store 锁外进行。
2. 拉取 JSON，校验 HTTP 状态、响应大小、条目数量和格式。
3. 过滤档位、通过记录、时效、地址，按端点去重。
4. 排除已有线路、人工禁止重入、自动暂缓重入的端点；池已满时不再探测无必要候选。
5. 在尚未过期的候选中，优先最近成功、连续通过较多的记录；延迟只作后续排序依据。出口观测可信且新鲜时优先分散，同分时采用确定顺序。结合有界的历史导入任务明细优先推进尚未探测的候选，避免每轮只检测同一批失败端点、后续候选始终排不到；近期网络失败可短暂退避，但不写入 24 小时淘汰记录。预览记录不参与该调度状态。
6. 由固定数量 worker 拉取有限队列；只复检候选上限以内的端点。达到拟导入上限后停止派发新探测，不把未探测候选记为失败。
7. 收集通过集合。取消、配置变更或整体超时发生在提交前时，不落部分线路变更。
8. Store 在锁内重新核对配置 revision、当前去重结果、禁止重入记录、来源容量及候选成功时间，单事务提交线路、来源元信息及导入结果。
9. 提交成功才发布内存状态；数据库失败全部回滚。不会通过多次单条新增形成半轮入库。
10. 保存汇总，记录实际新增数和提交时因并发变化跳过的数量；允许有效订阅最终新增 0 条。

提交具有明确的完成点：取消在提交前生效则不写入；事务已成功提交后才到达的取消不回滚已导入线路，也不能把结果显示为“未导入”。最终导入摘要应与事务一起持久化，避免进程恰在提交后退出导致 UI 与线路表矛盾。

### 6.3 本项目复检门槛

- 使用本项目 `internal/proxy` 的出站协议实现和对应 ZCode 配置请求 UA，正常校验 TLS 证书，不模拟 Chrome，不降级 HTTPS。
- 默认必测 `https://zcode.z.ai/api/v1/client/configs`：HTTP 200、有效 JSON、`code=0` 且 `data.providers` 为包含有效标识的非空数组；HTML、关键词占位页、验证码页、405、5xx 均不算通过。
- 配置响应结构依据当前参考实现记录制定，实施前核对契约；若上游合法结构发生变化，报告契约不匹配并停止新增，不能放宽为“有响应就通过”。
- 备用站连通性可以作为诊断明细，不能替代必测主站门槛。已有浅检测与本次“入库复检”名称、结果和用途分开。
- 不向真实模型路径盲发 GET/POST；配置入口通过仍不证明模型调用、账号状态或长流可用。
- 若部署改写了 `ZAI_UPSTREAM_URL` 到其他 origin，默认专项门槛不再自动适用：阻止启用自动导入并提示需要另外评审探针配置，不继续拿默认站点的成功背书。
- 响应限长、超时、错误均按阶段分类；只记录结构摘要，不在日志或任务历史保存原始响应体。

## 7. 持久化、幂等与现有机制衔接

### 7.1 最小状态模型

复用当前 SQLite，优先在 `meta` 中新增带 schema version 的独立状态，不把辅助字段混入账号模型：

- `proxy_subscription_config`：来源 ID、订阅地址、revision 与阈值配置。
- `proxy_subscription_registry`：`profile_id → 来源 ID、端点指纹、导入时间、外部 last_ok、本地复检时间、有限的展示字段`。
- `proxy_subscription_blocks`：端点指纹、禁止/暂缓原因、产生时间、失效时间；人工禁止不自动过期。
- `proxy_subscription_runs`：有数量上限的历史摘要及当前任务，不保存原始订阅或无界候选列表。

以上为建议逻辑键，实施时可合并紧密相关的有界状态；不创建第二个数据库。不要求改变现有 `ProxyProfile` 基本 JSON 字段。管理列表可增加可选 `source` 等展示字段，旧客户端可忽略。

### 7.2 不重复、不覆盖

- 相同端点再次出现：保留原 ID、名称、URL 和启用状态，不重复创建；来源自有线路只允许更新观测元信息。
- 与手工线路冲突：视为已存在，不抢占来源归属，不改名、不启用、不重绑。
- 人工改名：保持来源归属但订阅不覆盖名称。人工更改 URL：旧端点登记人工禁止重入，该线路脱离自动来源管理，新 URL 不被订阅改回。
- 人工停用：保留停用状态；登记重入保护以免之后更名、删除或重建绕过。人工重新启用或显式解除禁止时才解除相应限制。
- 订阅已配置期间，人工删除或停用手工线路也记录其端点的“禁止订阅重入”意图，防止手工线路消失后被同址订阅候选重建；不改变其手工来源属性、删除/改派规则或账号状态。未配置订阅的旧安装不启用这项额外记账。
- 更换订阅 URL 不清除现有来源归属、线路及禁止记录。第一版一个稳定来源 ID，不以含 token 的 URL 充当来源标识。

### 7.3 淘汰后的暂缓重入

必须覆盖现有删除路径，而不只监听管理页面删除接口：

| 事件 | 新增的订阅状态处理 | 保持不变的行为 |
| --- | --- | --- |
| 人工删除 | 登记人工禁止，直到显式解除 | 原删除、账号改派规则 |
| 自动巡检删除 | 登记 24 小时暂缓 | 原失败判定与改派规则 |
| 代理端点故障删除 | 登记 24 小时暂缓 | 原快照与真实出口检查 |
| 线路断流熔断删除 | 登记 24 小时暂缓 | 原完整流计数和熔断阈值 |
| 新号空套餐规则删除 | 登记 24 小时暂缓 | 原授权范围和账号保护规则 |
| 账号命中 405 后换线，但未删除线路 | 不新增全局线路封禁 | 仍由现有账号级失败历史、冷却和静默期处理 |

- 由删除入口传递明确处置原因，在 Store 的共享删除/事务路径记录，不根据日志推断，不把所有删除都当成人工删除。
- 自动淘汰暂缓只记录来源自有线路；人工操作的禁止重入按 7.2 节执行，手工线路不因此变成自动来源线路。
- 删除、账号改派、来源状态与暂缓记录必须原子提交；失败不能出现“线路已删但暂缓记录丢失”。
- 暂缓到期仅恢复候选资格，仍必须取得新的有效外部记录并通过本地复检，不能自动启用旧结果。
- 来源失败、结果过期或列表缺项本身不删除存量线路。存量线路继续由已有巡检与故障机制负责，不宣称订阅模块保证存量永久新鲜。
- 不增加按出口 IP 或 ASN 的全局封禁，不把一次 405 归因为整条线路的问题。

## 8. 配置、资源限额与脱敏

### 8.1 本项目初始默认值

| 配置 | 初始默认值 | 说明 |
| --- | --- | --- |
| 自动同步 | 关闭 | 升级后不产生自动外部请求 |
| 订阅 URL | 未配置 | 只允许管理员设置 |
| 同步间隔 | 10 分钟 | 建议可调范围 5～1440 分钟，从完成后排下一轮 |
| 外部结果最大年龄 | 120 分钟 | 应与检测端间隔和单轮耗时共同调整 |
| 最少连续通过记录 | 2 | 首版固定下限 |
| 每轮实际复检候选数 | 50 | JSON 返回记录可更多，实际发包有限 |
| 每轮新增上限 | 10 | 受池剩余容量进一步限制 |
| 来源自有线路容量 | 50 | 包括停用线路；不限制手工线路；降低上限不自动删除 |
| 新增线路自动启用 | 关闭 | 试运行默认先入库停用；确认后开启，仅影响未来新增 |
| 复检并发 | 4 | 首版硬上限 8，不与业务任务共用工作队列 |
| 单目标探测超时 | 6 秒 | 单候选总预算不超过 12 秒 |
| 订阅拉取超时 | 10 秒 | 不无限重试 |
| 单轮总预算 | 180 秒 | 超时在提交前则本轮不导入 |
| 订阅响应大小 | 2 MiB | 按解压后实际读取大小限制 |
| 解码条目硬上限 | 1000 | 超出整轮拒绝，不静默截断后导入 |
| 探针响应大小 | 64 KiB | 超出视为契约/响应异常，不无界读取 |
| 自动淘汰暂缓时间 | 24 小时 | 与账号风控静默期是不同状态，不能互相清零 |
| 历史保留 | 最近 50 轮 | 每轮最多保存 50 条脱敏明细 |

完全自动补给需要管理员最终同时开启“自动同步”和“新增线路自动启用”。此前入库停用的线路不会因为修改默认值而被批量启用，需明确操作。

有效暂缓/人工禁止记录也要设置存储预算；达到预算时暂停新增并提示管理员清理或调整，不悄悄丢弃仍有效的禁止记录。为当前来源池可能发生的删除预留记录空间，不能因容量不足破坏正常淘汰路径。

### 8.2 网络和连接生命周期

- 订阅读取使用独立客户端，明确直连所配置来源，不继承环境代理，也不走正在筛选的代理。
- 来源 URL 只允许 HTTP/HTTPS、禁用重定向；管理员明确配置的本机/私有网络检测端可以访问，不能把这个许可继承给订阅中的候选代理地址。
- 探测目标固定且不跟随重定向。候选不能提供自定义探测 URL、请求头或方法。
- 从现有传输构造中提取共享实现：生产继续使用原缓存，候选使用短生命周期 Transport，结束或取消即关闭空闲连接、释放响应体引用，不写入 `transportPrec`。
- 还要覆盖自动来源线路长期轮换：已入池再淘汰的端点可能已被生产/巡检加入缓存，不能只释放候选 Transport。在线路删除或 URL 更改成功后，清理不再被线路/账号引用的旧端点缓存条目（包括不同超时变体），只关闭空闲连接，不中断在途请求；验证与并发新增、共享端点的竞态和锁顺序。此清理属于持续自动补给的资源验收范围。
- 复检可与生产请求同时运行但必须限流；对现有巡检记录不同日志来源，不以暂停业务或修改业务超时换取检测吞吐。
- 无新增生产第三方依赖是目标，不以代码行数或未测量的 MB 数字承诺性能；通过后续远端测试验证工作者、缓存、响应和历史有界。

### 8.3 敏感信息

- 完整订阅 URL 只保存在配置中；GET 返回配置状态和脱敏显示，更新时未提供 URL 表示保持原值，清空需显式操作。
- token 可能在路径或查询参数中，不能只打码密码；日志只写来源 ID、脱敏 origin、阶段和错误类别。
- 不直接输出 `url.Error`、完整响应体、完整订阅 JSON、管理鉴权信息。
- 代理地址先校验后进入日志摘要；不把外部错误文本直接拼入日志或 HTML。

## 9. 模块与接口设计

### 9.1 放置位置

- 新增 `internal/proxysub` 模块：隐藏下载、过滤、队列、复检和任务生命周期，实现预览与导入共用的流程。
- 模块外部 Interface（接口）只暴露配置/状态、启动、取消及关闭等必要操作；候选阶段与判定属于模块 Implementation（实现）。
- Store 的批量提交 Interface 是持久化 Seam（可替换行为的接缝）；实际 SQLite Adapter（适配实现）负责事务和并发重检，不让 HTTP handler 编排多次单条写库。
- 时钟、订阅读取、候选探测提供内部测试接缝，覆盖真实流程而不是只测试孤立解析函数；模块不依赖 `adminapi`，避免包循环。
- 不为了将来可能出现的多个订阅格式设计插件注册系统，也不改造整个后台调度体系。

### 9.2 管理 HTTP 接口草案

全部复用现有后台管理鉴权，最终命名可在实施时按代码风格微调：

| 方法与路径 | 含义 |
| --- | --- |
| `GET /admin/api/proxies/subscription` | 脱敏配置、当前任务、下次运行时间与容量 |
| `PUT /admin/api/proxies/subscription` | 原子校验保存配置并更新 revision |
| `POST /admin/api/proxies/subscription/runs` | `mode=preview/import`；返回 202 和 run_id，忙时 409 附当前任务 |
| `GET /admin/api/proxies/subscription/runs` | 有界分页/限量的历史与当前任务摘要 |
| `GET /admin/api/proxies/subscription/runs/{run_id}` | 进度与有限脱敏明细；已淘汰历史返回 404 |
| `POST /admin/api/proxies/subscription/runs/{run_id}/cancel` | 取消本人管理的运行中任务，终态重复取消不改变结果 |
| `GET /admin/api/proxies/subscription/blocks` | 有界查询禁止/暂缓记录 |
| `DELETE /admin/api/proxies/subscription/blocks/{fingerprint}` | 管理员显式解除重入限制；不立即导入或启用 |

摘要统一字段：接收、格式拒绝、时效拒绝、已有、暂缓、候选、复检通过/失败、未探测、新增、提交冲突跳过、总耗时及终态原因。成功可为 0 新增，不能把源为空与网络失败混成同一错误。

### 9.3 前端

- 在代理页增加“自动补充代理”区域，明确区分“预览”“立即导入”“自动同步”。
- 展示阶段、进度、上次结果、下次时间、来源容量；任务运行中禁用重复提交，仍可查看和取消。
- 线路列表增加来源标签、导入时间和最近复检时间；原有手工操作保留。
- 结果名称使用“入库复检通过”“未验证模型业务”，不沿用含糊的“低风控”“业务可用”标签。
- 配置区说明启用新线路会使其参与现有后续选线，但同步动作不会立即改派现有账号。
- 使用现有组件、请求库和通知方式，不增加前端生产依赖；按仓库要求更新 `frontend/dist`。

## 11. 分阶段实施与验收

### 阶段 A：供应端配置与契约确认

- 文档化部署配置、档位、强制复测和订阅获取方式。
- 测试契约只使用构造的 JSON，不读取或上传实际账号/代理运行数据。
- 如用户另外授权真实部署，先观察至少两个完整复测周期；记录稳定订阅数量、结果年龄和任务耗时，暂不导入生产。
- 验收：能解释空订阅、档位、时间戳与连续通过语义；确认业务服务器资源预算。供给不足时停止扩大投入，不通过降低门槛制造“可用”数量。

### 阶段 B：预览与小批量手动导入

- 完成传输生命周期、下载过滤、任务接口、事务导入、来源与重入保护，再接前端预览和手动按钮。
- 不提前开放缺少重入保护的自动入口。默认新线路停用，预览除任务摘要外不修改线路/账号/禁止记录。
- 验收：重复操作幂等、并发人工操作受保护、取消及失败无半轮入库，页面刷新能恢复状态。

### 阶段 C：自动补给

- 开启配置驱动的后端调度，页面显示下一轮时间；全局单任务、历史限额和重启 interrupted 处理落地。
- 经明确验收后才开启“自动同步”和“新增线路自动启用”，并从小容量开始。
- 验收：来源断网/为空/变更、任务超时/重启均不误删池子；淘汰线路不被立即重新导入。

### 阶段 D：观察与后续决策

- 观察每轮新增量、重复比例、外部记录年龄、本地复检通过率、来源线路存活时间、网关请求延迟及错误情况。
- 405 改善作为后续真实业务观察，需有请求数和账号/模型/时间条件，不能只比较绝对次数或把相关性当因果。
- 只有供应量和时效确有瓶颈时，再考虑修改 proxy-checker 的过滤、排序、输出批次或采集策略；不作为第一版前置需求。

## 12. 自动化测试矩阵与远端门禁

### 12.1 必须覆盖

1. **契约**：真实输出结构的合成样例、稳定计数、缺字段、错误布尔类型、秒/毫秒混用、过期/未来时间、非 zai、HTML 登录页、截断 JSON、超大解压后响应、超量条目。
2. **地址**：规范化重复、协议区分、IPv4/IPv6、公私网和映射地址、非法端口、userinfo、查询参数、候选不能控制目标或重定向。
3. **复检**：HTTP CONNECT 与各 SOCKS 协议的本地测试链路、TLS 校验、超时/断连/取消、假 200、有效配置 JSON、普通 405/风控文案/5xx、备用站通过不能抵消主站失败。
4. **资源**：worker 上限、总预算、候选传输不污染生产缓存、退役线路缓存清理不伤在途/共享端点、响应体关闭、重复运行后状态及连接生命周期有界；避免依赖不稳定的绝对内存阈值断言。
5. **Store**：按端点幂等、手工同址、停用/改名/改 URL、池容量、来源切换、并发新增/删除、配置 revision 变化、提交失败回滚、提交与终态一致、旧版本状态无来源字段可读。
6. **删除衔接**：巡检、端点故障、断流熔断、新号规则、人工删除的原因与暂缓；到期仍需新记录和复检；账号单次 405 不产生全局线路封禁；原改派策略保持不变。
7. **调度与管理接口**：管理鉴权、自动/手动互斥、预览不入库且不影响后续候选排期、候选数超过单轮上限仍能推进、停止、取消提交竞态、断网/空订阅、重启、历史保留、完整 URL/token 不进入响应摘要和日志。
8. **前端**：配置保存、URL 保持/替换/清空、忙碌状态、预览与导入区分、取消、刷新恢复、0 新增、部分拒绝、容量满、来源标签和解除禁止的明确确认。

### 12.2 执行要求

- 按 `AGENTS.md`：本机只阅读、修改、格式化与差异检查；不运行 Go 测试、竞态、静态检查或完整后端构建。
- 修改前端时，本地构建只用于生成必须提交的 `frontend/dist`，不替代远端验证。
- 自动化测试统一使用隔离 SQLite、合成 token、受控时钟和本地测试服务器；网络依赖通过测试接缝注入，不让 CI 获取公共代理或访问真实 ZCode。
- 实施时使用 `codex/` 工作分支，只推送 `origin`；由当前 SHA 的完整 `ci.yml` 结果验收，优先 `gh run watch`，失败后读取该轮日志修复。
- 不用旧提交成功、单一通过任务或本地产物构建代替全量 CI；不因测试慢或 Windows 开发机环境问题删测试。
- 发布只在用户另行要求时进行，并保持分支 CI 和发布复用完整 CI 的双重门禁。

## 13. 回退与完成标准

### 回退

- 关闭自动同步：停止计划和在途自动任务，不删除已导入线路，不影响现有业务进程。
- 需要停止使用来源线路时，管理员按来源筛选后明确停用/删除；说明停用不等于立即迁移既有绑定，删除仍遵循现有改派规则。
- 订阅来源故障不成为网关启动或请求处理的硬依赖，已导入线路保持原有独立生命周期。
- 代码回退前关闭同步；旧版本可忽略新增 `meta` 键。旧版本继续修改线路后再升级时，按实际 ID/端点核对来源记录，不给失配线路补回或自动恢复启用。

### 完成标准

- 外部可以持续提供符合契约的候选，本项目可以预览、少量复检并幂等导入。
- 无账号凭据流入外部检测端，无不必要的生产依赖增加。
- 不改写手工线路和现有账号状态，不误删池子，不循环导入刚淘汰的代理。
- 任务、连接、响应大小、正式来源池和历史均有明确上限。
- 配置、用户界面、部署说明、回归测试与前端产物一致，当前提交完整远端 CI 通过。
- 验收表述限定为“自动代理补给闭环完成”，不把尚未验证的 405 降幅或模型业务成功写成成果。
