# 模型巡检实施与验收说明

基线：`f8e4517` / `v2.10.7-go`。工作分支：`codex/proxy-model-health`。目标补丁版本：`v2.10.8-go`。

## 实现范围

- `internal/modelprobe` 提供同源的最小请求、完整 JSON／SSE 判定、可替换时钟和有界工作者；管理端与自动调度共用真实发送路径。
- `internal/store/model_probe*` 负责设置、专用角色、一次性跨路许可、滚动预算、去重队列、成对状态机、证据保护及历史。生产部署沿用单进程独占数据库。
- `internal/store/proxy_retirement.go` 提取共享严格退役事务，业务规则与主动规则分开归因、共用执行；未另建一条绕过持久禁止的删除路径。
- 共享纯账号风控阶梯逻辑；探测不调用业务自动换线。初始化／固定出口约束保持，新增探测角色不能同时人工补入初始化。
- 后台增加独立面板、可配置间隔、账号和线路选择、出口组、预算与参考→目标步骤；保留原连通性接口含义。

没有操作生产服务器或真实账号，没有读取运行 `data/`。开发机只做代码修改、格式化、差异检查，以及用于提交产物的前端构建；未运行本地 Go／前端自动化测试。

## 最终验收口径

仅以最终发布提交 SHA 的完整分支 CI 与 `release.yml` 复用验证为准。完整检查继续包括工作流、前端 lint／测试／产物一致性、Go build／vet／全量与重复测试／race、SDK、固定 New API 合同、Windows 严格日志专项、跨平台二进制和 Docker。

新 `Repeat model probe contracts` 步骤覆盖 `internal/modelprobe` 与管理端 `TestModelProbe*` 十次重复执行。真实出站使用隔离本地 HTTP 代理和合成 JWT；窗口测试推进测试时钟，不等待实际五分钟，也不缩短生产冷却。

## 显式限制

- 出口组是管理员声明，不是供应商 IP 因果证明。无健康锚点或证据不足时保留“不确定”。
- 正常业务与探测证据分开，固定最小模板不冒充多种真实业务内容；小请求成功不能替长上下文或长流背书。
- 本版不自动创建探测账号、不迁移所有固定业务账号、不调整供应商账号数量／速率策略。
- 历史与预算持久化，半组对照不跨重启复用；证据丢失保护结束前不产生新主动删除。
- 原手动流测保持接口兼容，本模块请求预算不冒称覆盖所有旧人工模型请求。
