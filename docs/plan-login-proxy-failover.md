# 回调登录的代理自动换线与会话续用

## 目标

输入回调后若命名代理无法访问 OAuth 凭据端点，不再固定失败出口或要求退出新增对话框；删除故障线路，沿用现有代理分配策略，继续处理同一个回调直到成功或没有可尝试的出口。

## 方案

1. 登录会话保留原 state、回调身份、已失败 URL 和当前代理；每次只处理一个完成请求，防止并发兑换一次性授权码。
2. OAuth 网络请求支持取消并保留结构化底层错误。仅代理连接、握手、超时、传输中断和代理认证失败触发换线；业务错误、无效回调、普通 HTTP 错误、无效响应和取消不触发删除。
3. 删除前核对代理 ID 和 URL，不能删除已被修改的新配置。代理删除和全部关联账号改派作为一个事务提交，失败完整回滚。
4. 同一会话避开已失败 URL（包括同地址别名）；选择仍使用“空闲优先，否则绑定最少，同负载按列表顺序”，停用线路不参与。
5. 无可尝试代理时沿用既有直连回退；直连也失败则保留会话，管理员补充代理后可直接重新提交同一回调。显式直连不自动改为代理，手工 URL 不误删命名配置。
6. 每次操作受原登录会话有效期和请求/服务取消约束，不反复尝试同一失败出口，也不无限重试业务错误。
7. 成功收到的 OAuth 凭据暂存于会话内，保存失败后可重试而不再次消费授权码；成功完成后只保留账号 ID 和回调身份，重复提交返回同一账号，不重复刷新或领取。
8. 新账号绑定最终成功的出口，再进入现有额度/领取收尾。自动重登已有账号仍保留其既有指派语义，不扩大改动范围。

OAuth 授权码已经被上游消费、但成功响应完全丢失时，本地无法恢复未收到的凭据；后续若返回授权码失效，停止换线并明确提示重新授权，不能把业务拒绝继续归因给健康代理。

## 实施与验证

1. 使用隔离 SQLite、合成回调和本地 HTTPS/CONNECT 代理建立回归：初始代理失败后同一回调成功、共享账号改派、重复提交只兑换一次。
2. 先推送测试提交，读取远端失败日志确认缺口，再实现会话重试及存储事务。
3. 补充最少绑定选择、连续失败/同 URL 避让、普通业务错误、取消、并发提交、代理变更、事务失败、凭据缓存和会话过期测试。
4. 本地仅格式化和差异检查，测试、静态检查与构建统一由 GitHub Actions Ubuntu 执行，并重复验证关键链路 20 次。
5. 当前提交完整 CI 通过后推送 `go-rewrite`；确认默认分支 CI 后发布 `v2.9.8-go`。
6. 发布仍经过完整 CI 门禁，最后核对 5 个二进制附件、两种 Linux 架构镜像、`latest` 和实际提交 SHA。
