# 计费失败观测与代理自动删除保护

日期：2026-10-16。目标补丁版本：`v2.10.14-go`，发布前重新核对 origin。

## 问题与目标

额度查询的客户端超时只能证明该次计费请求未完成，不能证明共享代理永久失效。
旧 `quotaRequestFailure → proxyguard.Purge` 绕过统一网络巡检的二次复核、参考对照和处置模式，且默认业务出口没有自动删除保护。

本次统一故障处置入口，不通过放大超时掩盖问题，不改变模型协议或降低测试覆盖。

## 方案

1. **计费失败只观测**：余额查询、领取及资格预览的传输失败／可疑请求只记录原错误，保留节点、账号绑定、上次成功额度和既有冷却；取消与迟到身份不产生新处置。单次计费失败不得直接删除。
2. **复用统一网络复核**：当前账号／凭据／线路代次有效的异常按节点合并，送入现有无凭据网络巡检；受开关、配置代次、时间窗口、容量和最短重查间隔约束。异常通知不是删除证据，也不自动发起真实模型请求。目标恢复、参考也异常、配置变化或请求取消均不得据此删除。
3. **保护人工维护的出口**：新增持久字段 `auto_delete_protected`。当前默认业务出口及仍由托管账号使用的默认出口自动受保护；同路由别名不得绕过保护。代理页面提供勾选和有效保护原因，当前页面新增手工节点默认勾选。旧 API 省略字段时保持兼容，更新时不得清空已有保护。
4. **统一自动删除门禁**：故障触发的普通删除、断流熔断、登录失败清理以及新严格退役决定，均检查统一处置模式和节点保护。仅观察不产生新自动删除／改派；显式手动删除仍可操作。已持久化的严格退役恢复事务不回滚，不恢复历史删除或解除账号冷却。
5. **明确观测范围**：计费错误不等于模型不可用。返回值／日志区分“仅记录”“等待网络复核”和“已删除”；保护不把异常节点标记为健康，也不强制固定出口账号直连。

## 回归接口与验收

测试通过现有额度查询、代理管理 HTTP 接口、Store 公共接口和统一巡检管理器执行，不使用真实账号、外网目标或运行数据目录。

- 真实本地 HTTP 代理先返回成功额度，再等待响应头超时：共享节点和所有绑定仍在，余额／状态保留，错误可见；恢复后可再次查询。
- 领取／预览传输失败或可疑请求只记录，保留已有冷却与成功领取记录；普通 HTTP 业务错误的既有边界不变。
- 异常通知合并、限频、取消、旧凭据／旧绑定／旧 URL／启停代次、关闭巡检及观察模式。
- 两次网络失败且独立参考正常时，仅自动模式中的未保护节点可删除；恢复、参考共同失败、保护节点均保留。
- 默认出口、托管默认出口、手工保护、同路由别名；保护持久化、旧客户端更新、显式手动删除。
- 断流／登录／严格模型归因自动删除也遵守保护和观察模式；已存在的退役恢复仍按原事务契约完成。
- 前端显示有效保护原因，编辑／新增提交保护字段，编辑不意外启用停用节点。

## 实施与发布步骤

1. 推送计划和能够暴露旧行为的回归测试，在 Ubuntu CI 获取真实失败日志。
2. 实施观测与保护，按新的产品语义更新旧“单次失败就删除”用例；保留并扩充并发、事务、取消及身份隔离断言。
3. 本地仅代码编辑、Go 格式化、差异检查和必要的前端 dist 生成。完整构建、静态检查、自动化测试与竞态检测由 GitHub Actions 执行。
4. 推送工作分支，当前提交完整 CI 成功后再更新 origin 默认分支和推送真实版本标签。
5. `release.yml` 再次复用完整 `ci.yml` 验证，通过后才发布五个二进制及两种 Linux 架构镜像；核对远端标签、附件、版本镜像和 latest。
