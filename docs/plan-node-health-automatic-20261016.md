# 节点巡检自动化修正实施方案

基线：`f1506cf`，工作分支：`codex/node-health-auto-selection`。目标补丁版本：`v2.10.12-go`（发布前重新核对远端版本）。

## 目标与约束

- 周期模型巡检无需目标或账号名单；全部启用、未严格退役且未显式排除的节点自动参与主动检查。
- 账号在准备派发时依据当前资格、剩余请求预算、近期可靠性和占用择优，持久业务绑定不变。
- 修正基础调度节拍与完整轮转周期重复放大的问题；缺账号／预算保留待检，业务成功旁证不替代主动检查。
- 统计最终 HTTP 尝试，区分业务与探测来源、账号类与网络类异常；统计不能扩大严格退役证据范围。
- 保留双轮对照、十分钟证据、反证、冷却、代次及原子退役门禁。网络巡检独立维护。
- 按项目规范只在 GitHub Actions 运行构建、静态检查与测试；本机仅阅读、修改、格式化、差异检查及生成需提交的前端产物。

## 模块与接口

沿用统一 Manager / Store 模块。外部入口只需开关、周期与处置方式，自动选择细节放在 Store 内部：

1. 调度器用基础间隔划分配额窗口，以最久未主动检查的节点优先；完整周期仅用于复测到期与展示，不再拿来分批限流。
2. 自动队列不提前冻结账号；执行槽确定后统一读取预算快照、资格与排名，过滤正被其他探测占用的账号。开始对照后冻结身份，不能拼接不同主体证据。
3. 无资源的初筛任务保留等待状态，并以有界频率重评；未发送不算已观测，诊断时间预算从实际执行开始。
4. 账号统计通过现有真实模型请求的完成路径汇入独立近期窗口；严格代理观测仍保持原过滤规则。
5. 摘要同时给出主动观测覆盖、业务成功旁证、资源等待与网络异常；界面状态与后端派发使用相同口径。

## 迁移与交互

- 策略版本升级为 3。旧手工配置迁移为自动覆盖／自动选号并释放旧专用角色；保存原开关、预算、处置模式、显式排除、出口组声明及直连许可，不额外扩大删除权限。
- 后端保留手工模式兼容旧管理客户端／既有合同；新界面不再提供周期目标、账号或参考多选，保存统一使用自动模式与自动参考。
- 延续现有摘要行与抽屉，不另做视觉重构。核心信息为“实际检查 X/N、等待原因、预计周期”；账号展示只读选择依据。高级设置保留预算、并发、排除与直连许可。
- 旧短流测试保持独立诊断含义，不将其无绑定账号限制套用于周期巡检。

## 回归顺序

先推送断言失败的回归，验证基础节拍、预算换号、派发时选择、冷启动并发、业务旁证不免测、缺资源自动恢复及前端非正常状态。远端失败日志确认后实现修正。

随后补齐统计分类、样本置信度／过期、凭据变化、业务占用、预算持久化、迁移与界面合同。既有严格处置、网络、同步／异步、账号健康回归不得删减或放宽。

## 发布门禁

分支完整 CI 通过后才推送 `v2.10.12-go` 标签。`release.yml` 再复用完整 CI，成功后上传五个平台二进制并推送双架构 GHCR 镜像。核对 Release 附件及版本／latest 镜像摘要和提交标签后，才报告发布完成。
