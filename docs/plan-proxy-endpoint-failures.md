# 计费端点不可达与领取可疑请求的代理淘汰

## 范围与兼容性

- 用户已确认：新增规则覆盖新老账号。老账号单纯无额度仍不删除代理；新账号双次空额度规则继续保留。
- 对实际通过命名代理发送的余额查询、领取资格预览及套餐领取生效，包括后台手动操作、自动/每日领取、额度监控和 CLI 对应路径。
- 遥测上报、验证码求解、OAuth 授权及模型请求不额外扩展本规则；它们沿用既有处理。

## 删除条件

1. 代理出站连接、DNS、TCP、TLS、CONNECT/SOCKS 握手失败、超时，或成功响应的传输中断，导致无法完成对应端点请求。
2. 代理鉴权返回 HTTP 407；非法的已配置代理不再静默回退直连。
3. 领取/资格预览明确返回 `3012` 或可疑请求/风控错误文案，包括 `unusual activity`、`suspicious request` 和中文可疑请求。

普通 HTTP 401/403、429、5xx、验证码错误、已领取、资格不足、名额耗尽、无可领套餐、缺字段、JSON 格式异常及请求取消，不单凭这些情况删除代理。只有明确的代理连接失败或可疑请求信号才能触发新增规则。

## 状态与并发要求

- 删除时重新核对账号、凭据、代理 ID 和地址，不能根据旧请求删除已经改派或修改后的代理。
- 复用现有事务，把删除和所有关联账号的改派一起提交；提交失败不发布半套内存状态。
- 继续采用“空闲优先，否则绑定账号最少，同负载按列表顺序”的策略；停用线路不参与，原 URL 的别名不作为替代线路，无替代线路则明确回退直连。
- 保留账号额度、启用/归档状态、使用记录和领取冷却；新规则不受是否曾领取/使用、是否存在套餐的限制。
- 同一失败请求最多淘汰其原线路一次。领取遇到此类失败即结束本轮，不在改派后的线路递归重试。
- 批量操作的后续账号重新读取最新绑定；额度缓存不得把旧代理的查询结果带到新代理。
- API 结果和日志明确记录代理删除、改派及直连回退，日志不输出代理密码。

## 实施与验收步骤

1. 新增隔离端到端用例：余额代理断连、领取代理断连、已用老账号领取可疑请求，以及全部共享绑定改派。
2. 推送工作分支，读取该提交的完整远端 CI 失败日志，确认真实缺口。
3. 实现统一代理故障分类、原子淘汰与各入口接入；更新上一版本中被新需求取代的“领取风控不删除”断言，保留老号普通空额度保护。
4. 补充取消、HTTP/业务错误、缓存、迟到响应、共享代理、无替代线路、事务失败、并发重复处理及 CLI 路径测试。
5. 本地只格式化和检查差异；全部构建、静态检查、测试及 20 次重复回归由 GitHub Actions Ubuntu 执行。
6. 完整 CI 通过后快进到 `go-rewrite`，确认当前提交的默认分支 CI，再推送 `v2.9.7-go`。
7. 发布工作流复用完整 CI 后构建、上传并推送；最终核对 5 个二进制附件、两种 Linux 架构镜像、`latest` 与提交 SHA。

## 核心回归矩阵

| 场景 | 预期 |
| --- | --- |
| 新/老账号通过代理无法查询余额或领取 | 删除原代理，原子改派所有绑定账号 |
| 曾使用、有套餐的老账号领取返回可疑请求 | 同样淘汰，不受新账号空额度判据限制 |
| 某套餐领取成功，后续套餐返回可疑请求 | 保留成功记录，仍淘汰发生故障的原代理 |
| 批量领取/预览共享同一代理 | 后续账号使用改派后的地址 |
| 取消、普通鉴权/验证码/上游服务错误 | 不删除代理 |
| 仅无套餐或余额耗尽的老账号 | 不删除代理 |
| 请求期间改派、修改 URL、换令牌、删除账号 | 迟到响应不能删除新的有效代理 |
| 代理删除事务失败、并发重复故障 | 不出现部分状态，原线路最多删除一次 |
| 直连、手工 URL 或绕过账号线路的测试客户端 | 不误删代理池中的命名线路 |
| 无替代线路或仅剩原地址别名 | 清除原绑定并明确回退直连 |
