# 风控线路避让与逐次出站日志

日期：2026-10-01；目标版本：`v2.9.2-go`。

## 问题与目标

用户提供的 v2.9.1 容器日志显示：同一个账号四次风控均完成改派，但分配目标出现
`A → B → A → C`，最终请求由其他账号完成，原账号仍升级失效。原始日志、账号和代理
信息不进入版本库。此次只修正近期线路重复选择及观测缺口，不承诺换线可解除上游风控。

## 行为约定

1. 以账号为范围记录实际触发消息风控的代理 ID 和规范化 URL 摘要，避让窗口默认 24 小时。
   不把其他账号使用同一线路的失败扩大为全局禁用；不记录明文代理凭据。
2. 选择时排除当前线路及窗口内该账号已失败的线路，再按空闲优先、最少绑定分配。
   候选用尽时保留当前绑定与冷却，明确记录原因；不回退旧失败线路或直连。
3. 历史写入现有 SQLite meta，和改派同事务提交，重启保留，无 accounts JSON/schema 变更。
   过期、已删除账号记录在更新时清理，每账号最多保留最近 64 条；到期可再次选择。
4. 继续保护迟到响应与人工改派，保留现有冷却、连续风控升级失效和请求级重放防护。
   更新凭据/成功调用不提前清除仍在窗口内的线路历史；管理员手工指定线路不受限制。
5. 同步和异步请求在每次真正调用 HTTP 客户端时记录独立的 attempt 日志：请求/票 ID、
   出站序号、账号 ID、线路 ID/名称、脱敏端点、是否直连回退、响应头状态或连接错误类别。
   区分同账号重试与换账号，不改变原有请求汇总字段；不输出 Token、代理认证或请求正文。
6. 风控换线日志补充请求关联、换线前后 ID/名称/脱敏端点、结果及跳过原因。
   端点是代理配置入口，不是探测得到的公网 IP；此次不增加公网 IP 探测请求。

## 验证与发布

验证边界沿用 Store 公开换线接口和同步/异步 HTTP 测试入口；覆盖 A/B/A 重现、
账号隔离、TTL、重启、同 URL 别名、无候选、事务失败、并发及管理员改派；日志验证
逐次关联、重试编号和敏感信息不泄漏。先运行失败用例，再逐项实现并复跑。

本地执行专项、全量 Go 测试、构建、静态检查；推送当前发布分支后等待 GitHub CI
（包含 Linux race、SDK、前端一致性及镜像构建）通过，再推送版本标签触发 Release。
最终确认五平台二进制及双架构镜像交付。用户已有未跟踪文件不纳入提交。
