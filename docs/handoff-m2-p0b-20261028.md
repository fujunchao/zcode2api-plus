## 1. 本次落地

### 1.1 Token 池（internal/captcha/token_pool.go）

- 按 `sceneId|region|prefix` 分桶；配置键变化清空旧桶与 CertifyIdRegistry。
- token 一次性：Take 取出即删除；TTL 默认 95s（`ZCODE_CAPTCHA_POOL_TTL_MS`）。
- 后台 refill：默认 min=2 / max=6，1s 节拍（`ZCODE_CAPTCHA_POOL_REFILL_MS`）。
- 池空时做 1–2 路并发 solve 竞速（`ZCODE_CAPTCHA_POOL_EMPTY_SOLVE`，上限 2）；
  多余成功结果回填池子，失败按现有错误上抛。
- CertifyIdRegistry：同一 certifyId（解析不出时用 token 原文摘要）只允许 mint 一次，
  防止并发 F008/重复交出。
- `Manager.Close` 停止 refill 与在途 mint；`ZCODE_CAPTCHA_POOL_ENABLED=false`
  退回逐请求求解。
- 池只在浏览器求解器启用时由 main/CLI 开启；配置首次成功前不后台预解。

### 1.2 配置缓存（internal/captcha/captcha.go）

- `CaptchaConfigCacheTTL` 默认由 10 分钟改 1 小时（`CAPTCHA_CONFIG_CACHE_TTL` 可覆盖）。
- 成功才写；失败保留 last-good，不覆盖、不清空；last-good 存在时 30s 退避，
  避免配置接口故障时每个 JWT 请求都等配置超时。
- 无 last-good 时仍按原语义回退 `DefaultConfig`；`enabled` / `skip_model_request`
  判断顺序与语义不变。

### 1.3 严格获取与挑战重试

- 拿不到 token 仍由 gateway 映射 503 `captcha_required`，绝不裸发。
- 3007 / 验证码响应头 / F001 文本的识别与有限重试逻辑未改。

### 1.4 CPU governor 与指标

- `cpu_governor.go`：Linux 读 `/proc/stat`；其他平台用 `runtime/metrics`
  的进程 CPU 时间折算；无新增依赖。
- CPU ≥70% 降半速、≥85% 降到 1/4；空闲 120s 缩到 1 条，900s 停补（保留 1 条唤醒）。
- `/admin/api/monitor` 新增 `captcha`：pool_size/take_total/empty_take_total/
  mint_total/mint_fail_total/wait_p50_ms/wait_p95_ms 等。
- 请求诊断 `[#]` 行尾部追加 `captcha_wait_ms / captcha_pool_size /
  captcha_empty_take / captcha_mint_fail`；不打印 token。

### 1.5 Docker 资源建议

- `docker-compose.yml`：`ZCODE_CAPTCHA_BROWSER_WORKERS=2` 起步、
  `ZCODE_CAPTCHA_POOL_ENABLED=true`；注释给出 2 CPU / 2 GB 与每 worker 0.5–1 GB 预留。
- README/PLAN 同步环境变量与资源建议；不改镜像基础结构。
