# 取消代理订阅历史硬门槛并发布 v2.10.3-go

## 目标与基线

- 基线：v2.10.2-go / `7303450`，复用本会话独立工作树，新分支 `codex/proxy-subscription-live-check`。
- 用户已确认同时取消“外部最近成功时间必须在有效期内”和“连续成功至少两次”这两个硬门槛，并要求推送、发布补丁。
- 触发场景：一批 321 条候选因历史次数和历史时间全部被提前过滤，根本没有进入本项目复检。回归使用相同分布的合成数据，绝不把真实订阅地址、代理明细或日志交给 CI。
- 新原则：PRX 提供候选，历史时间与次数只作排序参考；本项目当次配置入口复检及提交保护决定能否入库。不假设 PRX 永远及时清理失效线路。

## 改动范围

1. **解析层**：移除 last_ok 有效期和 pass_streak 下限判断。缺失或格式异常的这两项仅降为未知参考值，不因此拒绝其他条件合格的候选；明显异常/未来时间不获得排序优势。
2. **持久化层**：去掉 FinishSubscriptionRun 中同样的外部时间与连续次数复验，避免“复检通过但提交又拒绝”。保留本机 ProbedAt 的最近有效性检查，不能拿过期本地探测结果写库。
3. **兼容性**：max_age_minutes 只作为旧配置/旧客户端兼容字段保留，不再参与筛选或入库；保留原值及格式，升级后无需重设已有订阅或数据库迁移。
4. **界面**：移除“结果有效期”输入，新界面保存时不再发送这个兼容字段。明确“历史仅供参考”；新任务标记历史策略，新结果不显示无意义的“过期 0”，旧任务仍标注“旧规则”以保留真实历史。
5. **文档**：更新指南、README 和 v2.10.3-go 发布说明；订阅示例不再建议 stable=1，否则来源端仍会过滤只有一次成功的线路。

## 不变项

- JSON 数组、来源 zai/usable/zcode 附加探针和失败标记校验不变；不扩大到任意 TXT/其他平台订阅。
- 公网地址、协议、去重、禁止/暂缓重入、池容量、每轮数量、并发、单目标和整体任务超时不变。
- 真实本机 ZCode 配置入口探测仍必需，不发送模型请求或账号凭据，不因外部标记可用而直接入库。
- 原子提交、配置 revision、取消、手工线路保护、账号绑定及阶梯冷却不变。
- 自动同步、新线路自动启用的默认值和用户已有设置不变。
- 本轮不修改 PRX 源码或服务器配置，不自动访问真实订阅/代理。

## 回归与实施顺序

1. 先提交新回归到工作分支，使用远端 CI 观察旧规则拒绝合成旧记录/一次成功候选的失败信号。
2. 修改解析和 Store 两个判定点，更新因产品规则变化而不再适用的旧断言；不删除其他安全/事务/超时断言。
3. 覆盖 321 条合成数据、旧配置升级、缺失/异常参考字段、排序、Manager 经过本机探测、Store 允许旧历史而拒绝过期本机结果。
4. 更新 UI 回归：旧字段消失且不提交，当前策略提示正确，旧任务统计保留，连接/任务预算依然可见。
5. 本机仅阅读、修改、格式化、差异检查，以及生成必须提交的 frontend/dist；自动化测试、竞态和静态检查仅在 GitHub Actions Ubuntu 执行。
6. 最终发布提交完整分支 CI 通过后快进 origin/go-rewrite，再推 v2.10.3-go 标签；release.yml 复用完整 CI 后才上传附件/镜像。
7. 下载并校验五个附件的 SHA256，核对版本镜像/latest 摘要和 linux/amd64、linux/arm64 架构。不以标签推送成功代替发布完成。

## 验收

- 合格地址和来源标记相同的情况下，旧成功时间、仅一次成功、缺失历史不再让候选被提前拒绝。
- 新任务必须经过本机探测，失败不能入库；过期本地探测、取消、并发配置变化等仍被阻止。
- 更新后的历史策略对已有 120 分钟等配置立即生效，无需用户调大数值。
- 本次只能承诺取消历史硬门槛，不能承诺实际代理仍可用或全部 321 条都能导入。
