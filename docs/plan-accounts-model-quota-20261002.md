# 账号池按模型汇总额度

目标版本：`v2.9.4-go`。

## 问题与计划

上个版本只替换了仪表板的跨模型额度统计，账号池仍在前端遍历 `liveAccounts`，
把所有模型的 `total` 和 `remaining` 混合累加到“总额度（剩余）”卡片。
下方账号明细原本已经按模型、套餐分别列出，保留这些明细，避免丢失套餐周期和到期信息。

1. `/admin/api/accounts` 新增 `model_quotas`，复用仪表板状态接口使用的 `SummarizeModelQuotas`。
2. 汇总固定为非归档账号全池口径，不受列表的筛选、分页、归档区展开或批量勾选影响。
   保留停用、冷却、失效账号的账面快照，与仪表板一致；不等同于当前可调度额度。
3. 账号池删除混合额度卡和前端累加逻辑，复用 `ModelQuotaCards` 分别展示两个模型的总额、已用和剩余。
   沿用现有中性色卡片、等宽数字和绿色/琥珀色进度；桌面并列，窄屏堆叠。
4. 新数据由已有账号查询取得，不另发 `/status` 请求；保留 5 秒轮询。
   单号/批量额度刷新、领取、删除、归档等操作既有的账号查询失效机制同时更新汇总。
5. 复用未知值、零额度、部分数据的处理规则；不修改数据库、请求调度和上游扣费逻辑。

## 验收与发布

- HTTP 测试：账号接口与状态接口汇总完全一致；筛选和分页不缩小总额；归档不计入；更新后及时反映；无额外上游查询。
- 前端测试：账号页真实挂载双模型卡，不再显示旧合计；筛选不改变总额；单号刷新后更新模型额度；保留套餐明细。
- 运行全量 Go/前端测试、构建和产物一致性检查，检查浏览器显示。
- 推送当前分支，CI 成功后推送 `v2.9.4-go` 标签，确认二进制与双架构镜像发布完成。
- 保留现有三个未跟踪项目，不纳入提交。

## 本地验证记录

- 前端 7 个测试文件、21 项测试通过；生产构建通过。
- 后端新增账号汇总及原有额度汇总回归通过，`go vet`、编译通过。
- 本机全量测试的失败均为 Windows 临时目录清理错误（非业务断言）；发布前须通过远程 Linux 全量测试及 race。
- 浏览器模拟数据验收：账号池两张模型卡正常显示，明细筛选后汇总保持不变，恢复“全部”后套餐明细完整显示。
