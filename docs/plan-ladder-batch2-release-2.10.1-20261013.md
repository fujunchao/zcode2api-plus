# 阶梯冷却恢复、第二批修复与 v2.10.1-go 发布计划

## 基线与目标

- 起点：v2.10.0-go / `771f068b9899e8f4385b5777f921f869d22b7f65`。
- 独立工作树，分支 `codex/ladder-batch2-2.10.1`；只推 origin，所有 gh 命令指定 fujunchao/zcode2api-plus。
- 根据用户使用反馈恢复默认纯阶梯冷却，不把代理相关性描述成已证实的唯一风控原因。
- 第二批限于 SSE 成帧/用量一致性和 API Key 兑换的业务错误归因；保留上一版账号权益头保护。

## 一、冷却策略

- `ZCODE_RISK_SILENT_HOURS` 默认改为 0，不再在阶梯外叠加 24 小时静默。
- 保持 5 / 15 / 60 分钟阶梯、超档失效、成功清连续计数；保留风控观测历史。
- 显式设置的额外隔离仍兼容；部署若曾固定为 24，须改为 0 或移除覆盖。
- 不自动复活失效、停用、归档、额度耗尽账号，不修改代理配置、换线机制、停止换号阈值和重放保护。
- 默认行为测试改为验证阶梯到期重新入池；24 小时保护改为显式配置用例，保留原断言。
- 修正前端“默认 24 小时”提示并生成 frontend/dist；本机构建只用于必须提交的产物。

## 二、SSE 按完整事件解析

- 建立小型共享成帧器：处理空行分隔、多行 data、冒号后有无空格、LF/CRLF、event 字段及 EOF 尾事件。
- 原生 /v1/messages 保持字节级透传；只修复其旁路用量统计。
- UsageCollector 的累计输入/输出/cache 和终值判据基于完整 JSON 事件，不再逐 data 行解码。
- 异步转发使用同一成帧逻辑，避免合法多行或 data: 后无空格时静默丢消息。
- 异步 event-only 事件在 payload 缺少 type 时补上类型，保持现有 ticket/chunk/done 外层契约。
- 保留累计值取最大、不重复落账、最终 usage 与 message_stop 分离、取消不伤账号/线路、上游 error 不冒充断流等既有行为。
- 不混入新的模型、消息内容能力或无依据的限制调整；异步现有扫描上限保持。

## 三、API Key 兑换错误

- 通过公开 ExchangeAPIKey 的完整 HTTP 链验证，不只测试私有 JSON 辅助函数。
- 业务登录、机构查询、Key 列表、创建与复制均先校验业务 code；HTTP 200 不代表业务成功。
- 兼容已有缺省/数字 0/字符串 0 成功形态；401 给明确的业务认证失效信息，不误报“缺机构/项目”。
- 失败即停止后续请求，不回显真实令牌，不把业务错误归为代理不可达。
- 不修改主 OAuth code→JWT 流、不增加全局登出；可选 API Key 兑换失败不删除已保存 JWT。

## 四、回归边界与反馈顺序

全部使用隔离目录、合成凭据、httptest HTTP/TLS 服务；不读取 data/，不向真实账户服务发送测试请求。

1. 先提交原生多行 SSE 用量回归，远端证明旧代码漏计，再实现成帧/统计与四入口对照。
2. 冷却覆盖默认阶梯、显式隔离、成功重置和超档失效，包含同步/异步与人工恢复。
3. SSE 覆盖多行、无空格、CRLF、跨读取块、event-only、EOF 无尾空行、重复/迟到用量、畸形 JSON、断流和 error 事件。
4. API Key 兑换通过受控传输把目标请求全部限制到本地 TLS 服务，覆盖各步骤 200/401、其他业务失败、合法成功和不继续创建/复制。
5. 既有测试若缺失合法 SSE 事件分隔，修正夹具为真实协议形态，保留用量和终态的精确断言，不用删测试掩盖问题。

已完成静态缺口定位，不重复广泛猜测；每个修复使用对应远端失败日志形成反馈。所有 Go 构建、静态检查、自动化测试和竞态检测均在 GitHub Actions 执行。

## 五、发布门禁

- 版本更新为 2.10.1-go，客户端声明保持 3.15.1。
- 本地只阅读、编辑、格式化、差异检查；前端只为生成 dist 运行构建。
- 推工作分支，等最终 SHA 的完整 ci.yml 成功后才快进 origin/go-rewrite。
- 同一提交主线 CI 通过后推 v2.10.1-go，不强推、不覆写已有标签。
- release.yml 仍复用完整 ci.yml，成功后才发布五个平台二进制及双架构镜像。
- 核对附件、GHCR 版本/latest 清单和实际远端提交；保留用户原工作区资料，收尾再安全快进同步。
