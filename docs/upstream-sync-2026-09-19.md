## 本轮未做

1. **`handleUpdateSettings` 全量校验后批量落库**（`5dc6b44` 的一半）：现在的写法仍是
   「验证一段写一段」，中途失败会留下半套生效的配置，而管理员看到 500 以为整批没生效。
   需要重写整个 handler（我们的设置项比上游多：claim 三项、代理巡检两项、cap 三项…），
   本轮未纳入。
2. **前端 `accounts.tsx` + `frontend/dist` 重建**（`8131176` 的 UI 部分）：后端已改为
   删除失败回 500 并带 `failed` 列表，前端据此提示更准确；改前端需要重建 dist 再入库，
   建议单独一次做。`guest.tsx`（含 SRI）我们没有该页面，不适用。
3. **`securityHeaders`（CSP / X-Frame-Options / nosniff）**：后台金钥存在 localStorage，
   而 localStorage 以 origin 为界不分路径，上游加 CSP 是有道理的；但我们的前端与上游
   不同（没有 guest 页），照抄其白名单有把后台页打死的风险，**应先审计前端的外部脚本
   来源**再上。
4. **`ac896d7`（claim/quota 共享直连 client）**：纯性能优化，收益是复用连接、减少
   TIME_WAIT；不影响正确性，故未纳入本次。
