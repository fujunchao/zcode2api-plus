# v2.14.0-go

升级默认客户端身份到 **ZCode 3.18.0**，并修复 3.18.0 档案在首轮/续轮与旧版本回退路径上的提示词装配问题。

## ZCode 3.18.0 身份升级

- 新增 3.18.0 专用 system 档案：API 校验的 CLI Prefix（35 B）与 Agent Identity（1,233 B）逐字节取自 3.18.0 客户端，动态块 1,595 B；默认 `ZCODE_CLIENT_VERSION` 切到 `3.18.0`。
- 3.18.0 的 Environment / Desktop Context 不再放在 system，改为首轮 `role=user` 的 `<system-reminder>`；网关按官方装配顺序注入「环境 → currentDate → 用户正文」。
- 网关无状态，调用方历史不含出站时附加的提醒；**续轮也补基础环境提醒**（历史已有提醒或首条 user 是 tool_result 时仍跳过），避免模型从第二轮起丢失环境。
- 旧版本回退更干净：3.16/3.17 的 Prefix、Identity、旧动态第三块与独立 `# Environment` 块在 3.18 回退重建时会被精确剥离，只保留调用者真正追加的自定义后缀，不会把旧 Desktop Context / Environment 漂进新 system。
- `zcode2api probe` 增加第三块 dynamic 指纹输出，dry-run 可直接核对 `35 / 1,233 / 1,595` B 与三项 SHA16；服务器单账号真实请求已验证 200、无 3012。

## 其他修复

- 验证码配置按 3.18.0 客户端语义严格校验：`code` / `success` / `enabled` / `skip_model_request` 的类型与互斥必填关系对齐客户端；配置不完整时明确报错，不再静默透传。
- OpenAI 兼容流（Chat Completions / Responses）对上游 MCP 与内建服务端工具块做占位处理：不把已由上游执行的 `mcp_tool_use` / `server_tool_use` 等投影成客户端要执行的 `tool_calls`，并安全丢弃同 index 的参数增量，避免整条本可正常收尾的流被误判为协议错误。
- 补充 3.18.0 档案字节、首轮/续轮提醒、旧模板剥离、验证码配置、OpenAI 未投影块等回归测试。

## 升级说明

- 默认身份已切到 3.18.0，无需手工数据库迁移。
- 回退：`ZCODE_CLIENT_VERSION=3.17.2`；若显式设置过 `UPSTREAM_USER_AGENT`，同步改为 `ZCode/3.17.2`。
- 旧 3.17.x 客户端经本网关访问时会自动走旧模板剥离路径，不需要改客户端。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.14.0-go` 与 `latest`。
