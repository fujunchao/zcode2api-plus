# v2.0.8-go

把伪装客户端版本升到 3.11.2，让上报给上游的设备信息与请求头自洽，
并修掉后台手动「領取活動套餐」要先点一次「刷新資格」才会成功的 bug。

## 新增内容

- **客户端版本伪装升到 3.11.2**：`ZcodeClientVersion` 由 3.7.7 升至
  3.11.2，对齐官方客户端（与 zcode-switch 的 `CLIENT_APP_VERSION` 一致）。
- **设备伪装三项可配置**：新增 `ZCODE_CLIENT_OS_VERSION`（默认
  `10.0.26100`）、`ZCODE_CLIENT_LANGUAGE`（默认 `zh-CN`）、
  `ZCODE_CLIENT_TIMEZONE`（默认 `Asia/Shanghai`），与
  `X-Platform: win32-x64` 自洽。

## 修复内容

- **激活事件体与请求头自相矛盾**：此前设备字段跟随网关容器的运行
  环境——`device_os_category` 由 `runtime.GOOS` 得出 `linux`、
  `device_os_version` 恒为空串、`client_language` 回落 `en-US`、
  `client_timezone` 取到 `UTC`，而请求头同时声称 `win32-x64`，上游
  交叉比对即可判定非官方客户端。现在这四项统一读伪装配置；新增
  `DeviceOSCategory(platform)` 从 `ZcodeClientPlatform` 派生系统分类
  （win→windows、mac→macos、linux→linux，无法识别才退回运行环境）。
- **手动「領取活動套餐」必失败**：后台手动领取的代码路径漏掉了当日
  活跃上报，只有「刷新資格」与定时/入池路径会补——上游按「官方客户
  端当日活跃」判定投放，所以手动领取拿不到套餐、必须先点一次刷新。
  现已补上，账号页的领取按钮直接可用。回归测试
  `internal/claim/telemetry_test.go` 钉住字段映射与取值。

## 使用说明

伪装字段都有默认值，默认行为与旧版兼容，无需改配置。要贴近特定客户
端时可用 `ZCODE_CLIENT_VERSION` / `ZCODE_CLIENT_OS_VERSION` /
`ZCODE_CLIENT_LANGUAGE` / `ZCODE_CLIENT_TIMEZONE` 覆写，但务必与
`ZCODE_CLIENT_PLATFORM` 保持一致（改了平台就要一起改系统版本，否则
事件体又会与请求头不一致）。账号页的「領取活動套餐」按钮现在直接可用，
不需要先点「刷新資格」。

[客户端兼容说明](https://github.com/fujunchao/zcode2api-plus/blob/v2.0.8-go/docs/client-compatibility.md)

## Docker

```bash
docker pull ghcr.io/fujunchao/zcode2api-plus:2.0.8-go
```

支持 linux/amd64 和 linux/arm64，同时更新 latest。现有数据卷与非
root 运行方式不变。
