# v2.9.11-go

面向“服务器 Docker 网关 + 本地 API 客户端”的透明兼容修复。
不把本地客户端改造成 ZCode 桌面代理，不复制私人上下文或完整官方工具表。

## 调用者指令优先

- 新增 `ZCODE_PRESERVE_CLIENT_CONTEXT`，默认 true。已有 system/instructions 原样保留其语义，
  包括显式空字符串/空数组，不再叠加另一份网关身份和环境。
- 完整客户端系统块不会因与网关标准块不全等而被额外扩成五块；不通过关键词删除用户指令。
- 完全没有系统指令的 JWT 请求仍使用原有兼容兜底；已有消息内 system 时不另补网关环境。
- false 恢复旧版系统提示前置/精确去重与 OpenAI 指令统一提升，原有回退行为继续有回归覆盖。

## 中途系统消息（MCS）

- Chat/Responses 的初始指令进入顶层，会话开始后的 system/developer 保持原位置，
  不再把后续规则提前合并到整个历史的最前面。
- 原生 system 字符串不会被反向改成文本块；只把单个无额外属性的纯文本块压成字符串，
  保留缓存策略、扩展属性和多块内容。
- 同步与异步共用出站能力声明：实际含消息内 system 才合并
  `mid-conversation-system-2026-04-07`，去重并保留客户端其它 beta。
- 没有 MCS 的请求不自动补头，不注入技能轮次；不改变两种账号的鉴权及路由。

## 显式参数与本地工具

- thinking=enabled 不再因缺少 budget_tokens 被丢弃；不猜测预算，仍移除 clear_thinking，
  有预算时继续校验其与总输出上限的关系。
- 保持默认 8192 输出上限和显式 effort；不统一提高到官方桌面的 128000，也不强制 max。
- 保留本地客户端声明的工具、调用 ID 和结果关联。网关不增加 shell、文件或搜索执行器。
- 下游 JSON/SSE 交付、流式结束/异常/取消、账号调度、并发限制、签名策略和 OS 档案不变。

## 回归与发布门禁

新增公开 HTTP 入口回归，覆盖原生 Messages、Chat、Responses 和异步实际出站；
包括空指令、消息顺序、并行工具历史、缓存/扩展字段、beta 合并、旧行为回退及参数保留。
已有 Python SDK、Pi、全量 Go 测试和竞态检测继续执行；Compose 额外验证回退环境变量能进入容器。

测试只使用合成凭据、隔离目录和本地 httptest 上游，不读取运行 data/ 或真实账号。
自动化检查统一在 GitHub Actions Ubuntu 执行；版本标签仍须通过 release.yml 复用的完整 CI，
成功后才能发布二进制与镜像。上述回归不替代真实账号的生产运行观测。

## 升级与回退

无需数据库迁移，替换镜像/程序后重启。现有本地客户端不需要更换 API 地址或工具格式。

- 版本镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.11-go`。
- 滚动镜像：`ghcr.io/fujunchao/zcode2api-plus:latest`。
- 镜像平台：linux/amd64、linux/arm64。
- 二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。

需要恢复旧上下文行为时设置 `ZCODE_PRESERVE_CLIENT_CONTEXT=false` 并重建/重启容器。
仓库 Compose 模板已转发此变量；使用旧模板时必须加入 environment，只有 `.env` 文件并不会自动生效：

```yaml
environment:
  ZCODE_PRESERVE_CLIENT_CONTEXT: ${ZCODE_PRESERVE_CLIENT_CONTEXT:-true}
```

该开关仅回退上下文处理，不关闭现有鉴权、额度统计、流完整性检查或发布门禁。
