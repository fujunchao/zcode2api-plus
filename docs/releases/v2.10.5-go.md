# v2.10.5-go

## 严格代理闭环

- 以十分钟窗口内的完整模型 405/3012 与成功对照判定异常路由；单次失败、重复日志、截断错误、3xx、无终帧、缺消息 ID、错误目标或证据容量丢失均不能凑足删除条件。
- 达标后立即停止新派发，再原子提交禁止记录、代理删除、改派和自动等待补绑；已交付的流不重放。
- 后台/CLI 新增与导入、登录、模型、领取/额度、巡检、断流、空额度清理及订阅共用准入；旧线路/凭据/绑定代次不能操作新配置。
- 无合格代理允许直连；人工直连不被补绑覆盖，手工无效路由明确报错。严格禁止记录不因 24 小时到期、改名、换 ID 或重启自动解除。
- 增加受管理员鉴权保护的严格状态、事务恢复、带决定确认的人工解除接口；`strict_proxy_enabled=false` 只关闭新判定，不复活已删代理。

## 协议与在途身份

- 保留经过验证的可选 query-source；异步票据保存版本化逻辑归因、兼容旧内存票据并防止终态重投。
- desktop 默认前缀缓存布局与真实无 Gen UI 能力说明按网关生成路径修正，保留调用者上下文、工具、显式空值及 MCS。
- 错误体和原始 HTTP 状态不被等待字段改写：风险预算耗尽与本地重放保护提供真实剩余 `Retry-After`；普通 503/3009 仍按原规则恢复。
- 账号内部凭据代次不增加导出 JSON 字段；旧请求即使遇到凭据 A→B→A，也不能覆盖新健康、额度、领取状态或 Key。已经消费的 token 仍按账号累计。
- 非模型认证/来源头按实际接口区分，默认账号出站明确直连或代理，禁止隐式重定向携带敏感正文；非法代理 URL 诊断不回显凭据。

## New API 配合

提供固定 rc.41 提交的**可选、默认关闭**重试消费补丁及五个归因头的精确配置。Ubuntu CI 在该版本真实 controller、adapter、service 上分别验证原版缺口和补丁行为，包含多值拒绝及正常重试保留。

这不是现网升级：需由部署方先核对当前 New API 版本、渠道和 BaseURL，再按[消费端说明](../analysis-newapi-retry-contract-v3-20261014.md)单独应用。网关发版不会自动修改现有 New API。

## 升级与验证

- 发布门禁复用完整 CI：工作流、前端、Go build/vet/全量及重复回归/race、SDK、跨平台、Docker、New API 原版/补丁合同、Windows 恢复日志专项。
- 测试只使用合成凭据、隔离 SQLite、本地 HTTP/TLS；没有在开发机运行自动化测试、读取运行数据或修改生产服务器。
- 新内部代次、禁止记录、路由意图保存于既有 meta；恢复日志与数据库需共同保留。没有前端产物变更。**不要直接回滚到无法识别严格禁止状态的旧版本。**
- 边界：单副本；异步仍是进程内队列；没有默认开启缺乏可信 CallerScope 的托管会话/软粘号；没有重写 TLS/压缩栈，也不保证供应商不再返回 405。
- 详细矩阵与运维接口见 [v3 实施说明](../implementation-v3-strict-proxy-20261014.md)。
- 镜像：`ghcr.io/fujunchao/zcode2api-plus:2.10.5-go`，Linux amd64/arm64；发布成功时更新 `latest`。
- 二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
