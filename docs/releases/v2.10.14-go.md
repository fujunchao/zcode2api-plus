# v2.10.14-go

## 计费异常不再直接删除代理

- 修复额度刷新等待响应头超时就删除整条共享代理的问题。余额查询、套餐领取和资格预览的传输失败或可疑请求只记录异常，保留节点、业务绑定、成功额度快照、已有领取记录和冷却。
- 有效异常按节点合并为统一网络复核通知，不用计费失败凑网络删除证据。仍须真实首轮、延迟复核和健康参考；恢复或参考共同异常时保留节点。基础网络层关闭时仅记录，不隐式开启模型请求。
- 通知十分钟过期、同节点两次消费至少间隔五分钟、最多 1,024 个节点；配置、账号凭据、绑定或线路代次变化会丢弃旧通知，重启不续用。

## 默认出口与手工节点保护

- 当前默认业务出口及托管账号仍引用的默认出口自动受保护，同路由别名不能绕过。
- 代理新增／编辑页增加「禁止自动删除」，当前页面新增手工节点默认开启；列表显示有效保护原因。编辑停用节点不会顺手将其启用。
- 故障自动删除、断流熔断、登录失败清理及新严格模型退役决定统一遵守处置模式和节点保护。仅观察不会通过这些路径删除节点或连带改派；显式手动删除仍可操作。
- 受保护节点仍会显示真实异常，不自动标成健康或永久禁止；管理员可以主动停用或调整。网络确认失败时明确显示「受保护未删除」。

## 升级与验证

代理 JSON 增加可选字段 `auto_delete_protected`，无需手工改库；旧 API 更新省略此字段会保留已有保护。已有普通节点不统一改成受保护，已有默认节点自动享受默认出口保护。

不会恢复历史上已删除的节点，不解除账号冷却、风控终态或已持久化的严格退役记录。家庭节点若已被删除，仍需重新添加并选为默认出口。20 秒额度请求时限不变，修复的是失败处置而非放大超时。

回归覆盖真实 HTTP 额度超时、共享账号绑定、恢复、领取冷却、默认与手工保护、同路由别名、并发合并、限频、旧身份、持久化、统一网络复核和前端交互。所有自动化验证由 GitHub Actions 执行，分支完整 CI 与发布工作流复用的完整 CI 均为门禁。
