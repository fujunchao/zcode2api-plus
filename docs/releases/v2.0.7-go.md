# v2.0.7-go

领取这一层补上「可设定 + 可定时」，修掉一个 CI `-race` 抓到的领取状态竞态，
并把 Docker 镜像的 Chromium 运行库清单按实测补齐。

## 新增内容

- **领取设定进后台「系統設定」页**：入池自动领取开关、每日定时领取开关与时间、
  三个冷却时长（验证码冷却 / 失败冷却 / 刷新节流）都能在页面上直接改，**改完即生效**
  （调度器与领取路径每轮重新读取，无需重启）。环境变量 `ZCODE_CLAIM_*` 降级为默认值——
  页面上没有写过的键才回退到环境变量。
- **每日定时领取**（默认**关闭**）：时间可配（默认 23:00，本地时区）。到点对池内全部
  JWT 账号顺序领取一次：尊重上游给的 `claim.next_at`（刚领过的跳过）、**错过不补跑**、
  账号间隔 1s、抢不到串行闸门时限时等待而不是丢账号，结束记汇总日志。
  默认关闭是刻意的——升级或新装不该在你无感知时自发产生每日上游流量。

## 修复内容

- **领取状态的并发访问加锁**：CI 的 `-race` 在监控与领取并发时抓到真实数据竞争
  （后台领取 goroutine 写 `Account.claim`，同时后台快照与落库序列化在读）。
  现在读写统一走 `SetClaimState` / `ClaimView`，序列化由 `MarshalJSON` 在锁内完成，
  已发布的状态视为不可变、整体替换。回归 `TestClaimStateConcurrentAccess` 钉住该不变量。
- **Docker 镜像补全 Chromium 运行库**：apt 清单与上游对官方补丁二进制的 ldd 实测结果
  对齐，补上 `libxi6`、`libvulkan1` 等 18 个包——其中两个不在其他包的依赖闭包内，
  此前可能在容器里表现为「JWT 账号一直 503」（CI 只构建不运行，抓不到这类缺失）。
- 文档清理：`Dockerfile` / `docker-compose.yml` 注释改为简体（与仓库配置注释约定一致）、
  `go.mod` 顶部注释更新、`PLAN.md` 台账补齐勾选。

## 使用说明

无需改动任何配置，默认行为与旧版兼容。升级后可在后台「系統設定」页调整领取行为；
每日定时领取默认关闭，需要时手动打开。冷却与开关只约束自动路径，
账号页的手动「領取活動套餐」按钮永远可用。

[客户端兼容说明](https://github.com/fujunchao/zcode2api-plus/blob/v2.0.7-go/docs/client-compatibility.md)

## Docker

```bash
docker pull ghcr.io/fujunchao/zcode2api-plus:2.0.7-go
```

支持 linux/amd64 和 linux/arm64，同时更新 latest；现有数据卷与非 root 运行方式不变。
本版镜像的运行库清单已按 ldd 实测补全，验证码浏览器在容器内更可靠。

## 能力依据

- [Z.AI 官方文档](https://docs.z.ai/)

`claim.next_at` 取自官方客户端 billing/claim 与 billing/preview 响应里的 `data.plan.ends_at`。
Chromium 运行库清单对齐上游 `deploy/manage.sh` 中由 ldd 对官方 linux-x64 补丁二进制
实测得出的列表（bookworm 用非 t64 包名）。

定时批量的上游节奏（账号较多时 1s 间隔是否合适）与真实账号领取一次仍待在线观察。
