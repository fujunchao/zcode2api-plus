# v2.10.30-go

## 账号池新增「无额度」派生分组

v2.10.29 的生产窗口里有一类账号反复出现：**额度列显示「未取得」、状态仍是「正常」**。
本版给账号池加一个与「异常」组同型的派生筛选 tab，把它单独圈出来，便于批量停用、删除
或刷新额度。**只改前端筛选口径，不动后端、不落库、无数据迁移。**

### 这批账号是怎么来的

体验套餐（Start Plan）到期后，上游 `billing/balance` 可能返回成功但 `plans`/`balances`
为空。当前实现会把这个响应如实写进账号快照：

- `Quota` 与 `Plans` 被清空为 `{}`，状态**保持不变**（仍是 `active`/`cooling`）；
- 只写一条 `last_error="账号未返回可用套餐额度"`，不写错误类型；
- 于是它不会出现在「用完」「异常」「初始化」「停用」任何现有分组里；
- 又因为空快照账号的模型可用性是 `unknown`，池子里没有更优候选时仍可能被选号，
  以一次上游失败为代价。

「未取得」本身有两种来源：**上游成功返回空快照**（体验套餐到期常见），或**额度查询从未成功**。
本分组按「额度快照为空」的直观口径收口，两者都计入；tooltip 与本节都明确这一点。

### 分组口径

命中（全部满足）：

1. 非归档 JWT 账号；
2. 不处于初始化阻塞（「初始化中」「待固定代理」留在「初始化」组）；
3. 状态为 `active` 或 `cooling`；
4. 额度快照为空（`quota` 为空对象或 null）；
5. 排除本地风控隔离（`risk_isolation`）与探测专用账号；
6. 排除 `exhausted` / `invalid` / `disabled` 与 apiKey 账号。

因此：初始化中的新号、已用完、已停用、失效账号都不会混进本组；**直连新增、尚未取额、
又没有初始化任务的账号会被计入**——这是「所有无额度」口径的已知边界，删除前可通过状态
徽章与 tooltip 识别。

### 交互

- 顶部新增「无额度 <数量>」胶囊，位置在「用完」与「异常」之间；
- 计数与列表共用同一谓词，计数为全池非归档命中数，**不随错误类型筛选变化**；
- 与「错误类型」筛选取交集；切换分组或错误类型时清空勾选（沿用既有规则）；
- 勾选后复用现有批量栏：批量停用/启用/恢复/补入初始化/**批量删除**（确认弹窗 +
  `missing_ok` + 只提交当前可见选中项）；行内删除按钮不变；
- 空列表显示「暂无符合筛选条件的无额度账号」，0 数量入口仍然保留；
- 按钮 tooltip 写明口径边界。

## 兼容性与回滚

- 后端、接口、`accounts.data` 键集、调度规则全部未改；
- 无数据迁移；撤销本版前端即可回到原行为；
- 已知边界：本分组是「快照为空」的展示口径，不区分「套餐到期」与「查询从未成功」，
  也不提供到期时间。后续若需要精确的「到期事实」，可另做持久化字段（本次刻意不做）。

## 回归覆盖

新增 `frontend/test/accounts-no-quota-filter.test.tsx`：

- 计数与命中矩阵：active/cooling/空对象/null 命中；初始化阻塞、待固定代理、本地隔离、
  探测专用、停用、失效、用完、apiKey、归档、有额度均不命中；
- 零数量入口仍显示 + 专属空态文案；
- 与错误类型筛选取交集，分组计数不变；
- 切换分组/错误类型清空勾选；
- 批量删除只提交可见选中项且必须先确认（`missing_ok:true`）;
- 额度恢复后账号自动退出分组、计数同步更新。

自动化验证由 GitHub Actions 执行；分支 CI 与发布工作流复用的完整 CI 均为门禁。
