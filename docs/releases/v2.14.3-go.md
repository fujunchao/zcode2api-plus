# v2.14.3-go

同步伪装身份到 ZCode 3.19.1：新增独立的 3191 文案档案，默认客户端声明与 Compose 一并抬到
`3.19.1`。本版**不改变任何 HTTP 契约**——模型 API 路径、请求头、body 字段、能力头、
官方模型目录与 3.18.2 逐项一致；变的只有网关自建 system 的第三块内容。

## 背景

ZCode 3.19.1（2026-11-22 发布，本机实装 `3.19.1.10833` / build `60f20117`）做了全量静态逆向：

| 项目 | 3.18.2 | 3.19.1 |
| --- | --- | --- |
| block0 CLI Prefix | 35 B / `7779642e…` | 同字节 |
| block1 身份段 | 1,233 B / `aac4ba4c…` | 同字节 |
| block2 动态行为 | 1,595 B / `26a2daa8…` | **4,564 B / `929856d5…`** |
| Desktop Context | 1,100 B / `39a1e86c…` | 同字节 |
| 模型 API 路径 / 头名 / body 字段 | — | 增删 0 |
| 官方模型目录（两份 `zcode-builtin.json`） | rev 44 / rev 30 | 逐字节相同 |

第三块新增 `# Finishing work`（1,304 B）与 `# Memory, notes and feedback`（1,712 B），
`<total_tokens>` 由固定文案改为 `totalTokensReminderEnabled` 开关（默认关闭，开启时 4,615 B）。
因此 **3.19.1 不能别名到 3180 档案**：首两块相同只说明「3.19.1 客户端带着完整上下文进来时
仍可原样保留」，不代表档案可复用。

## 改动

- `internal/config/zcode_system_profile.go`：新增 `ZcodeSystemProfile3191`，`3.19.1` 精确映射；
  `UsesUserReminderEnvironment()` 同时覆盖 3180 与 3191（环境仍走首轮 user 的 `<system-reminder>`）。
- `internal/upstream/zcode_system_3191.json`（新）：三块 35 / 1,233 / 4,564 B 与 1,100 B 桌面上下文，
  逐字节取自 3.19.1 随包 CLI 的静态重建（AST 白名单求值，不执行客户端代码）。
- `internal/upstream/request.go`：新增 embed、档案来源分支，并把 3191 模板并入
  `knownOfficialTemplates`（旧模板剥离要能识别它）。
- `internal/config/config.go`：默认 `ZCODE_CLIENT_VERSION=3.19.1`；产品版本 `2.14.3-go`。
- `docker-compose.yml`、`.env.example`、`README.md`：默认值与回退说明同步到 3.19.1 / 3.18.2。
- 测试：新增 `system_profile_3191_test.go`（字节与指纹、档案隔离、桌面上下文、
  保留路径、旧模板剥离、环境提醒）；`version_test.go`、`version_env_test.go`、
  `zcode_system_profile_test.go`、`system_profile_test.go` 的默认值与映射期望同步。

## 行为影响

- 调用者自带官方首两块（3.18.x / 3.19.x 客户端）时仍**原样保留**其完整上下文，不重写第三块。
- 第三方 harness（首段非官方前缀）走回退重建：网关自建的三块改为 3.19.1 文案，
  每请求约多 3 KB system（约 800 token），只影响这条路径。
- 非模型端点（额度、领取、验证码配置、遥测）的 `app_version` 随常量自动变成 3.19.1。

## 升级与回退

- 无需数据库迁移；接口、配置项与数据结构不变。
- 回退（秒级，无需换镜像）：在 Compose 加 `ZCODE_CLIENT_VERSION: "3.18.2"` 后 `up -d`；
  3180 档案仍随镜像提供。若显式设过 `UPSTREAM_USER_AGENT`，同步改 `ZCode/3.18.2`。
- 部署后先验证再放量：

```bash
docker run --rm -v /opt/1panel/apps/local/zcode2api/data:/data:ro -e ZCODE_DATA_DIR=/data \
  ghcr.io/fujunchao/zcode2api-plus:2.14.3-go probe --dry-run
# 期望 client_version=3.19.1、profile=3.19.1、blocks=3
# 三块 sha16 依次为 7779642ea44a4696 / aac4ba4cc7b555b3 / 929856d5f112c283
```

## 风险

- 档案字节错 1 B 即可能 405/3012（3.17.1 事故形态）：三块字节数与 sha16 已在测试中锁死，
  探针不过立即按上面的方式回退。
- 上游是否已对 3.18.2 收紧无证据（`minCompatibleVersion` 是客户端自指）；抬到 3.19.1
  只会降低「版本过旧」风险。
- 客户端新增的本地能力（文档工具、design 生图、语音、MCP 异步、子任务后台、300 s 共享冷却、
  登录时钟容错、凭据恢复）不进网关，本版不跟进。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.14.3-go` 与 `latest`。
