# v2.10.2-go

## 代理订阅试运行

- 独立 proxy-checker 继续负责获取公开代理与批量检测；本项目新增 JSON 订阅接收、条件筛选、本机复检和增量入池。
- 管理入口：**代理设置 → 配置自动补充**。支持预览、手动导入、定时同步、取消任务、查看历史及管理禁止／暂缓重入记录。
- 升级后**自动同步默认关闭，新增线路自动启用默认关闭**。默认每轮最多复检 50 条、新增 10 条，来源池容量 50 条、并发 4、总预算 180 秒；配置上限允许后续扩大试运行规模。
- 正式启用前建议先预览，再少量导入停用线路核对。修改默认启用设置不会批量重新启用旧线路。

## 订阅要求与检测边界

- 使用 proxy-checker 同仓库的 **JSON 订阅**，不是 TXT 清单；外部建议使用 `zai` 档位、`force` 复测及 `ZAI_AUX_DEEP=1`。
- 接收端校验目标档位、ZCode 附加探针、连续通过记录、最近成功时间及地址格式；拒绝过期数据、非公网候选和异常响应。
- 复检使用本项目的 Go 出站协议实现，仅验证 ZCode 配置入口；不发送账号 JWT、管理密钥、网关密钥，不消耗模型对话或套餐领取额度。
- 配置入口通过不等于模型业务成功，不证明代理不会触发 405；自定义上游 origin 不适用默认探针时不会启动任务。
- 真实订阅地址由管理员在部署实例中配置，不内置到代码、日志或 GitHub Actions。

## 账号、线路与资源保护

- 按代理端点去重，保留已有线路 ID、名称和启用状态；不覆盖手工线路，不主动改派现有账号。
- 导入、来源记录和任务终态同事务提交，失败回滚；预览不导入线路、不顺带清理禁止记录。
- 人工停用、删除、改地址保留原端点的重入限制；来源线路被现有机制自动淘汰后暂缓 24 小时，避免立即再次导入。
- 自动淘汰暂缓与账号阶梯冷却是不同机制。账号单次 405 不因此升级为全局线路封禁，现有冷却和换线规则不变。
- 来源为空、失败或条目暂时缺失不清空现有代理池；池容量、检测并发、响应大小、任务预算及历史记录都有上限。
- 候选传输不进入生产连接缓存；退役端点释放空闲缓存，不中断在途流，也不清理仍被其他线路或账号引用的传输。

## 升级与验证

- 不增加生产运行时依赖，不修改 proxy-checker 业务源码；前端已内嵌。
- 复用现有 SQLite 的内部 `meta` 状态，无需手工数据库迁移。保留原数据卷即可，不自动清除账号冷却、失效、停用或额度状态。
- 本地只进行阅读、格式化、差异检查和必须提交的前端产物生成；完整测试、竞态、静态检查及构建由 GitHub Actions 执行。
- 自动化测试仅使用合成订阅、隔离数据库和本地 HTTP/TLS 模拟服务，未访问用户的真实代理订阅。
- 发布前验证版本提交的完整分支 CI；标签发布再次复用完整 CI，通过后才构建二进制和推送镜像。

## 服务器测试

- 固定版本镜像：`ghcr.io/fujunchao/zcode2api-plus:2.10.2-go`，提供 Linux amd64 / arm64。
- 建议先使用独立容器、端口和空数据卷，保持账号库隔离；不要把“拉取镜像”当成“功能已自动开启”。
- 完整配置和操作步骤：[代理订阅试运行指南](https://github.com/fujunchao/zcode2api-plus/blob/v2.10.2-go/docs/guide-proxy-subscription-trial.md)。
