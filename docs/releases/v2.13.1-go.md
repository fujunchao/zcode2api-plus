# v2.13.1-go

让「上游流式响应中断」不再无条件打断正在进行的会话：断流后的收尾形态改为客户端认得的**可重试**错误，并在尚未产出内容时先尝试换号重打。不改变模型协议、账号调度与计费口径。

- **断流终态可配置**：新增 `ZCODE_TRUNCATE_TERMINAL`，默认 `retryable`——上游在流中途被掐断时补 `event: error` + `error.type/code = overloaded_error`。ZCode 侧据此判定为可重试（`reason=ProviderOverloaded / retryable=true`）并自动重试（其 `maxAttempts=11` 预算此前被 `api_error` 白白浪费，整轮 turn 直接失败）。
- **未出内容时透明换号**：SSE 在「首个内容增量」之前不提交响应头，最多缓冲 `ZCODE_TRUNCATE_PREBUFFER_MS`（默认 12s）/ `ZCODE_TRUNCATE_PREBUFFER_BYTES`（默认 64 KiB）。这段期间上游断流会被当作「客户端一个字节都没收到」换号重打，用户无感；全部尝试都失败时返回 **HTTP 502** `upstream_stream_interrupted`（客户端按 5xx 重试），而不是 200 + 错误帧。
- **graceful 可选收尾**：`ZCODE_TRUNCATE_TERMINAL=graceful` 时，在「消息已开始、无未闭合 tool_use 块」的前提下补齐 `content_block_stop / message_delta / message_stop`，本轮按正常结束交付，并追加可见提示 `ZCODE_TRUNCATE_GRACEFUL_NOTICE`。半截工具调用一律降级为 retryable——把工具调用伪装成成功比报错更危险。
- **abort 兜底**：`ZCODE_TRUNCATE_TERMINAL=abort` 不补帧、直接断开连接，客户端按传输层错误重试（用于确认下游网关会丢弃自定义错误字段时）。
- **回滚开关**：`ZCODE_TRUNCATE_TERMINAL=legacy` 完全回到 v2.13.0 的字节形态（`api_error`，不可重试）；`ZCODE_TRUNCATE_PREBUFFER_MS=0` 关闭预缓冲。
- **异步池不在本次范围**：`/async/v1/messages` 的 error 事件是自有票务协议，没有 ZCode 这类客户端消费，保持原样。
- **演练通道**：`ZCODE_DRILL_KEY` 非空时，带 `X-Zcode-Drill: <key>` 的请求由网关直接产出一段可控 SSE（不接触账号池），用于在真实链路（new-api → 客户端）上验证终态字节与客户端重试行为。生产默认关闭。

| 變量 | 默認 | 說明 |
|------|------|------|
| `ZCODE_TRUNCATE_TERMINAL` | retryable | `retryable` / `graceful` / `abort` / `legacy` |
| `ZCODE_TRUNCATE_GRACEFUL_NOTICE` | （上游连接中断，本次回答被截断） | graceful 追加的可见提示；空=不追加 |
| `ZCODE_TRUNCATE_PREBUFFER_MS` | 12000 | 首个内容增量前的预缓冲预算（毫秒）；0=关闭 |
| `ZCODE_TRUNCATE_PREBUFFER_BYTES` | 65536 | 预缓冲字节上限 |
| `ZCODE_DRILL_KEY` | 空 | 演练通道密钥；空=关闭 |
| `ZCODE_LINE_TRUNCATE_STRIKES` | 2（原 3） | 连续断流即摘线路；坏线在「夹着成功」时永远到不了 3 连击 |
| `ZCODE_LINE_TRUNCATE_AVOID_SECONDS` | 600（原 60） | 断流后账号选线回避；60s 只够躲开客户端第一次重试 |

行为差异（同一条上游断流）：

| 场景 | v2.13.0 | v2.13.1 |
|---|---|---|
| 已产出内容后断流 | 200 + `api_error` → 客户端判不可重试 → 整轮失败 | 200 + `overloaded_error` → 客户端自动重试 |
| 尚未产出内容就断流（还有别的账号） | 200 + `api_error` → 整轮失败 | 换号重打，客户端无感 |
| 尚未产出内容就断流（没有别的账号） | 200 + `api_error` | HTTP 502，客户端按 5xx 重试 |
| 上游自己发 error 事件 | 原样透传，不计断流 | 不变 |

无需数据库结构迁移。替换程序或镜像并重启服务即可生效；若部署显式设置了上表变量，需核对实际传入进程或容器的值。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.13.1-go` 与 `latest`。
