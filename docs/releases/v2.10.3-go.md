# v2.10.3-go

## 取消代理订阅的两个历史硬门槛

- 不再因为 PRX 最近成功记录超过两小时或其他旧有效期，就拒绝候选。
- 不再要求连续成功至少两次；一次成功、缺少历史次数的合格候选也可进入本机复检。
- 外部 last_ok 和 pass_streak 只供排序参考，缺失/异常值降为未知，不改成当前时间；明显异常的未来时间不会取得排序优势。
- 解析层与最终入库层同时取消上述判断，避免本机复检通过后又被外部历史挡住。

## 实时检查与保护仍然保留

- 每条候选仍必须通过本项目当次 ZCode 配置入口复检。PRX 标记可用不等于直接入库，也不保证模型业务或长流可用。
- 来源档位/可用性/ZCode 附加探针、失败标记、JSON 格式、公网地址、协议校验不变。
- 连接和任务超时、并发、候选/新增/池容量、去重、人工保护与自动淘汰暂缓不变。
- 本机复检结果的提交时效、取消、配置 revision 和原子提交保护不变，不允许复用过期的本机结果。
- 不修改账号绑定、阶梯冷却、自动同步开关或新线路启用状态。

## 页面与升级

- 移除“结果有效期（分钟）”输入，新页面保存时不再提交该字段。
- 已存的 max_age_minutes 仅保留旧格式兼容，不再影响筛选或入库；升级后直接生效，无需手工重设订阅或修改数据库。
- 新任务记录“历史仅供参考”策略，不再显示无意义的“过期 0”；旧任务仍保留原统计，并明确标记“旧规则”。
- 如订阅地址含 stable=1，PRX 端仍会先过滤连续成功不足两次的条目；希望它们进入本机复检时，需自行移除这个来源过滤参数。

## 验证与使用

- 使用合成的 321 条记录复现旧行为：211 条一次成功、110 条多次成功，全部历史较旧；新规则允许它们进入候选，但仍受实际地址校验和每轮复检数量上限约束。
- 新增历史缺失/异常、排序、当前 HTTP 复检、Store 最终提交、旧配置兼容和新旧任务显示回归；没有将真实订阅或账号数据交给 CI。
- 本机只生成必须提交的前端产物；自动化测试、竞态、静态检查和发布构建均由 GitHub Actions 执行。
- 镜像：`ghcr.io/fujunchao/zcode2api-plus:2.10.3-go`，提供 Linux amd64 / arm64。
