# v2.9.12-go

面向“调用者 → New API → Docker 网关 → 模型上游”的诊断补丁。
补足定位依据，不调整上下文行为、重试预算、账号/代理调度或风控保护阈值。

## New API rc.41 请求关联

- 四个模型入口生成独立 UUID，同时返回 `X-Zcode2api-Request-Id` 和
  `X-Oneapi-Request-Id`。错误响应、重放拒绝与异步票同样可关联。
- 根据 `v1.0.0-rc.41` 固定源码，New API 会将后一响应头保存为日志的
  `upstream_request_id`；它自己的 `request_id` 与用户/令牌映射保持在 New API。
- 无需新增环境变量，不需要最终用户 ID 或全量请求头透传。
  网关忽略入站同名 ID，内部关联头不发给模型上游。

## 可区分的诊断事件

- 新增 HTTP 入口开始/结束日志；请求、出站及收尾诊断补 UTC 时间戳和完整关联 ID。
- 将实际出站请求 ID 与上游**响应**追踪 ID 分开记录；响应头采用白名单与受限形态。
- 补充错误体读取失败原因，区分拿到 405 响应头、错误体读断、完整业务错误及响应超限。
- 新错误元数据包括白名单业务码/类型、嵌套代码、布尔标志、消息长度与摘要；
  不复制消息自由文本、工具参数、代码、API Key 或响应全文。
- 结构摘要记录 system 来源/形态/块数、上下文开关、消息角色数、工具数和实际 MCS 声明。
- 重放保护早退也输出汇总，包含入口内容引用、零出站次数和剩余防护时间；读取不会续期。

旧日志标记与交付协议保留。HTTP 200、流协议完整和模型语义正常是不同结论；
跨账号风险阈值也不等于供应商已经判定正文触发了风控。

## 验证与边界

回归覆盖四个 HTTP 入口、rc.41 响应头读取契约模拟、内部头隔离、SSE 即时刷新、
同步/异步错误体读断、响应头白名单、结构摘要、重放窗口及日志不复制正文。
所有测试使用合成凭据、隔离目录和本地测试服务；自动化验证统一在 GitHub Actions Ubuntu 执行。
现有 SDK/Pi 兼容性、完整构建、全量 Go 测试、竞态检测、前端验证和发布门禁继续执行。

本版没有操作生产 New API 或重放被风控的请求。反代删除响应头、日志未启用、
未收到响应头的连接失败、New API 未落盘的中间重试仍可能使关联不完整。
新增诊断为后续排查提供证据，不承诺消除供应商风控。

## 升级

- 版本镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.12-go`。
- 滚动镜像：`ghcr.io/fujunchao/zcode2api-plus:latest`。
- 镜像平台：linux/amd64、linux/arm64。
- 二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。

替换镜像/程序并重启即可，无数据库迁移、无必填新增配置。
部署后用一次正常调用核对 New API 日志的 `upstream_request_id` 与网关 UUID 对应。
完整字段说明和检索步骤见 [请求诊断说明](https://github.com/fujunchao/zcode2api-plus/blob/v2.9.12-go/docs/request-diagnostics.md)。
