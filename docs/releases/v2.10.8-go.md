# v2.10.8-go

## 模型可用性巡检与交叉对照

- 新增 **代理 → 模型可用性**，与网络连通性分开显示。默认关闭，默认间隔 30 分钟；后台可自行设置 1–1440 分钟，保存后后续轮次生效，无需重启。
- 使用显式选择的探测专用 JWT 请求 `glm-5.3-flash`，最小输出 16 token、低 effort；专用账号不参与普通模型选号或自动领取，原业务绑定不被临时改写。
- 筛查异常后，遵守账号冷却，在十分钟有效窗口内形成两轮新鲜的“参考完整成功／目标 405/3012”才判定线路相关；参考成功过期会先重新核查。
- 支持账号／线路交叉判断；参考组也失败时停止扩散并退避。普通 405、限流、额度、鉴权、验证码、超时、取消、断流和不完整消息不凑成线路删除证据。
- 提供出口组声明，防止同一家庭出口的多个端口冒充独立参考。直连参考默认关闭，初始化中或托管固定出口账号不能用来跨线路探测。

## 两种模式与预算

- 默认仅观察；明确开启自动处置后，未解决的有效目标异常暂避新增绑定，达标则复用现有严格禁止／退役／改派事务，而非普通巡检删除。
- 2.10.7 固定节点的托管账号仍在节点失效后等待，不自动回到取额池或直连；原有默认自动代理分配不因未启用新功能而改变。
- 每次诊断最多 8 次真实模型 HTTP、2 个探测账号、20 分钟；默认滚动 24 小时全局 200 次、单账号 100 次。手动、参考和失败请求均计入本模块预算，重启不清零。
- 后台展示观测覆盖、剩余预算、等待原因、成对步骤、严格规则来源和已确认 token。真实消耗累计到账号，但不增加业务调用次数。

## 一致性与保护

- 账号凭据、持久绑定、代理配置和策略代次均在真实派发前复核；旧响应不能修改新状态。
- 关闭配置或进程终止旧诊断，不续跑半组对照；私有证据因重启或容量裁剪丢失时，持久保留剩余十分钟保护窗口，不借丢失的反证生成新删除决定。
- 新模型探测默认不访问真实账号或服务器；启用时需管理员明确选择账号、目标、参考出口及预算。小请求通过不代表供应商保证出口、长流或所有请求可用。
- 数据沿用现有 SQLite，新增独立巡检历史／请求预算表及版本化元数据；账号导出格式不附带诊断凭据。

## 验证与升级

新增真实本地 HTTP 代理对照、账号相关反例、固定出口等待、过期参考、SSE 完整性、权限／代次、预算与重启、模式准入及存储失败回归；全部自动化由 GitHub Actions Ubuntu 执行，CI 增加十次重复验证，发布继续复用完整 CI。

升级后新功能仍关闭。回退到旧二进制之前，先在新版本停用探测专用账号，或明确解除专用角色并复核业务绑定；不能通过回退清除已持久化的严格禁止。
