# v2.4.0-go

一次**行为修正版**。修的是 async 池与网关之间长期存在的一批不一致，外加同批上游 M11 提交里
被漏掉的 5 个伴生缺陷。全部 11 项都有「先红后绿」的反向验证记录。

> **一处历史更正**：v2.3.3 的发布说明把这个缺口写成「Python 版收 account 参数、Go 版移植时丢掉了」。
> 审计后确认**不是移植问题**，而是我们**逐笔挑拣上游提交时漏了一整批**——上游 2026-09-15 的
> `0d370e5`（async 走账号代理）是 `v2.0.9-go` 的祖先，却没进过本仓库。诊断方法与血缘证据见
> 仓库内 `docs/upstream-async-audit-2026-09-22.md`。
> 教训：**只看 tag/版本号会漏整批**，同步审计必须按「逐文件提交史」走。

## 一、async 出口语义修正（重要）

`POST /async/v1/messages` 现在与 `POST /v1/messages` 一致：**账号绑定了线路就走线路**。

此前该路径恒为硬直连——`Pool.client()` 返回的裸 `http.Transport` 的 `Proxy` 为 `nil`，既不读
`acc.ProxyURL`，也不吃环境代理。后果不只是「连不上」：

- 配了代理的账号在这条路径上**以服务器真实 IP 连上游**（IP 绑定、地区要求、规避风控全部失效）；
- 诊断行的 `route` 只能报 `direct`（见第四节）。

修复形态：`clientFor(acc)` → `proxy.TransportForTimeout(raw, 180s)`；`TransportFor` 拆出
`TransportForTimeout`，**缓存键纳入超时值**，使网关的 120s 与 async 的 180s 各持一份连接池
（否则先到者会把自己的超时固化进共享 Transport）。代理无效时回退直连并记日志，与网关同语义。

**附带收益**：原实现每次调用都新建 Transport，等于每次重试都重新 TLS 握手；现在复用缓存的
连接池，async 路径获得 keep-alive。**上游可见的连接建立频率会下降**，这是预期内的修正。

## 二、async 选号不再被 apiKey 账号打断

`Select` 是 round-robin，一次只回一个账号。此前代码在拿到**非 JWT 账号**时直接以
`no_account` 终止整张票，而且 `tried` 标记记在检查之后——于是下一次轮询可能又选中同一账号。

表现是：池里明明有可用的 JWT 账号，async 请求却**与账号状态无关地间歇性失败**。
现在非 JWT 账号会被跳过并继续选下一个（`tried` 先记后判）。

## 三、async 成功交付的记账对齐网关

成功转发完一条流后，async 此前只累加 token。现在与网关共用 `gateway.MarkSuccess`：
累计调用次数、写入最后使用时间、清零限流/风控/503 三个「连续失败」计数、把 `cooling`/`exhausted`
复位为 `active`。

两处可见变化：

- **后台用量页的 async 流量会跳变**（此前漏算调用次数与最后使用时间）；
- 冷却**已到期**的账号在 async 成功后**立即**恢复调度，不必再等下一轮额度轮询（默认 60s）。

## 四、诊断行 `route` 口径统一（读数语义变更）

`route` 现在取自 `clientFor(acc)`，与网关的 `ProxyLabel` 同口径：走线路报线路名，无代理 /
代理无效回退 / 开关强制直连报 `direct`。

⚠️ **这是一处已发布读数的语义变更**：v2.3.3 起的 async 诊断行固定报 `route=direct`，从本版起
同样的字段会报出真实线路名。若你有脚本按 `route=direct` 匹配来识别 async 路径，请改为按
`ticket=` 字段存在与否来区分（async 行恒带 `ticket=`，sync 行恒不带）。日志行的**格式**未变。

## 五、新增后台开关：Async 強制直連

**系統設定 → Async 強制直連**（设定键 `async_force_direct`，环境变量默认值
`ZCODE_ASYNC_FORCE_DIRECT`，默认关；落库后以后台为准，改动即时生效）。

这是**排障用**的控制开关：开启后 async 忽略账号代理、恒直连上游。存在的理由是保留
「线路侧 vs 上游侧」断流归因的**直连对照臂**——出口语义修好之后，那根本来靠实现缺陷得来的
对照组就没了，改由显式旋钮提供，两个方向都可复现，诊断行读数在两个方向上都如实。

⚠️ 开启后配了代理的账号会以服务器真实 IP 直连上游（与第一节描述的风险相同）。仅建议在取数
作证时临时打开，取完关掉。

## 六、async 入口模型名归一化

async 此前直接用原始模型名判白名单，而网关是先归一化（去 `provider/` 前缀、套用名称映射）再判。
于是 `anthropic/GLM-5.3` 这类写法**在 `/v1/messages` 能过、在 async 返回 400 `model_not_allowed`**
——与「模型白名单与 /v1/messages 一致」的承诺矛盾。票内 `model` 名不归一，还会让选号的模型分档
与额度比对用错键。现在入口与网关走同一套归一化。

## 七、额度刷新不再覆盖已归档 / 已停用账号

`store.SetArchived` 的契约是「调度、领取、刷新全部跳过」，但批量与单个刷新此前只按
`Mode == jwt` 过滤。这不仅是多变了几次请求：**刷新会经计费响应把归档账号的状态写回
`active`**，等于一次刷新撤销一次归档。现已按后台周期监控同一套筛选跳过这两类账号，并给出
明确文案。

## 八、其余三处修正

- **领取与「刷新資格」共用同一冷却判据**。此前 `handleClaim` 只看原始 `Status == cooling`，
  而 preview 用 `IsSelectable`（把「冷却已到期」视为可用）⇒ 同一账号在同一时刻
  **preview 能查出结果、点领取却说冷却中**。两处现已共用一个函数，判据不可能再漂移。
- **上游地址配置错误不再归咎于账号**。`req.URL` 来自 `ZAI_UPSTREAM_URL`，构造失败与账号凭证
  无关；旧实现把这种失败当成账号错误标 `invalid` 并换号——于是整池账号会被逐个标失效并落库，
  而换号根本修不好配置。现在直接以 `502 invalid_upstream_url` 终止并指明检查该配置。
- **编辑账号先指派线路再套用其余字段**。线路可能因并发删除而指派失败，旧顺序会先落库其他字段
  再回错误，留下「报了错但名字/密钥已改」的半套用状态。
- **失败计数表可回收**。鉴权失败计数只在同一来源地址再次请求时被裁剪，未鉴权的请求可以用大量
  不同地址把它撑到无界；超过阈值时改为全表清理。

## 兼容性与升级

- 直接替换二进制；**无数据迁移、无 API 契约变更**（`accounts.data` 的 34 键契约不变，未新增字段）；
- 设定面新增两项：后台开关 `async_force_direct`，以及 compose 里对应的
  `ZCODE_ASYNC_FORCE_DIRECT`（默认值与代码默认一致，不设也不影响行为）；
- **前端已重建**（`frontend/dist` 随本版更新，新增「Async 強制直連」卡片）；
- 无破坏性变更。需要留意的是三处**可见读数变化**：async 出口实际走线路（第一节）、
  `route` 取值语义（第四节）、用量页 async 数字（第三节）。

## 已知未决

300s 墙的**归属**（出口线路 vs 上游模型侧）仍未定论。本版把 async 的诊断读数修正为真值，
并把归因所需的「直连臂」做成了显式开关，判定手段因此齐备；结论仍待一次真机长流验证。
判定矩阵见 `docs/analysis-flash-5min-stream-cut-20260921.md` §4.1。
