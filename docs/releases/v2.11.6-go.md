# v2.11.6-go

## 3.17.1 文案修正（身份段 dBa 变体）+ probe 支持自定义 system

v2.11.5-go 的探针实验证明：**仅把 system 首段对齐还不够**，3.17.1 仍返回 405/3012。
对照实验（同账号、同代理出口、同请求体）定位到差异在客户端声明那一侧：

| 实验 | 版本/文案 | 响应 |
|---|---|---|
| 对照 | 3.16.3 / 3.16.x 档案 | **200 OK**（返回 "OK"） |
| 实验 | 3.17.1 / 3.17.1 档案（首段已对齐） | **405 / 3012** |

### 根因（静态还原）

3.17.1 的身份段有**两个变体**，由 ContextBuilder 按「是否配置了 Output Style」选择：

```js
n = config.outputStyle?.prompt.trim() ? config.outputStyle : undefined
t.push(wDn(n, midConversationSystem))   // wDn(e,t) => e ? pBa : dBa
```

- 有 Output Style → `pBa`：「You are an interactive agent that helps users according to their "Output Style"…」
- **没有 Output Style（默认）→ `dBa`：「You are an agent working with the user toward their goals, using your own judgment along the way.」**

v2.11.5-go 用的是 `pBa`，而桌面端默认会话走 `dBa` ⇒ 身份段不匹配 ⇒ 3012。
本版把 `zcode_system_3171.json` 重建为 `dBa` 变体（identity 1317 字符、block1 2419 字符）。

### 本版改动

1. `internal/upstream/zcode_system_3171.json` 重建：身份段首行改为 `dBa`。
2. `zcode2api probe --system-file <file>`：用 `{"blocks":[…]}` 覆盖 system，
   无需发版即可验证「官方客户端真实抓包」或任意候选文案；block 0 的 `cache_control` 自动剥离，
   出站形态与内建档案一致。报告新增 `system_source` 字段标明来源。
3. 回归测试补身份段首行断言（3.16.x → `"You are an interactive ZCode agent…"`，
   3.17.1 → `"You are an agent working with the user toward their goals"`）。

### 验证方式（单账号单请求）

```bash
docker exec -e ZCODE_CLIENT_VERSION=3.17.1 <容器> zcode2api probe
# 或直接用抓包文件验证，不依赖内建档案：
docker exec -e ZCODE_CLIENT_VERSION=3.17.1 <容器> zcode2api probe --system-file /tmp/real3171.json
```

- `200` ⇒ 文案方案成立，3.17.1 可进入灰度。
- `405/3012` ⇒ 说明还有文案之外的因素（请求体字段 / 版本放行），需以官方客户端抓包为准。

### 兼容性

- 默认仍是 `3.16.3`，生产行为不变；3.17.1 仅由 `ZCODE_CLIENT_VERSION=3.17.1` 显式开启。
- 无接口、配置项、数据结构变更。
