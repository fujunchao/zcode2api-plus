# v2.10.26-go

## 断流计入线路软失败 + 隔离到期进入观察期

v2.10.25 把 405、连接失败与大包超时都压下去了，这份日志（17:49–20:31，69 请求、94.2% 完成）
里剩下的 4 条失败中有 3 条是同一类：**上游中途断流**。而且它们本可以更少。

### 现场：一条线在 1 小时里弄坏 3 个请求

`订阅-f7eff3a956775fea` 的完整时间线：

```
17:54 连接失败①                       consecutive=1
17:57 断流①（316B，客户端可见）        断流不计软失败
17:58 连接失败② → 隔离至 18:28         consecutive=2 strikes=1 reassigned=2
18:20 网络巡检判 healthy              探测的是连通性，不是流
18:28 隔离到期 → 直接回池              无复检、档位还在但无人复核
18:48 断流②（3443B，客户端可见）       距最后失败 51 分钟，静默清零已抹掉档位
19:00 连接失败③                       重新从 1 计数
19:01 断流③（62689B，客户端可见）
19:02 断流熔断（连续 3 次）→ 移除
```

两个设计缺口叠加：

1. **断流不进软失败统计**。`softOutcomeSignal` 只认 success / timeout / connection_failed /
   uplink_slow；断流只走 `line-guard` 的独立计数（阈值 3，动作是不可逆删除）。
   于是出现倒挂：**客户端看不见的连接失败 2 次就隔离，客户端直接收到残缺响应的断流要 3 次才熔断**。
2. **隔离到期被当成恢复**。到期只判时间，回池前没有任何验证；而且静默 30 分钟会把
   `Strikes / Consecutive` 一起清零，等于「免费复活」。

## 1. 断流计入线路软失败

- 新增信号 `upstream_truncate`，在 `RecordUpstreamTruncate` 的 line-guard 判定之后记账；
- 刚被熔断移除的线路不记账（profile 已不存在，只会留孤儿条目）；
- 与连接失败共用「连续 2 次即隔离」，把止损提前到不可逆删除之前；
- 开关 `ZCODE_PROXY_SOFT_TRUNCATE`（默认 1）；关掉只停记账，line-guard 不变。

## 2. 隔离到期进入观察期

| 时机 | 动作 |
|---|---|
| 隔离到期后的第一条事件 | 不再直接回池，也不再因静默清零档位 |
| 该事件是完整成功 | `Strikes=0`、`Consecutive=0`，线路净身出户 |
| 该事件是失败 | **立即按下一档隔离**（30→60→120→240） |
| 24 小时无流量 | 条目被 TTL 清理（已声明的隐式出口） |

观察期**没有时间窗出口**：时间窗会让「每小时坏一次」的线路在隔离↔观察之间永久震荡，
或者在窗口末被无条件洗白。成功是唯一能证明它此刻可用的证据。

观察期是惰性判定：到期后的第一条事件会在同一次调用里完成「置观察期」与「解析」，
正常流量下不会有长期停留的观察期条目。

- 开关 `ZCODE_PROXY_SOFT_PROBATION`（默认 1）；`0` 恢复旧行为（到期即回池 + 静默清零）。

## 3. 后台日志行补时间戳

`[~]` / `[!]` 行此前没有 `ts=`，复盘上面那条线时只能靠文件行序 + 邻近 `[attempt]` 行反推。
现在统一在**行尾**追加 `ts=<本地 RFC3339>`：

```
[~] proxy-soft id=proxy-f7eff3… probation=0 trigger=probation action=quarantine … ts=2026-10-18T18:48:49+08:00
```

追加在末尾而不是前缀，`[~] <module>` 的既有形态不变，现有 grep 与外部脚本不受影响。
`proxy-soft` 行同时新增 `probation=` 与 `trigger=`（`probation|consecutive|rate|extend`）。

## 回放（按本次日志）

17:54 连接失败 → **17:57 断流即触发隔离**（不再等 17:58 的第二次连接失败）→
18:28 进入观察期 → **18:48 断流立即升档 60 分钟** → **19:00 / 19:01 不再发生**。
客户端可见失败 3 → 2。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZCODE_PROXY_SOFT_TRUNCATE` | `1` | 断流是否计入线路软失败 |
| `ZCODE_PROXY_SOFT_PROBATION` | `1` | 隔离到期是否进入观察期 |

## 兼容性

- 无数据迁移：`proxy_soft_failure_state` 只新增可选字段 `probation`，旧记录读出为 false。
- 两个开关互相独立，可分别回滚。

## 回归覆盖

两次断流即隔离、断流与连接失败合并计数、开关关闭不记账、熔断后不产生孤儿条目、
隔离到期首败直接升档（60 分钟）、观察期内成功清空档位、开关关闭恢复静默清零、
条目 24h 无流量被 TTL 清理、`[~]`/`[!]` 行尾时间戳可解析且前缀不变。

所有自动化验证由 GitHub Actions 执行，分支 CI 与发布工作流复用的完整 CI 均为门禁。

## 明确不做

- **不做「隔离到期先跑流式探测」的出口闸**，留 v2.10.27：需要新增探测调度与预算；
  而且合成探测也不保证——本次断流是间歇性的（19:01 那次传了 62 KB 才断），
  探测可能恰好落在它正常的窗口里。
- 不改 line-guard 的 3 次熔断（保留为观察期之后的升级手段）。
- 不动带宽选线与「内容级 405 的线路连击折扣」（v2.10.27）。
