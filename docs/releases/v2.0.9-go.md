# v2.0.9-go

新增账号时自动挑一条空閒代理線路，代理页支持一键測試全部線路，
顺手把登录链路的出站线路选择改成与新增账号一致的语义。

## 新增内容

- **新增账号自动指派空閒線路**：后台手动/批量添加、批量导入、OAuth
  登入、CLI 新增五个入口统一由后端处理——只要没显式指定代理，建号后
  自动挑一条「启用中且未被任何账号占用」的線路并落库。核心是 store
  新增的 `AutoAssignProxies`，在单把锁内原子完成「挑选 → 指派 →
  持久化」，所以批量导入不会把同一条線路分给两个账号。
- **代理页「測試全部線路」**：一次并发探测所有启用中的線路，逐行回填
  出口 IP / ASN / 运营商 / 延迟，末尾汇总「成功 X／失敗 Y」。检测结果
  不落库，与单条检测行为一致。
- **添加账号对话框默认项改为「自動」**：显示「自動（N 條空閒線路）」，
  没有空閒線路时提示「自動（無空閒線路，將直連）」，仍可手动改回
  「直連（不使用代理）」或指定某条線路。

## 修复内容

- **登录链路出口不一致的隐患**：`resolveLoginProxy` 现在返回自动标记，
  并在 `/login/start` 阶段就锁定一条空閒線路作为出口——此前若把「自動」
  留到落库阶段再挑，会出现 token 交换走直连、而兑换 API Key、刷新额度、
  领取走線路的情况，违反「登录全链路共用同一出口」的约定。
- **命中老号不再被换线**：登录会话带 `auto` 标记，若该账号已存在且用户
  没显式指定代理，保留它原有的線路指派，不会被自动分配改写。
- **兑换 API Key 改用账号实际地址**：原实现读会话里的代理地址，在自动
  分配场景下该值为空，会让这一步误走直连。

## 使用说明

「自動」是新增账号时的默认行为，无需任何配置。判定「空閒」只看命名
線路：同一条線路被某个账号占用后不会再分给第二个；手工填 `proxy_url`
的账号不占用命名線路。所有線路都被占用时新账号走直连，并在新增结果里
提示「其中 N 個沒有空閒線路，已使用直連」。

批量导入只给本次新建的账号分配線路，重复导入不会改动已有账号。
编辑账号页不参与自动分配——那里的选择是显式意图，`直連` 就是直連。

「測試全部線路」按并发 8 路探测，最坏情况单条约 36 秒（三个出口服务
依次 12 秒超时），全量耗时约为 `36s × ⌈N/8⌉`；测试期间按钮会禁用并
显示「正在測試全部…」。正常网络下首个出口服务数百毫秒即返回。

[客户端兼容说明](https://github.com/fujunchao/zcode2api-plus/blob/v2.0.9-go/docs/client-compatibility.md)

## 能力依据

- [Z.AI 官方文档](https://docs.z.ai/)

自动分配与批量检测都只针对本地代理配置，不改变出站请求本身的构造；
账号出站仍只看 `Account.ProxyURL` 这一个字段，`ProxyID` 仅标记線路来源。

自动分配与批量检测已通过单元测试与本地全量测试（含 17 个新增子用例，
批量检测用本地回环同时冒充出口服务与代理，不触网），但**尚未经过线上
真实代理环境验证**：真实線路的可用性判定、以及既有账号在导入后是否
保持原線路，仍待在线观察。
