# v2.14.4-go

修复 ZCode 3.19.1 网关强制回退时，旧官方第三块与调用者块内后缀一起被重复并入新版提示词的问题。

## 修复行为

当 `ZCODE_PRESERVE_CLIENT_CONTEXT=false`，3.18.2 客户端传入“官方首两块 + 旧第三块及自定义后缀”时，
此前会生成“3191 新底座 + 3180 旧底座 + 自定义后缀”，重复加入约 1.6 KB 文本并带回旧版
`<total_tokens>` 提示。现在输出“当前底座 + 自定义后缀”，后续独立指令保持原顺序。

- 静态第三块从全部已知档案登记，仅在首两块已确认属于官方模板后按完整字节前缀剥离。
- 多个底座匹配时取最长匹配，去掉至多一个拼接用双换行，保留后缀自身的空白。
- 不按标题或关键词删除指令；非官方前缀、非官方身份段和仅含同名标题的调用者内容继续保留。
- 支持 3.18.0、3.18.2、3.19.1 的双向档案切换，重复重建不会再次叠加模板。

默认 `ZCODE_PRESERVE_CLIENT_CONTEXT=true` 时，官方首两块匹配的客户端完整上下文仍原样保留。
默认客户端声明继续为 `3.19.1`，三块原始档案文本、缓存布局、用户环境提醒和 API 协议保持一致。

## 验证

新增真正的块内后缀回归、三版本之间的九组回退组合、同名标题与非官方身份保护检查，
以及 `NormalizeBody` 层的保留/强制回退和 JSON 往返幂等检查；同时验证调用者原对象不被修改。
自动化验证在 GitHub Actions 执行，分支及标签发布均使用完整 CI 门禁。

## 升级与回退

镜像：`ghcr.io/fujunchao/zcode2api-plus:2.14.4-go`，同时更新 `latest`。
二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。

本次没有数据库迁移。需要回退修复行为时使用 `2.14.3-go` 镜像；只修改
`ZCODE_CLIENT_VERSION` 会切换提示词档案，仍使用新的精确剥离逻辑。

修复方案与回归范围见 [plan-zcode-3191-fallback-suffix-fix-20261123.md](../plan-zcode-3191-fallback-suffix-fix-20261123.md)。
