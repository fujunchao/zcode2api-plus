# v2.10.6-go

## 新账号初始化代理策略

- 后台 **代理 → 新账号初始化** 新增启用开关、默认业务代理下拉框、全部/自选取额池及尝试预算。
- 自动模式的新入库 JWT 账号在创建事务中即进入调度保护；只有确认实际可用额度并提交固定绑定后，才进入正常模型调用。
- 每条候选执行受控的查询、激活、预览、领取和补查；默认每轮最多 32 个节点，单节点 120 秒，整轮 900 秒。明确的资格拒绝、限流和上游等待不被轮询清零。
- 已有账号重登、重复新增、备份导入、纯 API Key 和人工指定出口不自动接管。
- 后台新增/批量/OAuth 与 CLI 新 JWT 复用持久初始化流程；CLI `add-account` 仅登记任务，后续服务启动接管。

## 共享线路与固定出口保护

- **新号空额度不再删除共享代理或改派其他账号**，该修正不依赖新策略开关。
- 初始化失败只记录任务结果；业务连接故障、巡检、断流及严格模型风控保持独立规则。
- 托管账号的固定出口不被通用风控换线、删除改派、订阅补线或异步强制直连覆盖。固定节点不可用时等待，不偷偷退直连。
- 代理地址更新后重新识别默认节点别名；人工改绑/直连原子解除托管，停用、归档及身份变更撤销旧执行权。

## 进度、恢复与验证

- 账号页增加初始化筛选、进度、等待原因及暂停/重试操作；已到账账号只重试绑定，不重新领取。
- 领取 POST 前保存意图，重启或响应丢失后先核验额度；只有套餐信息、余额字段缺失、缓存与普通 405 都不能冒充到账。
- 任务、额度补丁、绑定与代理代次以 SQLite 事务提交；迟到响应和 A→B→A 变化不能覆盖人工操作。
- 上游 `Retry-After` 的秒数与日期格式被保存，人工重试仍受等待时间约束。
- 验证门禁继续复用完整 CI：前端行为与产物一致性、Go build/vet/全量及重复回归/race、SDK、New API 合同、多平台构建、镜像构建和 Windows 日志专项。

## 使用与升级

1. 将本地服务器的可达代理节点添加到代理列表，在“默认业务代理”下拉框选中它。
2. 选择取额候选并开启策略；设置页“入池自动领取”也需开启。新策略默认关闭。
3. 观察账号页初始化进度。默认节点改变仅影响后续任务；已有等待账号需明确选择“改用当前默认代理”。

新增 `account_initializations` 表，现有账号 JSON 和导出 version 1 不变；完整数据库备份保留任务进度。**回退旧版本之前先暂停并停用未完成初始化的账号**，旧版本不识别其调度保护。

本功能保证应用内状态与路由规则，不保证供应商发放配额或特定出口永久避免 405。验证码浏览器池仍不按账号出口隔离。测试只用隔离数据及本地测试服务，不在开发机运行自动化测试，也不操作真实账号或生产服务器。
