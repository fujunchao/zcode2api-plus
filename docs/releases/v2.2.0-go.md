# v2.2.0-go

修复 `529 / code=1305` 平台过载被整类漏判的问题，并给账号加上「最近错误」的归类记录与
按类型筛选的后台视图。

## 缺陷：平台过载落到「其余错误」分支，网关一次都不重试

一线现象：客户端报 `status_code=529, [1305][该模型当前访问量过大，请您稍后再试]`，而服务端
日志里只有 `上游错误 HTTP 529`——同一份日志中 `1305` 出现 **0 次**（5362 行）。

**根因**：官方错误码表把 `1305` 标为 429，而 z.ai 在 Anthropic 兼容面用 **HTTP 529**
（overloaded）承载它。分类链第 5 条的入口是 `resp.StatusCode == http.StatusTooManyRequests`，
529 不匹配，于是整类过载落到第 7 条「其余错误 → 原样透传」：**网关零重试**，全部重试压力
推给上层中转。实测中转以 77–88ms 间隔连冲 26 次后放弃——而官方对 1305 的处置建议恰恰是
「增加重试间隔，避免立即高频重试」。

顺带暴露的第二个问题：`1305` 与 `1302` 被一起归入「瞬时限流 = 该账号被限速」。两者在官方
文档里是两回事——`1302` 是**账户维度**速率限制，`1305` 是**平台服务过载，与单一账户的调用
行为无直接关系**。一旦上游改用 429 返回 1305（官方表就是这么标的），健康账号会被打上
30→60→120→300s 的递进冷却，整池账号被逐个踢出调度。

## 修复

### 平台过载独立成一条分支，且排在 429 之前

- 判据 `gateway.IsUpstreamOverload`：状态码 **529 或**业务码 **1305**。两个条件都要——线上
  形态（529）与官方表形态（429）不一致，只看一边会漏掉另一边；若上游改成 Anthropic 原生
  `{"type":"error","error":{"type":"overloaded_error"}}`（无 code 字段），状态码一侧仍能兜住。
- 行为：原地退避 **1s、3s**（±20% 抖动，`OverloadRetryDelays`），**不换号、不标账号状态、
  不动冷却、不计 fail_count**，用尽后原样透传上游响应；独立预算 `attemptBudget.overload`。
- 必须排在 429 之前：否则官方表形态的 `429 + 1305` 会先被限流分支接走，等于没修。
- `asyncpool` 同步镜像；过载不换号，用尽后原样投递上游错误体并终止本票。

### 账号「最近错误」归类

- `Account` 新增 `last_error_kind` / `last_error_at`（可空，键集 32 → 34，仍然只增不减）。
- 取值 `model.ErrorKind*` 共 12 项：`upstream_overload`、`rate_limited`、`quota_exhausted`、
  `model_busy`、`auth_failed`、`connection_failed`、`upstream_unavailable`、`captcha_failed`、
  `invalid_response`、`client_canceled`、`upstream_error`、`quota_query_failed`。
  **字符串一经上线不可改名**（会落进 `accounts.data`，并成为前端筛选值）。
- 写入点强制传 kind（`MarkAccount` / `bumpFail` / `RecordAccountError`），漏传编译失败；
  `MarkModelExhausted` 与 `MarkRateLimited` 的 kind 由函数语义唯一确定，内置不外露。
- `ErrorKindAccountFault` 标记「是否归因于账号自身」，供后台「帳號故障」聚合筛选——
  **只影响筛选归类，不参与状态机与 fail_count 决策**。
- 客户端取消只写「归类 + 时间」，不覆盖 `last_error` 文案：用户按一下 ESC 不该把上一次
  真实故障的文案冲掉。

### 日志补业务码与截断预览

`gateway.ErrorPreview` 提取业务码/类型 + 可读文案，单行化后**按 rune** 截断到 200 字符。
`上游错误 HTTP %d（账号 %s）` 现在带上它——此前只记状态码，`1305` 与风控 `405` 这两类
「关键信息在 body 里」的失败在日志里完全不可见，排查只能靠用户贴出客户端报错。

### 后台账号页

新增「最近錯誤」列（小徽章 + 相对时间，完整文案在 title；限宽 + truncate）与错误类型筛選
下拉（含「帳號故障」聚合项，只列当前有命中的类型）。纯前端本地过滤，后端列表 API 不变。
表格由 9 列增至 10 列，从呼叫／失敗／Tokens／最近使用／操作／出口線路各让出 16px。

### `quota` 的 405 判定

上游对重复查询回 405（幂等，可安全忽略），风控也用 405（`unusual activity`，真实故障）。
原来只看状态码，风控 405 被当成幂等成功静默吞掉、还顺手清掉 `last_error`。现在读 body
区分形态：风控按 `quota_query_failed` 记失败并保留错误文案；额度查询的 401/403 仍归
`auth_failed`。

## 升级注意

- `accounts.data` 新增两键，旧版读取时缺失即 `null`，无需迁移。
- 后台「重置統計」不清除「最近錯誤」——诊断信息与统计量性质不同。
- 平台过载不再计入 `fail_count`（与 402/429 一致：平台过载不是账号的错）。
- `quota.go` 的 405 现在会读 body，错误响应体读取统一限 8 KiB。
