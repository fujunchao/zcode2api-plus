# v2.9.19-go

## 恢复默认风控静默隔离

- `ZCODE_RISK_SILENT_HOURS` 默认由 `0` 恢复为 `24`：账号被上游风控命中（405 unusual activity / code 3012）后，24 小时内不参与选号；人工恢复这类账号时转入保护冷却，不直接放回轮转。显式设为 `0` 可关闭（应急回退，仅按阶梯冷却）。
- 依据 2026-10-13 上午的多批日志对照（网关、new-api、客户端会话）：上游对命中账号的服务端标记在 12 小时零请求的闲置期后仍未解除；默认纯阶梯下 300s 冷却到期即被重新选中、再 405，热账号被循环消耗。本地阶梯冷却只有分钟级，远短于标记时长。
- 阶梯冷却与连续计数机制不变：静默期结束后的首次调用即探测，成功清零连续计数，再次命中按阶梯升级（5 / 15 / 60 分钟），超档仍置失效；没有自动复活失效、停用、归档或额度耗尽账号。
- 池状态文案对齐：「本地風控靜默隔離（依配置計時，非上游封禁確認）」，不声称上游确认仍在封禁。

## 升级提示

如果部署曾显式设置 `ZCODE_RISK_SILENT_HOURS=0`（含按 v2.9.18 提示从 24 改过的），需移除该覆盖才能恢复默认隔离。已有冷却与静默记录不会被升级自动清除；页面显示本地限制与最早重新评估时间。

本版本不改变模型请求内容或既有账号数据，不声称修复供应商的所有 3012 风控触发原因。

验证使用合成凭据、隔离存储和本地 HTTP 服务；分支完整 CI 与发布复用 CI 均为发布门禁。
