# v2.11.8-go

## 默认伪装版本切到 ZCode 3.17.1（经真实抓包逐字节校准 + 单账号探针 200 验证）

`v2.11.4-go` 曾把默认值升到 3.17.1，因 system 身份段与版本不配对，导致全量 405/3012
（事故记录见 [根因分析](../analysis-zcode-3.17.1-405-incident-20261101.md)）。本版在把 3.17.1 文案
**逐字节对齐官方客户端**之后，才重新把默认值切过去：

| 项 | 值 |
|---|---|
| block 0 | `You are ZCode, an interactive agent`（35 字符） |
| 身份段（第 0 字节 → 身份段末尾） | **1235 字节**，sha16 `4058874023c7541f`（与官方抓包完全一致） |
| 单账号探针 | **200 OK**（`input_tokens=1688`，2265ms） |

### 本版改动

1. `ZCODE_CLIENT_VERSION` 默认值 `3.16.3 → 3.17.1`；伪装头、模型 UA、
   `app_version` 全部由该常量派生，自动跟随。
2. 3.17.1 文案档案（`zcode_system_3171.json`）取自官方客户端抓包：block 0 与身份段逐字节一致；
   桌面上下文段沿用静态文本（该段含用户私有路径，上游不参与校验）。
3. 回归测试同步：默认版本断言、UA 断言改为 3.17.1；身份段长度/指纹仍是双锁
   （3.16.x：1217 B / `fb4777a371fac341`；3.17.1：1235 B / `4058874023c7541f`）。

### 回退（一条命令，无需换镜像）

```bash
# compose/.env
ZCODE_CLIENT_VERSION=3.16.3
docker compose up -d
```

回退后 system 档案自动切回 3.16.x（档案按版本键控、缓存按档案失效），不需要改其它配置。

### 验证建议

- 升级后确认：`docker exec <容器> zcode2api status | head -5` 显示 `2.11.8-go`；
- 盯 `3012` / `unusual activity` / `405` 计数，出现即回退；
- 单账号体检（只读、单请求）：`docker exec <容器> zcode2api probe --account <账号>` → 期望 200。

### 兼容性

接口、配置项、数据结构均无变更。默认值变化只影响发给上游的版本声明与提示词文案。
