# v2.14.6-go

把默认伪装客户端版本从 ZCode 3.19.1 切到 4.0.0；复用已核验的 3191 system 档案，接口与默认请求形态不变。

## 背景

2.14.5-go 已登记 `4.0.0 → 3191` 的精确档案别名。4.0.0 与 3.19.1 的默认三块 system（35 / 1,233 / 4,564 B）、
Desktop Context（1,100 B）、来源头、SDK 版本、签名模块与随包模型目录逐字节/逐项相同；实质增量只在客户端侧
OpenAI Responses 无状态加密推理回放，不影响网关的 Anthropic 主链。

## 探针结论

用 2.14.5-go 镜像对隔离账号副本发单请求（不动生产库）：

- dry-run：`client_version=4.0.0`、`system_profile=3.19.1`、3 块、sha16 `7779642e…` / `aac4ba4c…` / `929856d5…` 全部正确。
- 真实请求：`glm-5.3-flash` 返回 **HTTP 200**（约 3.6 s，input 1,691 / output 16），无业务错误码。
- 两次 `glm-5.3` 探针返回 429 / `3009 model concurrency limit exceeded`，属账号/模型并发准入，与版本无关；
  换 `glm-5.3-flash` 后即 200。

## 变更

- `ZCODE_CLIENT_VERSION` 默认值改为 `4.0.0`（`internal/config/config.go` 与根目录 `docker-compose.yml` 同步）。
- 默认版本测试同步为 4.0.0；4.0.0 仍映射到 3191 档案，未知 4.0.x 继续回落 legacy。
- README 与实现记录更新。

## 升级与回退

镜像：`ghcr.io/fujunchao/zcode2api-plus:2.14.6-go`，同时更新 `latest`。
二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。

本次没有数据库迁移。回退：设 `ZCODE_CLIENT_VERSION=3.19.1` 重启即可（3191 档案保留）；整镜像回退用
`2.14.5-go` / `2.14.4-go`。

记录见 [implementation-zcode-4.0.0-profile-20261123.md](../implementation-zcode-4.0.0-profile-20261123.md)。
