# v2.11.4-go

## 同步 ZCode 3.17.1 客户端声明（模型 wire 未变）

本机 ZCode 客户端已由 3.16.3 升级到 **3.17.1**（exe `3.17.1.9553`、build `025f7f39`、构建时间 2026-10-29T12:42:31Z）。本版对安装包做了完整只读逆向，并与本机留存的 3.16.3 基线做**单版全包差分**（app.asar 27,773 → 31,849 个文件 / 341,378,894 → 374,627,566 B、CLI `zcode.cjs` 15,242,397 → 15,405,921 B、桌面 provider 配置 revision 33 → 43、外部资源 1,398 → 3,117 个文件），结论是：**模型请求主链路未变，本次只需同步伪装版本声明。**

### 逆向结论

- **差分规模中等、但集中在客户端本地面**：27,773 → 31,849 个文件，identical **24,102**、changed **115**、added **7,632**、removed **3,556**；added/removed 主体是 node_modules 依赖树变动（新增 `@ai-sdk/*`、`@agentclientprotocol/sdk`、mermaid/cytoscape 等，移除 `@opentelemetry/*` 588 个文件）与 renderer 带内容哈希文件名的重命名。
- **伪装身份零变化**：`buildZCodeSourceHeadersFromContext`（11 个头 + 3 个基础头）与 3.16.3 **逐行一致**；模型请求 UA 三个组成项全部未变——`ai-sdk/provider-utils/4.0.27`（CLI 内 `lto="4.0.27"`）、`runtime/node.js/24`（Electron 44.7.0 内置 Node v24.21.0）、`ZCode/<ver>`。
- **端点面零增删改**：桌面侧路径字面量 141 → 143，只新增 `/api/v1/remote/notification/{events,status}`（远程中继）；CLI 侧新增 `/api/v1/remote/device`、`/api/v1/remote/device/delete`、`/api/v1/remote/token`、`/api/v1/sites`。模型端点 `/api/v1/zcode-plan/anthropic/v1/messages`、计费 `billing/{preview,claim,balance,current}`、`coding-plan/reset`、`off-peak`、`highspeed` 全部未变。
- **新模型不是官方通路**：新增的 Kimi K3.1 Pro、MiniMax M3.1 Flash 位于 `config/provider/zcode-builtin.json` 的**第三方 BYO-key 模板**（moonshot-kimi / kimi-code-* / minimax-*）；官方账户套餐 `builtinProviderModelRules` 仍只有 GLM-5.3 / 5.3-Flash / 5.2 / 5-Turbo。网关模型映射无需新增。
- **`minCompatibleVersion=3.17.1` 仍不是模型 API 门槛**：它只约束“桌面 ↔ 远端 Source Server”兼容性（`evaluateSourceServerCompatibility`），不能据此推断服务端拒绝旧版本。
- **变化集中在客户端本地面**：ZCode Sites 插件与 `/api/v1/sites`、统一远程数据同步（`*DataSyncMethods` 族）、远程服务停止/重启与降级确认、MCP 内置 npm 运行时（1,677 个新增文件）、CUA 多会话光标、移动端日志拉取与推送、按步/按提示的 token 用量与 TTFT 遥测归因、插件市场导入管线重写、文档类插件 server.mjs 各瘦身约 224 KB —— 均不进入网关模型 API 链路，本版不迁移。
- **体积提示**：更新日志称“安装包体积明显减小”，但本机 Windows 口径相反（待安装 exe 190.8 MB → 233.8 MB，asar +33.2 MB），本版不据此做任何承诺。

### 本版改动

1. **默认伪装版本 `3.16.3 → 3.17.1`**：`ZcodeClientVersion` 默认值更新；`UserAgent`、`ModelUserAgent()`、`X-ZCode-App-Version`、`app_version` 查询参数、`ZcodeProfile.AppVersion` 全部随常量自动派生，请求形态不变。`ZcodeClientAISDKVersion=4.0.27`、`ZcodeClientNodeMajor=24` 维持不变（3.17.1 证据未变）。
2. **不新增任何请求头/端点/body 字段**；新增的 `x-zcode-session-features`（模型请求上下文头）本版**不跟进**，继续执行“未知 `x-zcode*` 头不透传”策略。
3. 版本测试期望值同步更新；发版号 `2.11.4-go`。

### 兼容性与回滚

- 端点、认证、请求体、调度、数据库结构均未改，**无数据迁移**；用户无需修改任何配置，接口与后台行为不变。
- 回滚：部署侧设 `ZCODE_CLIENT_VERSION=3.16.3` 即可让 UA/版本头/`app_version` 回到旧值（无需重编）。⚠️ Compose 需在 `environment:` 显式引用该变量才会进容器（应用本身不读 `.env`）。
- 自查是否被固定：`docker exec zcode2api env | grep ZCODE_CLIENT_VERSION`（无输出 = 走默认值，升级即生效）。注意 `/meta` 只显示产品版本，不反映伪装版本。
- 观察项：上游按 `app_version` 分级下发配置。上线后 30 分钟观察套餐投放与模型 2xx/405 比例，异常按上述方式回退。
