# v2.11.1-go

## 同步 ZCode 3.16.3 客户端声明（模型请求协议未变）

本机 ZCode 客户端已由 3.16.2 升级到 **3.16.3**（build `a82dd43e`，构建时间 2026-10-23T02:41:37Z）。本版对安装包做了完整只读逆向，并与本机留存的 3.16.2 基线做**单版全包差分**（app.asar 27,773 个文件 / 341,378,894 B、CLI `zcode.cjs` 15,242,397 B、桌面与 CLI 两份 provider 配置、1,398 个外部资源），结论是：**模型请求主链路未变，本次只需同步伪装版本声明。**

### 逆向结论

- **差分极小**：27,773 个文件中 identical **27,696**、changed **32**、added/removed 各 45（后两者全为带内容哈希文件名的重命名，已 1:1 配对）；`package.json` 仅 `version` 变化。
- **模型目录/思考档位/端点未变**：桌面 `config/provider/zcode-builtin.json`（revision 33）与 CLI `glm/provider/zcode-builtin.json`（revision 30）与 3.16.2 **字节完全相同**。
- **CLI 协议面未变**：45 个协议符号做标识符归一化后 **42 个逐 token 相同**（端点、来源头、UA、鉴权双头、归因头、`metadata.user_id`、系统提示词等）；仅 3 个 tool-search 内部函数结构变化，而工具搜索默认 off。
- **无新增 wire 面**：整包只新增 50 个稳定 token，**没有新增 `x-zcode-*` 头、没有新增 `/api/` 端点、没有新增模型名**；renderer 的 `window.zcode.*` bridge 方法数 128 不变。
- **变化集中在客户端本地面**：远程 Source Server 错误语义与握手（B8/B9/B10/B11/B13）、终端 owner 生命周期（B3/B12）、会话目录 `directorySessionId`/`sessionDirectorySource`（B19）、内置组件 bundled release 缓存回退（B2）、项目保存 `reuseExistingRoot`（B18）、输入法/输入管线（B4/B5）、插件市场 UI（B16/B17）、四个文档类插件 `isolation:"workspace"` 进程复用（F4）——均不进入网关模型 API 链路，本版不迁移。
- **`minCompatibleVersion=3.16.3` 不是模型 API 门槛**：它只约束"桌面 ↔ 远端 Source Server"兼容性（桌面 `upgradeTarget:"server"`，CLI `evaluateSourceServerCompatibility`），不能据此推断服务端拒绝 3.16.2。

### 本版改动

1. **默认伪装版本 `3.16.2 → 3.16.3`**：`ZcodeClientVersion` 默认值更新；`UserAgent`、`ModelUserAgent()`、`X-ZCode-App-Version`、`app_version` 查询参数全部随常量自动派生，请求形态不变。`ZcodeClientAISDKVersion=4.0.27`、`ZcodeClientNodeMajor=24` 维持不变（3.16.3 证据未变）。
2. **不新增任何请求头/端点/body 字段**；版本测试期望同步更新；继续执行"未知 `x-zcode*` 头不透传"策略。
3. 发版号 `2.11.1-go`。

### 兼容性与回滚

- 端点、认证、请求体、调度与数据库结构均未改，无数据迁移；
- 回滚：部署侧设 `ZCODE_CLIENT_VERSION=3.16.2` 即可让 UA/版本头/`app_version` 回到旧值（无需重编）；代码侧可 revert 版本同步提交；
- 观察项：上游按 `app_version` 分级下发公共配置。若 3.16.3 的验证码/领取下发语义发生变化，上线后观察 `/admin/captcha` 与领取行为，必要时用环境变量回退。
