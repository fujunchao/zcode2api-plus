# v2.9.6-go

完善新账号入池的领取后额度刷新，并将空额度代理检测严格限定为真正新建的账号。

- 后台首次授权登录、粘贴 Token 和批量新增的 JWT 账号：保留首次额度查询，领取完本轮可领取套餐后再实际查询一次。
- 领取任务繁忙时，新账号串行等待，不再直接跳过；等待和查询均支持停机取消。
- 领取后的查询绕过 15 秒缓存；如已有查询在途，等待其结束后发起新请求，避免把领取前的结果误当作第二次观测。
- 只有领取前后两次均成功确认“没有获得初始配额”，且同一账号、凭据与代理绑定仍匹配，才删除原代理。网络/鉴权失败、缺少必要字段、405 幂等回包、已有套餐或已分配额度耗尽均不触发删除。
- 复用既有“空闲优先、否则绑定账号最少”的代理分配策略，排除原代理的相同 URL。共享线路上的关联账号一并原子改派；无替代线路时明确回退直连。
- 已有账号重新登录、重复添加、手动/每日领取和备份导入不会触发本项检测；取消旧的“单次空额度＋领取风控就删除代理”逻辑。
- 领取失败或无可领套餐也补查额度；换线保留本次领取状态与冷却，只处理原线路一次，不在新线路循环重领或继续淘汰。
- 增加接口、查询缓存、并发等待、取消、老账号保护、账号变更、事务回滚等回归测试，并在 Ubuntu CI 重复执行相关场景 20 次。

不修改数据库结构或既有 API 响应格式。替换程序或镜像并重启后生效；不追溯处理历史账号。“入池自动领取”关闭时，不执行这条领取后检测链路。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.6-go` 与 `latest`。
