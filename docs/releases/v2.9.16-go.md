# v2.9.16-go

修复第三方客户端经本网关访问时的 405 回归，并把内置提示词快照更新到已实装的
3.14.5 客户端；不修改鉴权、调度、重试预算或风控保护阈值。

## 前缀感知的上下文保留

`v2.9.11-go` 起「带自有 system 的客户端原样透传」有一个边界被跨过：第三方
harness（如 DeepSeek Harness 桌面版）的自身提示词会让上游看不到官方固定前缀，
而服务端从 system 第 0 字节逐字节校验到身份段末尾，首段不符即返回 `3012`
（unusual activity），客户端侧表现为 405 / 被风控拦截。

- `ZCODE_PRESERVE_CLIENT_CONTEXT=true`（默认）现在收窄为**前缀感知**：首段自带
  官方固定前缀（或显式空值 / 消息内 system）的调用者原样保留；非官方前缀回退
  旧版「官方标准块前置 + 精确去重」，调用者内容原样保留在标准块之后。
- 判定收敛到单一来源 `upstream.ShouldPreserveCallerSystem`，同步、异步、
  兼容接口（Chat / Responses）与结构诊断画像共用同一判定，不再各自散落条件。
- `ZCODE_PRESERVE_CLIENT_CONTEXT=false` 仍是全量回退开关（恢复「一律前置标准块」
  与旧版指令提升行为），行为语义不变。

## 提示词快照更新至 3.14.5

- `internal/upstream/zcode_system.json` 块 1 由 1211 字符更新为 3.14.5 实发的
  2313 字符（补 `# ZCode Desktop Context` 一节；字节来源为本机 model-io 实录，
  与线上客户端逐字节一致）。
- 附带收益：完整官方三块输入在回退合并时按块精确去重，重新收敛为原样三块，
  不再多留一份扩展 identity；对「上游校验边界是否已扩展」的情形也同时覆盖。

## 回归与发布门禁

- 新增 `body_test` 第三方 system 用例（blocks / string 两种形态与重复提交幂等），
  `request_shape_test` 新增 `foreign_preserve` 画像用例；asyncpool 四协议诊断与
  openai 兼容入口断言同步更新；systemprompt 快照测试补桌面段存在性断言。
- 已有回归继续覆盖：自带官方前缀的调用者原样保留（含缓存策略与扩展字段）、
  显式空指令不被替代、消息内 system（MCS）位置与 beta 声明不变。
- 继续执行全量测试、竞态检测、SDK/Pi、前端、交叉编译与镜像验证；测试仅使用
  隔离目录、合成凭据和本地测试服务。
- 标签发布继续先复用完整 CI，再上传二进制和推送镜像；不绕过发布门禁。

## 上线验证建议

- 升级后各发一条真实消息对照：DSH（`?beta=true` 入口）应恢复 200；ZCode 客户端
  应保持 200 且前缀缓存命中率不退步。
- 验证前勿反复重试：修复前的每次拒绝都会真实消耗账号冷却并累计风险 streak。
- 出现异常时先回退开关 `ZCODE_PRESERVE_CLIENT_CONTEXT=false` 再排查，
  不要改上游地址或重试预算。
