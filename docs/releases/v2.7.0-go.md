# v2.7.0-go

一次**伪装格式对齐版**：把出站请求头与请求体收敛到官方客户端的单一来源，
并给风控排查补上两个可检索字段。

## 背景

2026-09-24 的两次日志复盘（`docs/analysis-riskcontrol-and-client-format-20260924.md`）
与官方客户端 3.14.3 的静态拆解，发现差异不是「少加几个头」，而是**同一批语义散在四处
各写一份**——于是长出了「body 里写 `Platform: linux-x64`、请求头声称 Windows 桌面端」
这种自相矛盾：

| 类别 | 修复前 |
|---|---|
| 来源头 | 只发 4 个，缺 `X-Platform`/`X-Os-Category`/`X-Os-Version`/`X-Client-Language`/`X-Client-Timezone`/`X-Title`/`X-Release-Channel` |
| 归因头 | 官方每个模型请求必带的 5 个被 `HasPrefix("x-zcode")` 一刀切丢弃，且从不合成 |
| body 的 `# Environment` | 写死 `Platform: linux-x64` / `Shell: unknown` / `OS Version: unknown` |
| 设备身份 | 发在请求头（官方模型请求**不带**），body 里反而没有 |
| `# Harness` 文案 | 旧版本措辞 |

## 核心发现：官方格式是一个三元组的纯函数

客户端 `detectEnvInfo` 只读三项，头与 body 的 `# Environment` **都从它派生**：

```
platform  = process.platform              → win32
arch      = process.arch                  → x64
osRelease = os.release()                  → 10.0.26100
```

⇒ 官方**结构上不可能**头体矛盾。所以对齐的核心是**收敛单一来源**，不是加头 ——
这正是本版把 `internal/config/profile.go` 作为伪装身份唯一入口的原因
（新增静态守卫，禁止别处再出现平台/版本/语言/时区字面量）。

## 行为变更（升级需知）

### 1. 设备身份从头挪到 body（账号隔离不变）

官方模型请求**不带** `X-Device-Mid`，设备指纹在 body 里：

```json
"metadata": {"user_id": "{\"device_id\":\"<本账号指纹>\",\"account_uuid\":\"\",\"session_id\":\"<会话 id>\"}"}
```

- `device_id` 仍是**每账号一份** ⇒ 账号隔离不依赖请求头；
- `session_id` 与 `X-Session-Id` 头**恒等**（官方实测如此），由同一份归因标识产生；
- **只删头不加 body 是错的**（设备身份会消失），本版两件事一起做；
- `dropHeaders` 同步新增 `x-device-mid`：我们不再写固定值后，若不拦截，下游送来的同名头
  会原样上行 —— 等于让调用方指定本账号的指纹。

### 2. `[#]` 诊断行新增两个字段（行尾追加）

```
[#] 8ccbc1 model=glm-5.3-flash stream=true ... err=- bodyhash=c4c78dadf921 riskscope=2
```

- `bodyhash` = 请求体 sha256 前 12 位，**跨账号可比**：指纹取「注入账号身份之前」的内容
  视图。若直接哈希最终 payload，每账号不同的 `device_id` 会让同一份内容换号后指纹不同，
  而该字段的用途恰是回答「这个 body 打过几个账号」。
- `riskscope` = 本请求命中的**不同**风控账号数（按 ID 去重），`≥2` 即请求级。
- 两个字段都**追加在行尾**，不改变既有字段的位置与顺序。

### 3. 其它

- 非模型端点（`quota`/`claim`/`captcha`）**行为不变**，只是 `HTTP-Referer` 统一引用同一常量。
- 接口（请求/响应格式、错误类型、`accounts.data` 键集）无变化。

## 验证

**方式：直接抓官方客户端自己的请求做基准**（可复现步骤见
`docs/analysis-client-golden-diff-20260924.md`）——用环境变量把客户端指向本地记录型
反向代理，跑一次无头请求，落盘完整的头与原始 body，再与网关出站逐字段比对。

| 判据 | 结果 |
|---|---|
| 系统提示词**块 0 / 块 1** | 与官方**逐字节相等**（42 / 1211 字符） |
| `# Environment` 标签集与顺序 | 完全一致 |
| 查询参数 `platform=` | 官方形态实测确认为 `windows-x86_64`（本版未改，见「未纳入」） |
| 签名 | 服务端开关为 `true`，但客户端因凭据形态不满足而 **fail-open 发未签名** ⇒ 不实现签名的决定被证实 |
| `build ./...` | OK |
| 全量测试 | 17 包通过（仅 `captcha` 的符号链接用例因沙箱降级本地必失败，属既有环境问题） |
| `gofmt-check` | 105 文件 0 不合规 |

**反向验证 7 条全部确认守卫有效**（把实现回退后测试必须变红，否则测试没在守行为）：
设备头默认值 / 透传拦截 / body 设备身份 / 会话一致性 / 每账号指纹 / 内容视图指纹 /
归因兜底 body 会话。每条的红都来自**断言**而非编译失败。

## 未纳入本版

- **阶段 4**：`platform=` 查询参数格式（`win32-x64` → `windows-x86_64`）与非模型端点补齐 6 个头。
  额度/领取当前是工作的，**改前必须用真实账号验证**，单独提交。
- **P1-3 重放防护**：同一 payload 短时重放的快速失败（可把单次事故的账号代价降到 1）。
- **P1-4 `streak` 止跌**：请求级命中时回滚/不递增冷却阶梯 —— 现在只回滚 `CoolingUntil`，
  阶梯仍是单向棘轮。
- **P2 签名开关巡检**：把 `GET /api/v1/agent/configs` 的 `codingPlanSignature.enable`
  纳入定期探测（上游若改为强制，需要提前知道）。

详细规格与逐项状态见 `docs/plan-client-format-parity.md`。
