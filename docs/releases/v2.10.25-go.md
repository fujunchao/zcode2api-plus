# v2.10.25-go

## 让大包请求与 405 都不再打断工作

本版解决 2026-10-18 日志（v2.10.23 · 08:34–11:40）里剩下的三类打断。v2.10.24 的拨号/握手
超时收紧只覆盖了其中一部分：它让死线失败得更快，但**慢线仍然吃满 90 秒首字节预算**，
巡检仍然只到 `suspect` 从不删除，请求级 405 之后仍然封锁 60 秒。

| 现象（v2.10.23 日志） | 本版处置 |
|---|---|
| 8.34 / 8.55 MiB 请求 3 次尝试全无首字节，240 秒后 503 | **上行速率闸门**：按实测速率外推，2 秒判死并换线 |
| 22 次 watchdog 超时、15 条脏线，12 条隔离线里 10 条仍留池 | **巡检双证退休**：真实 405 两次 + 巡检 405 即删除 |
| 3 条脏线连击后，客户端 57 秒内重试 11 次全被拦 | **一次性放行**：判定后允许同内容再试一次 |
| 死线失败会冷却账号 300 秒（v2.10.24 让死线更快报错，反而更容易触发） | **连接失败归因线路**：不冷却账号，只换线 |

## 1. 上行速率闸门

`internal/gateway/uplink.go` 包装请求体，每读一块就按「已写字节 / 已耗时间」估算：

```
rate = sent / elapsed
eta  = (total - sent) / rate
eta > 本次尝试预算 - 3s  →  立即中断
```

- 判据用**本次尝试的 90 秒预算**，不是请求总预算 240 秒：尝试本来就会在 90 秒被看门狗
  掐断，拿 240 秒比等于永不触发。
- 采样需同时满足 256 KiB 与 1 秒，小请求完全不参与（慢启动不能代表线路带宽）。
- 只替换 `http.Request.Body`，**保留 `ContentLength`**：否则出站退化成
  `Transfer-Encoding: chunked`，字节形态偏离官方客户端。
- 不冷却账号、计入软失败 `uplink_slow`（连续两次 → 线路隔离 30 分钟）。
- 全部尝试都因上行不达标被淘汰 → `503 upstream_uplink_too_slow` + `Retry-After: 30`，
  不再伪装成 524 或 `no_available_account`。

预期：8.34 MiB 在 19 KB/s 的线上，从「白等 90 秒」变成「约 2 秒换线」。

## 2. 连接失败归因线路

- 同步：`client.Do` 返回传输层错误（dial / TLS / 写入 / 重置）时，**不再冷却账号 300 秒**，
  只记错误证据并换线；线路级止损交给软失败「连续 2 次即隔离」。
- 异步：连接失败此前既不冷却账号、也不回避线路；现在返回 `errLineTransport`，
  与超时同一条出路（换线、按票据共享预算），日志文案区分「上行带宽不足 / 线路连接失败」。
- 回退开关：`ZCODE_COOL_ON_CONNECTION_FAILURE=1` 恢复旧行为。

## 3. 巡检双证退休

v2.10.22 的巡检结论只回写状态：实测 22 条结论全是 `suspect`、**0 次删除**。原因是
`route_correlated` 要求「两轮 target 405 + 参考线成功、间隔 ≥5 分钟、10 分钟内新鲜」，
叠加每目标 1 小时诊断限频后几乎不可达。

新判据用两条**互相独立**的证据：

```
该线路已被隔离 ≥ 2 次（Strikes≥2，即 30 分钟放出去后又被真实流量 405）
且 巡检结论 = failed
且 Policy.Mode = auto_retire
→ startStrictRetirementLocked(..., "line405_probe_control", ...)
```

删除仍走唯一退休事务：保护名单（手动保护 / 默认出口 / 托管默认线路）、配置代次、
证据窗口全部沿用既有校验；删除写订阅墓碑，不会被下一轮订阅拉回。

## 4. 请求级 405 一次性放行

`ReplayGuard` 条目增加「一次性放行余额」：

- 判定成立时武装 1 次（同一窗口内重复判定**不重新武装**，防止重试风暴把脏线当免费额度）；
- 入口检查改用 `Take()`：第一次同内容请求放行，第二次起才返回 `503 risk_control_cooldown`；
- 每 60 秒窗口最多多试 3 条线，代价有界。

依据：10:34:30 那次判定后，客户端 57 秒内重试 11 次全被挡，而 **207 秒后同内容
（827687B vs 827622B）换线即成功**——内容没问题，是连撞三条脏线。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZCODE_UPLINK_GATE` | `1` | 上行速率闸门开关 |
| `ZCODE_UPLINK_GATE_MIN_BYTES` | `262144` | 低于此体量不判定 |
| `ZCODE_UPLINK_GATE_MIN_MS` | `1000` | 最短采样时长 |
| `ZCODE_UPLINK_GATE_MARGIN_SECONDS` | `3` | ETA 与预算的安全余量 |
| `ZCODE_COOL_ON_CONNECTION_FAILURE` | `0` | 1 = 恢复「连接失败即冷却账号」 |
| `ZCODE_LINE405_PROBE_RETIRE` | `1` | 0 = 只隔离不删除 |
| `ZCODE_LINE405_RETIRE_MIN_STRIKES` | `2` | 触发退休所需的隔离次数 |
| `ZCODE_RISK_REPLAY_ALLOW_ONCE` | `1` | 0 = 判定后一律封锁 60 秒 |

## 诊断

- `[#]` 行末尾新增 `up_kbps=`（最后一条尝试的实测上行速率）与 `uplink_abort=`
  （被闸门淘汰的尝试次数）。`up_kbps` 为 `-` 表示未采样（小请求或闸门关闭）。
- 日志：`上行速率不足（账号 …，线路 …，19 KB/s），换线重试`、
  `line405-probe retire id=… decision=… removed=… reassigned=…`。

## 兼容性

- 无数据迁移；`accounts.data` 键集不变。
- `proxy_soft_failure_state` 新增信号值 `uplink_slow`（旧版本读到只当作未知信号）。
- 四项开关互相独立，可分别回滚。

## 回归覆盖

闸门：慢体中断 + 原因哨兵、快体不触发、小体不参与、`ContentLength` 与 `GetBody` 保持、
开关与门槛、实测速率；连接失败：默认不冷却 + 开关恢复旧行为（同步）；
重放：一次放行、余额耗尽拦截、同窗口不重新武装、新窗口重新武装、开关关闭即拦截；
双证退休：两次隔离 + 失败结论删除、单次隔离不删、observe 模式不删、开关关闭不删。

所有自动化验证由 GitHub Actions 执行，分支 CI 与发布工作流复用的完整 CI 均为门禁。
