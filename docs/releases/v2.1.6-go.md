# v2.1.6-go

回移上游 `gakiyukr/zcode2api-plus` 自 v2.0.7-go 以来一轮审计修复中的 11 笔（上游已到
v2.0.9-go）。这批全部是缺陷修复，没有新功能；本地逐条读 patch 后核对，**10 笔对应本仓库
确认存在的真实缺陷**，含 3 处「会带走整个进程」和 1 处「代理链路每连接污染 1 字节」。

## 修复

### 出站代理：socks5 域名回复少读 1 字节

CONNECT 回复的地址类型是**代理**选的。当代理回 `ATYP=0x03`（域名型 BND.ADDR）时，读取
长度算成了 `(len-1)+2` 而应为 `len+2` —— 每连接有 1 字节留在 socket 里，被后续应用层
当成数据首字节，表现为 TLS 握手失败或请求行被吃掉。

**任何 socks5 / socks5h 线路只要回域名型地址都会中招**，不只是 socks5h。同时补上回复
版本号校验（非 `0x05` 直接判失败，不再当成握手成功继续用隧道）。

### 三处会终止整个进程的路径

- **`quota` 解析**：`entitlements` 以 `map[any]` 为键，上游把 `entitlement_id` 回成数组
  或对象时 `hash of unhashable type` —— 该调用发生在自建 goroutine 里，`net/http` 不会
  兜，**一个异常响应就能杀掉进程，连带掐断所有在途串流**。改为按字符串键，非字符串跳过。
- **`quota` 刷新路径**：`FetchQuota` 的查询 goroutine、 `RefreshAccounts` 的每账号
  goroutine、后台监控的每一轮，现在都各自隔离 panic（兜住之后仍保证唤醒等待者、清理
  inflight，否则把 panic 换成死锁）。
- **请求体无上限**：八个入口都把 `r.Body` 直接解进 `map[string]any`，网关还会按候选账号
  再序列化一次，一个超大 JSON 就能吃光内存。改为服务端统一限 16 MiB（中间件包在 mux
  外层，新增端点自动受保护）+ 请求头 64 KiB。

### 验证码池两处「永久失效」

- **排队请求被取消时不归还槽位**：槽位只在 `serveLoop` 顶端归还，错过一次就永不执行，
  池容量永久少一格 —— 默认 `size=1` 时整个池失效，而 `IsStarted` 仍是 true 不会被重建。
- **死亡探针没有 deadline**：`Browser.getVersion` 跑在无超时的 ctx 上，浏览器假死
  （CDP socket 连着但不回应）时探针永久阻塞，槽位再也回不来，调用方即使超时也走不到
  「判死槽位 → 重建」那一步。改为 3 秒超时。

### 内存边界

错误响应体与「200 但为 JSON」的异常分支原本整段读进内存做分类，上游或代理异常时可能回
任意大的 body。四处读取统一限 64 KiB（正常流式路径边读边传，不受影响）。

### 数据完整性

- **账号 ID 按字节截断**：`safe[:32]` 会把多字节字符切成非法 UTF-8（11 个汉字 = 33 字节），
  落库后主键与内存不一致，**重启载入时同一账号被插成第二行**。改为按 rune 截断。
- **删除账号先改内存再落库**：落库失败时账号在本次进程里已消失、重启后又回来 —— 删除
  常用来撤销可疑或外泄的凭证，这种「显示已删除、实际还在」是安全相关的静默失败。改为
  先落库；后台删除接口也不再吞错误，任一失败即回 500 并带 `failed` 列表。
- **新建账号同理**：先落库再改内存。
- **设备指纹落盘失败静默**：`DeviceMid()` 忽略 `MkdirAll`/`WriteFile` 的错误，落不了盘时
  每次重启都换一个指纹（上游视为新装置），而管理员只看到「账号莫名被风控」。现在写
  stderr 提示。

### 落库顺序与设置读取

- **设置改为先落库再改内存**：失败时内存不再留下一个重启就回滚的值。
- **落库失败不再完全静默**：统计路径刻意忽略 `Update` 的错误，但「磁盘满导致统计与状态
  全部不落库」此前在日志里毫无线索。新增节流（每分钟一条）的失败日志；该 helper 在持有
  store 锁时调用，因此只在锁内判断、**把 stdout 写交给独立 goroutine**（stdout 阻塞会
  把整个 Store 锁住）。
- **设置读取改走原子快照**：鉴权路径每次请求都要读设置，原来与写路径共用 store 锁，
  一次慢写（`busy_timeout` 最长 5s）会让所有请求的鉴权一起排队。现在读完全不碰锁；
  写入点（`load` / `SetSetting` / 线路落库）都会发布新快照，且有测试钉住「写入后立即可见」。

## 验证

- 新增回归用例：socks5 域名回复（断言握手后管道无残留字节）、不可哈希 entitlement
  （含正常字符串仍能对应周期）、验证码槽位归还（取消与关闭两条出路）、错误体限长
  （限内仍分类 / 限外不参与）、quota panic 隔离、账号 ID 按 rune 截断、删除与新建的
  落库顺序、`SetSetting` 落库失败后内存不变、设置写入立即可见。
- **反向验证**（临时退回改动确认用例变红）：socks5 残留字节实测为 `\x90HELL`；
  不可哈希键实测为 `panic: hash of unhashable type` 且崩在 `FetchQuota` 自建 goroutine；
  验证码槽位用例两条子用例同时变红；错误体限外的业务码不再参与分类。
- `go build ./...`、`go vet ./...`、`go test -count=1 ./...` 通过；本机 `-race` 不可用
  （无 gcc / cgo），由 CI 覆盖。本机 `internal/captcha` 的符号链接用例仍因沙箱把
  symlink 降级而失败，与本版本无关。

## 本轮未做（已知，记录在案）

1. 后台设置的「全量校验后批量落库」：现在仍是验证一段写一段，中途失败会留下半套生效的
   配置。需要重写该 handler（本轮未纳入）。
2. 前端 `accounts.tsx` 与 `frontend/dist` 重建：后端已改为删除失败回 500，前端提示仍会
   显示「已刪除」；改前端需重建 dist 再入库，建议单独一次做。
3. 后台页面的 CSP 安全头：金钥存在 localStorage，加固有价值，但我们的前端与上游不同，
   应先审计外部脚本来源再上。
4. `claim`/`quota` 共享直连 client：纯性能优化。

## 升级

```bash
docker compose pull && docker compose up -d
```

无需任何配置变更。数据层修复只影响**新建**账号的 ID；已存在的中文名账号 ID 不会被改写，
但如果你在旧版本上曾对超长中文名账号做「删除后重新添加」，建议核对账号列表里有没
重复条目。
