# v2.0.11-go

代理检测收敛为只验证一件事——能不能连上 z.ai；账号页的额度单元格也收窄了，
右侧的呼叫／失敗／Tokens／操作等列不再被挤出视窗。

## 行为变更

- **不再查询出口 IP / 国家 / ASN**。上一版为出口信息与 z.ai 可达性并存，
  本版把出口查询整体删除：出口 IP 与 ASN 只能证明「线路活着、落地在哪」，
  证明不了「z.ai 接受这个出口」——被边缘拦截、被代理按域名白名单挡住都测
  不出来，而后者才决定这条线路对本项目有没有用。后台因此**不再显示出口
  IP / 国家 / ASN**，只保留三态结论。
- **连不上 z.ai 不再返回 502**。那正是探测要报告的结论，不是接口错误，所以
  改为 `200 + ok=false` 加一句可读原因（「z.ai 返回边缘拦截页」或具体网络
  错误）。502 现在只留给代理协议不支持这类真正的请求错误。
- **单条检测最坏耗时由 36 秒降到 12 秒**。原来绝大部分时间是在等出口查询站
  超时；现在只探两个 z.ai 入口，各 6 秒超时。批量仍按 8 路并发。
- **两个界面名称随之调整**：「伺服器目前出口」→「伺服器直連 z.ai」，
  按钮「測試目前線路」→「測試直連」——它测的本就是「服务器自身（不经代理）
  能不能连上 z.ai」，外网断了或 z.ai 挂了时能先排除这一层。

## 新增内容

- **z.ai 侧入口可达性成为唯一探测口径**：经同一条线路对上游真实入口
  （`zcode.z.ai`、`api.z.ai`）发一个无凭据请求，判据是**能否拿到 HTTP
  响应**而非状态码是否 200——无凭据请求本就该被 401/403 拒，拿到状态码恰恰
  证明请求已到达 z.ai 的边缘。逐入口的状态码与耗时也一并返回，可区分
  「主站被拦、备援站仍通」。

## 修复内容

- **额度单元格撑破表格**：账号页每行的配额进度条此前用 `flex-1`，会被拉满
  整个单元格，把右侧的「呼叫／失敗／Tokens／最近使用／操作」挤出视窗。现改为
  固定宽度（80px），模型名那一列也固定宽度以保证各行进度条对齐，剩余/总量
  数字右对齐。整行收敛到约 300px，腾出的横向空间回到原本的列。

## 使用说明

代理页仍是两个入口：「測試直連」验服务器自身到 z.ai 的可达性，「測試全部線路」
并发探测所有启用中的线路。结果三态不变：**绿色为可用，琥珀色为被 z.ai 边缘
拦截，红色为不可达**。无需任何配置。

批量检测单条最坏 12 秒，全量约为 `12s × ⌈N/8⌉`；测试期间按钮禁用。

仍然测不到的三件事：代理是否缓冲 SSE 长流（本项目 `unexpected EOF` 那一族故障
的成因）、请求体大小上限、以及账号级的 429/403——它们都需要带凭据的真实请求，
本次没有为此引入副作用。

[客户端兼容说明](https://github.com/fujunchao/zcode2api-plus/blob/v2.0.11-go/docs/client-compatibility.md)

## Docker

```bash
docker pull ghcr.io/fujunchao/zcode2api-plus:2.0.11-go
```

支持 linux/amd64 和 linux/arm64，同时更新 latest。现有数据卷与非 root 运行
方式不变。

## 能力依据

- [Z.AI 官方文档](https://docs.z.ai/)

探测只读取 HTTP 状态码与响应头，不发送任何凭据，也不改变本地代理配置或账号
状态；检测结果不落库，仅用于后台展示。

探测改为单口径已通过单元测试与本地全量测试（三个用例分别覆盖「可达」、「被
边缘拦截」、「完全不通」；桩服务器同时冒充代理与上游入口，整条链路不触网），
但**尚未经过线上真实代理环境验证**。另外额度单元格的宽度改动**未经目视确认**
——只保证不撑破表格，实际观感仍待在线观察。
