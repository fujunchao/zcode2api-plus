# v2.5.0-go

一次**功能加固版**。立项依据是 2026-09-22 事故定论（`docs/analysis-flash-5min-stream-cut-20260921.md` §8）：
DSH 会话三次 ~300s 思考断流全部落在 **mihomo-zai-024 同一账号同一线路**（诊断行 `trunc_total`
1→2→3 是账号级计数的铁证），成因是「中途断流不标账号」+「额度优先黏住最富账号」；当天其余
9 条线路 10 次 >300s 长流全部成功——墙是**单条线路的连接时长上限**。本版把止损做进网关，
两条止血线（立即换线 + 连击熔断）都在真实流量上自动生效。契约见 `PLAN.md` §5.15 / M20。

## 一、线路断流熔断（核心）

同一**线路**连续 N 次上游侧断流（默认 3，后台「系統設定 → 線路斷流熔斷」在线可改，0=关闭）
即自动移除该线路并改派绑定账号——复用 proxy-health 的 `PurgeProxyProfiles` 原子路径，
日志打 `[~] line-guard`。

- **按线路聚合而非按账号**：多账号可共享一条线路，责任也在线路。按账号聚既命不中真凶，
  又会把上游的墙变成对账号的集体惩罚（与 405/503 两次事故的教训同源）。
- **「连续」以完整成功交付为复位点**。复位刻意不放进 `MarkSuccess`：engine 的 success 在流
  开始读取之前调用，「每次正常开头、~300s 被切」的链会刚复位又被计入，永远凑不满连击。
- 账号级 `StreamTruncateCount` 语义不变（纯观测、只增不清、不驱动状态机）。
- sync 与 async 两条路径统一走 `gateway.RecordUpstreamTruncate`，顺手修掉 async 在
  `diag==nil` 时断流整段漏记的缺陷（诊断行只是展示，计数与熔断必须照常发生）。

## 二、断流账号短回避 + 即时额度刷新

- **短回避**（默认 60s，在线可改，0=关闭）：上游侧断流后，该账号在回避期内暂不被选号——
  **仅选号层软过滤**，不是冷却：不写 Status/CoolingUntil/last_error、不进面板、到期自动失效、
  全池被回避时不过滤（保证永远选得出号）。客户端 TRANSPORT 重试 ~2s 后原样重放，这一层让
  重试**立即换线**，比 3 连击熔断更早止血——本次事故里它能省下后两次各 ~5 分钟的白烧思考。
- **断流即额度刷新**（sync + async）：断流账号的额度读数停在旧值，会以「幽灵最富」持续黏住
  额度优先调度；刷新让下一次选号回到真实读数。async 池为此新增 `OnQuotaRefresh` 钩子。

## 三、后台线路页：断流计数 + 流式探测

- 每条线路显示**断流徽标**（连续/累计，`GET /admin/api/proxies` 合并内存态计数）；账号
  API 新增 `stream_truncate_count`。
- 新增**「流式探测」**按钮（`POST /admin/api/proxies/{id}/stream-test`）：借该线路绑定的
  JWT 账号发一条最小流式请求（≤30s），回答「响应头能不能到、首个数据行多久到、流能不能走到
  message_stop」——「能连上、能协商、但流在中途被掐」这一族只有它看得见，普通 GET 探测
  结构上抓不到。**能力边界**：30s 预算测不出 300s 量级时长上限，那由熔断用真实流量兜底；
  探测只读（不写账号状态、不记断流、不入用量账），任何完整业务响应（401/429/验证码挑战）
  判连通性通过。

## 四、验证与已知事项

- 新增回归 15 组：熔断（含阈值 0 关闭、成功复位、移除+改派、日志）、短回避（用额度差构造
  黏性，证明是回避而非轮询在换号；全池回避不饿死）、断流刷新（sync/async）、store 计数与
  软过滤、adminapi 设定往返与非法 400、探测四分支、`TruncateAvoidUntil` 的 Clone/序列化守卫。
- `[#]` 诊断行格式未动（契约冻结）；`accounts.data` 34 键契约未动（新字段全部 `json:"-"`）。
- 在线观察项：好线路被 3 次偶发断流误杀的频率；阈值 3 / 回避 60s 是否合适（后台均可调）。
- 本机（Windows）跑全量测试偶现 `TempDir RemoveAll cleanup` 竞态失败——已用基线对照确认是
  预存的环境性 flaky（无我的改动同样出现），非本版回归；权威验证以 CI（Linux + -race）为准。
