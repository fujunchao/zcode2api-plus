# v2.9.15-go

为**风控失效**账号补上手动恢复入口：此前被连续风控命中升格为失效的账号只能靠
「换凭据」救回，现在后台账号页提供单条与批量恢复。不修改请求协议、调度、重试预算或
风控保护阈值；纯新增功能，不调用新端点即无感知。

## 手动恢复（单条 + 批量）

连续命中风控超过阶梯档位数（默认第 4 次）后账号被置为**失效**，且不受额度探测、
成功调用等自动路径影响。本版为其补上显式的管理员救济出口：

- 单条：`POST /admin/api/accounts/{account_id}/recover` → `200 {"ok": true}`；
  账号不存在 404；非风控失效或已归档 400。
- 批量：`POST /admin/api/accounts/batch/recover`（体 `{"ids": [...], "missing_ok"?: bool}`）
  → 逐条明细（ok / not_found / error）；严格模式（默认）含缺失 ID 则整批拒绝、零改动。
- 判定收口到单一来源 `model.IsRiskControlInvalid`（`status=invalid` 且
  `last_error_kind=risk_control`）；额度侧的风控保护改为调用同一函数，行为不变。
- 动作与「换凭据」同语义：`Status → active`、清 `CoolingUntil`、`RiskControlStreak → 0`、
  清 `LastError*`；**不动** `Enabled` 与归档标记（启停、归档与本出口正交）。
- 只接受风控失效：冷却中（会自然到期）、凭据失效（另有额度探测恢复路径）、额度耗尽、
  已归档（先恢复到账号池）一律拒绝；批量里逐条回报为失败、不整批中断。
- ⚠️ **不解除上游仍生效的账号级标记**（实测 ≥14 小时）：若上游仍在拦截，恢复后会重新
  冷却或失效（连击从零起算，重走阶梯）。

## 后台界面

- 账号页对「风控失效」行显示**手動恢復**按钮（仅此类账号渲染，不影响其它行的布局）；
  确认框注明「不會解除上游仍生效的風控標記」，并显示最近风控时间。
- 批量栏新增**批量恢復**：对勾选集合全量提交、服务端逐条判定，非风控失效项逐条回报失败。
