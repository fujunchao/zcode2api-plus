# v2.11.12-go

## 同步 ZCode 3.17.2 客户端声明（system 文案与 3.17.1 逐字节相同，复用同一份档案）

### 一、背景

ZCode 桌面客户端 2026-11-02 发布 3.17.2（app.asar build `a2d1ba73`，exe `3.17.2.9661`）。
上游按 `app_version` 判定套餐投放资格，并对「system 第 0 字节 → 身份段末尾」做逐字节校验，
所以客户端每次升版都必须先把这两段文案核清楚，再决定版本号怎么跟（2026-11-01 的事故就是只升版本不换文案）。

本次对 3.17.2 安装包做了只读逆向（app.asar 31,849 文件全量解包 + resources 整份比对 + 随包 CLI 重建），
结论是 **wire 面零变化**：

| 面 | 3.17.1 → 3.17.2 |
|---|---|
| system block0 | 35 B / sha16 `7779642ea44a4696`，逐字节相同 |
| 身份段 | 1231 字符 / 1235 B / sha16 `4058874023c7541f`，逐字节相同 |
| 伪装来源头 | `buildZCodeSourceHeadersFromContext` 827 B ↔ 827 B，仅 3 个压缩标识符改名；11 个头名与取值来源全同 |
| 端点 | out/ 路径字面量 143 → 143（0 增 0 删）；URL 168 → 168、域名计数全同 |
| UA 组成 | ai-sdk 4.0.27、Electron 44.7.0 / Node v24.21.0 全同 ⇒ `runtime/node.js/24` 不变 |
| 模型目录 | `config/provider/zcode-builtin.json` 逐字节相同（`62412a27…`） |
| minCompatibleVersion | 命中 31 → 31，仍只服务 Source Server 兼容协商，不是模型 API 门槛 |

分析全文见 [3.17.2 逆向报告](../analysis-zcode-v3.17.2-20261103.md) 与
[项目影响笔记](../analysis-zcode-v3.17.2-project-impact-notes-20261103.md)。

### 二、本版改动

| # | 改动 | 说明 |
|---|---|---|
| A | 默认客户端声明 `3.17.1 → 3.17.2` | UA / `X-ZCode-App-Version` / 查询参数 `app_version` 全部由 `ZcodeClientVersion` 派生，改一处即全链路生效 |
| B | 版本→文案档案映射补 `3.17.2` | 原 `ZcodeSystemProfileFor` 只认精确串 `"3.17.1"`：只升版本号会**静默回落 legacy 文案**（block0 42 B），正是 405/3012 的形态 |
| C | 新增 `ZcodeSystemProfileForExact` + 启动告警 | 未命中精确映射时启动横幅显式告警，把静默错配变响 |
| D | 新增 `TestDefaultClientVersionHasExactSystemProfile` | 默认版本一旦升到没核验过文案的版本，CI 立即失败 |
| E | `internal/upstream/system_profile_test.go` 增 3.17.2 用例 | 用同一组基线（1235 / `4058874023c7541f`）锁死「3.17.2 与 3.17.1 文案相同」 |

### 四、兼容性与回滚

- 接口、配置项、数据结构均无变更；升级后用户无需操作。
- 回退：在 `.env` 设 `ZCODE_CLIENT_VERSION=3.17.1` 并重启；根目录 Compose 已按同名值透传。未使用 Compose 时直接设置进程环境变量。
- 回退目标必须是「有精确档案的版本」：3.17.1（3171 档案）或 3.16.3（legacy 档案）；中间版本没有映射，会静默回落 legacy。
- ⚠️ 只把版本号改到 3.17.2、镜像仍是旧版（无映射）的部署，会以「新版本号 + legacy 文案」出站并触发 405/3012；本次修复必须随镜像一起升级。

### 五、档案完整性校验的哈希口径

`internal/upstream/zcode_system_3171.json` 的 sha256 与取文件方式有关：

| 口径 | 大小 | sha256 |
|---|---|---|
| Git blob / `raw.githubusercontent.com`（LF） | 7,728 B | `df76f852d50cdd279638b5f3f64b7090168bb70b8f6fe0e9d9064fbdbf829620` |
| Windows 工作区检出（CRLF，`core.autocrlf=true`） | 7,749 B | `4db29a33dc6f04c43538a9cea06917b431541008230f84cd037bd38d58a6f740` |

差异只在换行符，解析出的 blocks 完全相同；**校验完整性用 git blob / raw 口径**。

### 六、仍未覆盖
