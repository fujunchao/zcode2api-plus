# v2.9.9-go

修复上游 API Key 账号的模型额度恢复后仍持续返回“无可用账号”的问题，并同步 ZCode 客户端声明。

- 默认 `ZCODE_CLIENT_VERSION` 更新为 `3.14.5`，请求头、配置查询和默认 UA 继续统一派生；不改变模型协议、验证码分工或 Coding Plan 重置接口。
- 普通 Anthropic/OpenAI 网关优先使用正常账号；正常候选用尽后，允许到期的 API Key 模型借一次真实请求探测恢复，不额外生成模型请求。
- 首次等待 5 分钟，未成功时依次等待 15 分钟、1 小时、6 小时并封顶；明确欠费、套餐过期、不包含模型从 6 小时起步。每账号/模型独占，每个入站请求最多一个恢复探测。
- 发送前持久化下一次探测时间；重启保留退避。旧耗尽记录自动建立恢复状态，不需要删除再添加账号。
- 仅完整有效的模型响应可以解除目标模型标记；取消、错误响应、SSE 错误和断流不作恢复。不会解除风控、未到期冷却、归档或人工停用。
- 通过失败代次、凭据及出站身份校验保护并发修改；恢复记录与账号变更同事务提交，落盘失败不乐观发布成功。
- JWT 继续使用原有余额刷新，异步池继续只使用 JWT；未新增官方手动重置/领取机会功能。

无需数据库结构迁移，账号 JSON 字段保持兼容。内部恢复元数据不通过账号导出或公开设置暴露。
没有流量或仍有健康候选时不主动探测；外部重置配额不代表网关立即解除耗尽，要等待下一次符合条件的真实请求确认。

替换程序或镜像并重启服务即可生效。部署若显式设置 `ZCODE_CLIENT_VERSION` / `UPSTREAM_USER_AGENT`，还需检查实际传入进程或容器的覆盖值。独立 `zcode-switch` 仓库不包含在本次发布中。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.9-go` 与 `latest`。
