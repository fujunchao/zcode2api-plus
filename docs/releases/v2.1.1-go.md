# v2.1.1-go

一次**以并发正确性为主的重构版本**，附带一处后台界面布局修复。对外接口、配置项、
数据格式与 2.1.0-go **完全一致**，升级只需重启。

## 本次解决的核心问题

服务里长期存在一类「账号对象被多个 goroutine 无锁共享读写」的竞态：`store` 的读
接口把**内部指针**交给调用方，而调用方习惯「在锁外改字段，再调 `UpdateAccount`
落库」。CI 的 `go test -race` 实测抓到两对：

- 后台领取任务读账号 `ProxyURL` ‖ 删除线路时在锁内写 `ProxyURL`；
- 后台领取取账号副本 ‖ 额度刷新写 `Plans`/`Quota`/`Status`。

排查中有两条结论值得记下：**只改读侧没用**（取副本本身就是一次读）；**只改写侧
也没用**（Go 内存模型下「无锁读 vs 加锁写」仍然是竞态）。所以这一版把两侧一起改：

- **读侧**：`Select` / `Find` / `FindAny` / `ListAccounts` 一律返回**深拷贝**，
  账号对象不再逃出 store；长活任务（后台领取）改用副本，结果按 ID 回写。
- **写侧**：新增 `Store.Update(provider, id, fn)` 作为唯一的账号变更入口——读改写
  全程在同一把锁内完成。`quota`、`gateway`、`asyncpool`、`adminapi` 的写入全部迁入。
- **删掉 `UpdateAccount`**：那个「锁外改完再落库」的载体从 API 层消失，新代码想误用
  都会被编译器拦住。

顺带修掉 2.1.0-go 里一个不彻底的地方：额度信号的强状态守卫（`invalid` / `cooling` /
`disabled` 不被额度信号刷回 `active`）此前是在**锁外**判定的，判定与写入之间仍有窗口；
现在整段判定都在锁内，窗口消失。

## 行为变更

- **编辑账号时校验失败不再留下半套改动**。此前字段是逐个直接改在账号对象上的，
  若后面的字段校验失败（例如代理地址非法），前面已经改掉的字段仍会被落库；现在
  先把请求体解析、校验成一份补丁，校验全通过才在锁内一次性应用。
- 账号已被删除时，状态标记（限流冷却、模型耗尽等）静默跳过而不是尝试回写。

除此之外**没有对外可观察的行为变化**：HTTP 接口、`accounts.data` 的 JSON 契约、
导出格式、配置项与后台界面功能均不变。

## 修复内容

**后台界面**

- 账号表格的「額度」列不再被超长文本撑开。`claim.last_error`（上游错误体原文）与
  代理名渲染时没有截断，而表格单元格带 `whitespace-nowrap`——任意一行出现长文本，
  该列最小宽度就会被顶到六七百像素，表头飘到内容之外、右侧几列被裁掉；坏行常常
  不在首屏，所以只表现为「某列莫名很宽」。现在这两处都限宽截断（悬停可见全文），
  额度数字紧跟进度条而不是被推到格子右缘。

**并发正确性**

- 额度刷新、后台领取、删除线路改派三条路径现在互不交错：写入都在同一把锁内完成。
- 领取结果回写只改领取状态字段，不会用旧副本覆盖掉期间发生的线路改派。

## 运维 / CI

- CI 的竞态检查步骤改为 `go test -race -count=1 ./...`。此前不带 `-count=1`，测试
  结果缓存可能让「这次其实没跑」显示成通过——竞态是时序相关的，缓存下来的 PASS
  不能当作证据。

## 验证情况

- 本机：`go build`、`go vet`、全量测试（`-count=1`）、`gofmt` 74 文件 0 不合规、
  四平台交叉编译，全部通过。
- 新增回归用例：读接口返回副本（含内层 map 深拷）、字段级写入方法的逐项语义、
  账号不存在时的返回值、以及「回写领取状态不得覆盖并发改派」。
- CI：同一提交**连续两次**全绿（含 `go test -race -count=1`）。

**仍未覆盖的部分**（与上一版相同）：

- 本机没有 C 编译器，`-race` 结论全部来自 CI；
- 容器实跑与验证码浏览器路径仍无实机验证；
- 反代场景「端口只绑回环」是建议而非自动生效。

```bash
docker pull ghcr.io/fujunchao/zcode2api-plus:2.1.1-go
```

支持 linux/amd64 和 linux/arm64，同时更新 latest。现有数据卷与非 root 运行方式不变。

## 能力依据

- [Z.AI 官方文档](https://docs.z.ai/)

本版的设计参照了上游仓库 `gakiyukr/zcode2api-plus` 的同名重构（其做法是读接口返回
深拷贝 + `Update(provider, id, fn)` 锁内写 + 删除 `UpdateAccount`）。我们按自身结构
独立实现，并保留了本仓库独有的增量：账号领取状态的独立锁与不可变替换、删除线路时
在单锁内完成「摘指派 → 补位 → 退回直连」。
