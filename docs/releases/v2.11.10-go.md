# v2.11.10-go

## 补齐第二条泄漏路径：字符串形态的 system 也必须重建

### 现场（v2.11.9-go 实测）

`v2.11.9-go` 修好了块形态：不带 system 的常规请求走 `gateway_fallback`、
`official_identity_match=true`、200。但**字符串形态**仍能穿透：

```text
system_source=input system_form=string system_blocks=1
system_text_bytes=[66]
official_prefix_match=true official_identity_match=false
→ 405 / code=3012
```

复现请求体：`{"system": "You are ZCode, an interactive agent\n\nSome custom instructions here", ...}`

### 根因

`ShouldPreserveCallerSystem` 的字符串分支仍只做前缀匹配。字符串形态**无法携带身份段**，
所以「前缀 + 任意自定义指令」透传出去，上游从第 0 字节校验到身份段末尾时必然失败。

### 修复

字符串形态除「显式空值」（调用者声明无指令）外**一律重建**：走三块 canonical，
调用者原文并入 dynamic 块，内容不丢。同时删除已无调用方的 `hasOfficialSystemPrefix`。

### 回归测试

- `internal/upstream/preserve_test.go`：字符串为「官方前缀 + 自定义指令」→ 不保留；
  字符串为「仅官方前缀」→ 不保留；空串 → 保留。
- `internal/openai/protocol_attribution_http_test.go`：原生 `/v1/messages` 入口的字符串
  system 必须重建为 canonical，且原文并入 dynamic 块。

### 升级与回退

- 默认仍是 `3.17.1`；升级后用一条**带自定义 system 的字符串请求**验证：
  日志应为 `system_source=gateway_fallback` 且 `official_identity_match=true`。
- 回退：`ZCODE_CLIENT_VERSION=3.16.3` + 重启，无需换镜像。
