# v2.15.0-go

接入 GLM-5.4，并修复上游额度结构变化导致的 GLM-5.3 额度丢失与调度排除。

## 修复：额度模型身份改为读 capabilities

2026-11-23 起，上游 `billing/balance` 的余额条目把模型身份放进 `capabilities`
（如 `["model:glm-5.3"]`），`show_name` 可能为空、且不再有 `model` 字段。旧解析只读
`show_name` / `model`，把 GLM-5.3 额度落成通用名 `model`：

- 后台“GLM-5.3 额度”显示 0 个账号、0 个额度项目；
- `ModelAvailability` 对请求模型判 `absent`，`Select` 只保留 `available`/`unknown`，
  导致 80/80 个账号被排除出 GLM-5.3 调度。

现在按官方 `resolveZaiStartPlanBalanceModelIds` 的口径解析：`capabilities` 的
`model:` 项优先，其次 `show_name` / `model`，全空才使用兼容占位名；多模型共享额度桶
时各记一列。同一解析也用于账号初始化观察。旧快照里身份未知的 `model` 桶在
`ModelAvailability` 中按 `unknown` 处理（不再判 `absent`），避免部署后到额度刷新前
出现 5.3 全池 `no_available_account`。

## 新增：GLM-5.4

- `AvailableModels` 增加官方标准 ID `GLM-5.4`（云端运行时目录 revision 48 下发），
  `/v1/models`、Messages / Chat / Responses / Async 四个入口与后台额度汇总同时生效。
- `ModelNameMap` 增加 `glm-5.4 → GLM-5.4`，小写请求统一映射到官方 ID。
- OpenAI 兼容入口的 `reasoning_effort` 支持 GLM-5.4 的 `low/high/max` 三档；
  与 5.3 一样不能关闭思考。
- `probe` 新增 `--effort`，用于单账号验证三个思考档位。

## 验证

- 新增 capabilities 解析、共享额度桶、旧快照 unknown、`/v1/models`、四入口白名单、
  GLM-5.4 推理档位等回归；自动化测试、构建与静态检查在 GitHub Actions 执行。
- 部署后：后台额度刷新恢复 5.3 行；单账号探针验证 GLM-5.4 的 low/high/max 三档。

## 升级与回退

镜像：`ghcr.io/fujunchao/zcode2api-plus:2.15.0-go`，同时更新 `latest`。
二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。

本次没有数据库迁移。额度快照会在部署后的后台刷新周期内自动重建；需要立即生效可
