# v2.11.11-go

## 流水线瘦身（每次发版省约 10 分钟）+ `status` 只读打开

### 一、为什么要改

统计最近 40 次运行：分支 CI 平均 5.6 分钟、`go-rewrite` CI 7.5 分钟、release 9.3 分钟，
**一次发版纯流水线 ≈ 22 分钟**，其中约 13 分钟是「同一份代码跑三遍」。
并且 `test` 单 job 占 7.5 分钟（build+vet+全量测试+14 组 -count=20 重复回归+race 串行）。

### 二、本版改动

| # | 改动 | 效果 |
|---|---|---|
| A | `go-rewrite` 不再触发 CI（它只接受来自已绿分支的 ff 合并，树完全一致） | 每版 **-7.5 分钟** |
| B | release 的 `validate` 传 `validate_only: true`，跳过前端/镜像/交叉编译（紧随其后的 build、image 会真正编译五平台） | 每版 **-1~2 分钟** |
| C | `test` 拆成三个并行 job：`test`（编译+vet+全量）、`test-race`（-race）、`test-repeat`（14 组重复回归，内容一字未改） | 墙钟 **7.5 → 约 4 分钟** |
| C2 | `push` 增加 `paths-ignore`：纯文档提交（`docs/**`、`**.md`、`temp/**`）跳过整条流水线 | 文档提交 **0 分钟**（原来 5.6） |
| D | `zcode2api status` 改为**只读打开**数据库，失败才回退可写入口 | 服务常驻时不再报「数据库正在被其他服务或 CLI 使用」 |

发版纯流水线预期：**22 → 约 10–12 分钟**。

### 三、status 只读的边界

- `store.NewReadOnly()`：只建连接、只读 meta 里的两个密钥 + 账号 JSON 快照；
  **不建表、不迁移、不写任何字段**（只读连接上写会直接报错）。
- 首次安装（库还不存在）时只读打开失败，`status` 自动回退到可写入口，顺带完成建库。
- 迁移仍只由 `serve` 负责——只读命令不承担任何升级职责。

### 四、回归测试

- `internal/store/readonly_test.go`：独占锁被持有（服务在跑）时，只读打开必须成功且能读到账号与密钥；
  库不存在时只读打开必须报错（调用方据此回退建库）。

### 五、兼容性

- 接口、配置项、数据结构均无变更；`status` 输出格式不变。
- 发布门禁没有放宽：`release.yml` 仍先跑 `ci.yml`（test / vet / compat / workflows），
  只是不再重复跑「构建/镜像」这类马上就会真跑一遍的 job。
