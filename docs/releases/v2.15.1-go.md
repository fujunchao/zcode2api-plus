# v2.15.1-go

模型额度改为「按当前权益公布」，并对已下架模型返回确定性 400，避免客户端与中转层把永久下线当成临时故障反复重试。

## 背景

2026-11-24 起 ZCode Start Plan 官方目录（CDN revision 48）已用 **GLM-5.4** 取代 **GLM-5.3**：
生产 80 个 `zai/jwt` 账号的额度快照只剩 `glm-5.3-flash` 与 `glm-5.4`，`GLM-5.3` 归零。
此前 `/v1/models` 仍静态列出该模型，请求落到 `503 no_available_account`，客户端与 new-api 会当临时故障重试。

## 变更

### `/v1/models` 按当前权益公布

- 只列出池内**确有权益**的模型：至少一个账号持有该模型的额度条目，**或**存在权益未知的账号
  （从不刷额度的 API Key 账号、刚入池还没刷新过的新账号）。
- 额度列全部为「不会自动刷新且已过期」的模型不再公布（日额度不受影响：次日刷新，不抖动）。
- 全新池 / 一次额度都没刷到时退化为完整支持清单，避免返回空列表让客户端无法配置。
- `AvailableModels` 仍是请求白名单全集：仍有 GLM-5.3 权益的部署（Coding Plan、API Key）不受影响，
  官方恢复权益后也无需发版即可重新出现。

### 确定性不可用 → `400 model_not_available`

当**每个非归档账号**对该模型的权益都已确定且都是「不含」（快照里没有该模型，或额度列已到期）时，
Messages / Chat Completions / Responses 三个入口返回 `400`：

```json
{"error":{"type":"model_not_available","message":"模型 GLM-5.3 無可用帳號：目前 80 個帳號的套餐均不含此模型（該模型可能已下架、未開通或已到期），請改用 glm-5.3-flash、GLM-5.4","details":{"model":"GLM-5.3","unavailable_accounts":80,"snapshot_accounts":80,"suggested_models":["glm-5.3-flash","GLM-5.4"]}}}
```

只要还有账号持有该模型（哪怕正在冷却/耗尽/停用）、或存在权益未知的账号，仍返回 503 让客户端可重试——
「宁可 503，不可错报 400」。异步入口已先返回 200 SSE，只在 `no_account` 事件里对齐同一份文案与 details。

### 管理端「模型额度」

新增 `snapshot_accounts` 字段：0 账号的模型不再画空进度条并提示「请刷新额度」，而是区分
「账号套餐均不含（可能已下架）」与「尚未获取额度，请刷新」。

### 其他

- `probe` 默认 `--model` 改为 `glm-5.3-flash`；`examples/pi-models.json` 以 GLM-5.4 置首。
- 网关测试夹具隔离 `config.DataDir`，不再把 `device_mid.txt` 写进仓库 `data/`。

## 验证

- 新增 `internal/gateway/models.go` 与配套回归：权益四态（持有/可用/未知/已到期）、`/v1/models` 收录与兜底、
  确定性 400 与 503 的边界（冷却持有者、权益未知、无快照、日额度未刷新、1005）、async `no_account`、
  OpenAI 兼容层透传、`snapshot_accounts` 汇总。
- 自动化测试、竞态、前端 tsc/oxlint/vitest 与产物一致性、五平台交叉编译、镜像构建均在 GitHub Actions 执行。

## 升级与回退

镜像：`ghcr.io/fujunchao/zcode2api-plus:2.15.1-go`，同时更新 `latest`。
二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。

本次没有数据库迁移。部署后 `/v1/models` 立即按现有额度快照生效，无需等待刷新。
回退使用 `2.15.0-go` 镜像即可；回退后 `/v1/models` 会重新静态列出 GLM-5.3 并返回 503。
