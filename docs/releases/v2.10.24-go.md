# v2.10.24-go

## 软失败判据改为「连续失败」

v2.10.15 的软失败隔离上线一天后几乎没触发：全天只有 2 次隔离。原因不是判据写错，而是**样本量不够**——
「30 分钟内同线路 ≥3 次失败且 ≥3 次尝试」假设一条线吃很多请求，实测却是 211 次尝试分散在 84 条线路上，
单线 3 小时平均只有 2.5 次，阈值永远够不着。

本版增加**连续失败**判据：

- 成功一次即清零；
- 软失败累加，超过有效期（默认 2 小时）则重新从 1 计；
- `连续 ≥ 2 次` 即隔离，与窗口内的尝试密度无关；
- 原失败率规则保留作兜底，两条任一成立都会隔离。

有效期这一层是必要的：一条线路早上失败一次、傍晚失败一次（中间根本没有请求），
按计数会被判「连续」，但这两次相隔 6 小时，算不上连续证据。超过有效期就重新计数。

隔离仍复用既有链路：只移出自动选线、不删配置、30 分钟自动回池、到期后 30 分钟无失败则连档位一起归零。

## 拨号与握手超时收紧

复盘发现 240 秒的请求钱花在拨号上：8.7MB 请求三次 `connection_failed` 各约 70 秒。
根因是 `dialTimeout = 30s` 一个常量同时管「连代理」和「握手」，一次死线尝试最坏 60–80 秒。

拆成两个可配值：

| 变量 | 默认 | 作用 |
|---|---|---|
| `ZCODE_PROXY_DIAL_TIMEOUT_SECONDS` | `12` | 连接代理服务器本身（正常 <1s） |
| `ZCODE_PROXY_HANDSHAKE_TIMEOUT_SECONDS` | `20` | SOCKS 握手 / 到目标建连（跨境 5–10s 常见） |

单次死线尝试从 60–80 秒降到 ≤35 秒，3 次尝试的请求会在 ~110 秒内以真实错误结束，不再撞 240 秒上限。

顺带修两处：

- **`socks4` 握手此前完全没有 deadline**（`readFull` 只受 conn 读超时约束，而没人设过），
  半死不活的代理能把握手无限期挂住。现在与 socks5 共用同一份握手预算。
- socks5 的握手 deadline 改为「握手预算与 ctx 截止时间取更早者」，调用方自带更紧的 deadline 时不会被忽略。

## 连接失败也进请求级回避

此前只有首字节超时、408/524 会把线路加入本请求的回避集合。连接失败恰恰说明这条线路此刻不可用，
现在一并加入：多个账号共享同一条死线时，第二次尝试直接换线，不用再等一个完整超时。

## 诊断

`[attempt] event=error` 增加 `elapsed_ms`，`[~] proxy-soft` 增加 `consecutive=`。
前者用来验证超时是否真的生效（应从 60–80 秒落到 25–35 秒），后者是连续判据的直接证据。

## 升级与验证

无数据迁移：`ProxySoftFailure` 只新增两个可选 JSON 字段（`consecutive`、`consecutive_since`），旧记录读出为 0。

三项开关互相独立，可分别回滚：
`ZCODE_PROXY_SOFT_CONSECUTIVE=0`（关连续判据，只剩失败率兜底）、
`ZCODE_PROXY_DIAL_TIMEOUT_SECONDS=30`、`ZCODE_PROXY_HANDSHAKE_TIMEOUT_SECONDS=30`。

回归覆盖：连续两次失败即隔离、成功打断连续计数、跨有效期重新计数、关闭连续判据后失败率兜底仍生效、
拨号/握手配置读取与非法值回落、socks4/socks5 在无响应代理上按时失败。
所有自动化验证由 GitHub Actions 执行，分支 CI 与发布工作流复用的完整 CI 均为门禁。
