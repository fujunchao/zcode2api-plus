# v2.10.27-go

## 导入记账：删除有日志，导入也必须有

巡检删除有 `proxy-health … removed=N` 可查，但订阅导入只写库、不打日志，池子的收支一直对不上——
「一晚上删了 485 条」到底是在缩水还是正常代谢，日志答不了。

本版补两行：

```
[~] proxy-import source=<run-id> added=7 skipped=3 received=12 total=104
[~] proxy-import source=manual id=proxy-a1b2c3d4 total=105
```

- 只在 `added > 0` 时输出，空轮不刷屏。
- `total` 是落库后的池子条数，与 `proxy-health` 的 `removed=N` 直接对账。
- 两处都在持锁路径上，日志用 `go web.Warn` 异步输出——`web.Warn` 是同步 stdout 写，
  管道阻塞时会卡住整个 Store 锁（`store.go` 的 `logPersistFailure` 已有同样的先例）。

## 最近成功免删：不删正在用的线路

静态探针只证明「此刻连不上」，不证明「这条线没在用」。一条正在承载用户流量的线路，
探针抖一次就被删掉，代价远大于多留一天。

巡检删除前增加一道过滤：**最近 24 小时内有过上游成功交付**的线路不进删除名单。
数据源是账号的 `LastUsedAt`（`MarkSuccess` 在上游成功交付时写，async 池共用），
不需要新增状态表。

边界（这几条是刻意的）：

| 路径 | 是否受保护 |
|---|---|
| 网络巡检确认失败 → 删除 | ✅ 是 |
| 严格退役（405 归因） | ❌ 否 |
| 断流熔断 / 登录失败清理 | ❌ 否 |
| 手动删除 | ❌ 否 |

为什么不对严格退役生效：`LastUsedAt` 是**账号级**的，一条脏线只要还有账号在上面成功过，
就会拿到 24 小时免死金牌——这正好推翻 v2.10.21–23 三版做的 405 归因退役。
所以保护只放在 `purgeProxyProfilesIfCurrentLocked` 这一条巡检删除路径上。

后台代理列表新增一条保护文案「最近 24 小时有成功流量，自动保护」，
与既有 `manual` / `default_proxy` / `managed_default` / `policy_unavailable` 并列。
