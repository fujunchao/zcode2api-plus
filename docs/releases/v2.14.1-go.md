# v2.14.1-go

把默认客户端身份同步到 **ZCode 3.18.2**。逆向核验与真机探针共同确认：3.18.2 的协议面与 3.18.0 完全一致——**没有新增档案，只是版本别名**。

## ZCode 3.18.2 身份同步

- 3.18.2 桌面包（`3.18.2.10443` / 构建 `2681f4af`）的三块 system 与 Desktop Context 与 3.18.0 **逐字节相同**：block0 35 B / `7779642ea44a4696`、身份段 1,233 B / `aac4ba4cc7b555b3`、dynamic 1,595 B / `26a2daa8c8381086`、Desktop Context 1,100 B / `39a1e86c93452c01`。
- 版本→档案映射把 `3.18.2` 精确登记到既有 3180 档案（**不新增档案常量**），默认 `ZCODE_CLIENT_VERSION` 切到 `3.18.2`；Compose、`.env.example`、README 与 UA 说明同步。
- 未核验的 `3.18.1` 仍显式回落 legacy，并新增负向断言看住「不得改成前缀匹配」。

## 核验证据

- **真机探针（生产服务器，单账号 2 条请求）**：基线 `ZCode/3.18.0` + 3180 三块 → HTTP 200；候选 `ZCode/3.18.2` + 3180 三块（`probe --system-file` 逐字节注入）→ HTTP 200，且 `input_tokens=91 / cache_read_input_tokens=576`，上游把两条请求判为同一缓存前缀，与「两版文案字节等同」互证。
- **反面取证**：`-client-version 3.18.2` 不补映射时 `probe --dry-run` 回落 `3.16.x`（2 块、block0 含 `coding` 42 B、身份段 1,217 B），即「新版本头 + 旧文案体」，正是 3.17.1 事故形态——所以本次是「加别名 + 抬默认」一起做。
- **差分结论**：端点 183→183、CLI 61→61、归一化 URL 219→219、请求头名 54→54、snake_case 请求体字段 8,719→8,719，全部零增删；`zcode-builtin.json` 模型目录逐字节相同（revision 44 / 30，仍 GLM-5.3 / GLM-5.3-Flash）。

## 边界（本次未变，也未被改动）

- 模型路由、Anthropic 上游地址、四项来源头（Authorization / X-Device-Mid / X-Client-Language / X-ZCode-App-Version）、SSE 事件与 `maxAttempts=11` 重试判定。
- 套餐领取与额度重置核销契约：3.18.2 日志里的「核销确认页」是远端 coding-plan webview 的界面，核销四端点与 `marketing/touch` 均未变，自动领取/核销脚本无需改动。
- 桌面新能力（语音输入、Worktree、Design、Session 管理工具、浏览器点选/导出、分享有效期、手机推送、字体平滑、麦克风重授权）都在本地或独立业务服务，不进入网关，也不放进容器。
- 未接入中国区 `zai_cn` 账号登录（不在本次范围）。

## 升级说明

- 无需数据库迁移，接口与配置项不变。
- 回退：`ZCODE_CLIENT_VERSION=3.18.0`（或更旧的 `3.17.2`/`3.17.1`）；若部署显式设置过 `UPSTREAM_USER_AGENT`，同步改为 `ZCode/<同一版本>`。
