# v2.10.4-go

## ZCode 3.15.3 兼容修复

- 默认客户端声明由 3.15.1 对齐 3.15.3；显式 `ZCODE_CLIENT_VERSION`、`UPSTREAM_USER_AGENT` 覆盖仍保留。
- OAuth 登录后转换 API Key 时，`getCustomerInfo` 改用裸业务 token。个人 API Key 列表、创建和 copy 仍使用 Bearer；普通 JWT/API Key 模型双认证头不变。
- 转换失败仍准确报告业务错误，不继续创建/copy，不回滚已经保存的 JWT，不回显凭据。

## 重新登录后的在途结果隔离

- 同步模型、异步模型及额度查询回写前，在存储锁内核对实际出站账号、provider、认证模式和凭据。
- 旧 JWT 请求迟到的 401/403 不再把重新登录后的身份标坏；旧身份的限流、服务不可用、风控、模型耗尽和错误记录不再污染新身份。
- 旧成功不再充当新身份恢复证明：不能清除新身份的失败阶梯或覆盖新额度。额度查询还保留出口身份核对。
- 同一凭据的真实失败仍按原规则处理，不忽略认证错误、不增加重试；同凭据模型耗尽事实仍记录，人工停用等整号强状态保持。
- 人工停用/归档不被在途健康结果改写；已经完成的调用和已消费 token 仍按同账号 ID 累计，不因重新登录丢失用量。

## 验证与升级

- 回归通过实际同步/异步 HTTP 入口与额度服务，使用 channel 固定“旧请求在途 → 重新登录 → 旧响应”时序；覆盖未换凭据对照、新凭据后续成功、旧成功用量、模式变更及人工操作。
- GitHub Actions 在完整测试之外对身份隔离回归重复执行 20 次，并保留全仓竞态、静态检查、SDK、前端、跨平台和镜像构建门禁。
- 只使用合成凭据、隔离 SQLite 和环回 HTTP/TLS；没有将真实账号数据交给 CI，也没有在开发机运行自动化测试。
- 无数据库迁移、无前端产物变更。替换二进制或镜像并重启即可；已有账号状态不会因升级被批量清空。
- 不移植桌面引导/更新退出或 CLI 签名器，不调整模型目录、SDK/运行时后缀、并发、风控阶梯或代理订阅策略；本补丁不等于服务端 405 已消除。
- 镜像：`ghcr.io/fujunchao/zcode2api-plus:2.10.4-go`，提供 Linux amd64 / arm64；同时更新 `latest`。
- 二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
