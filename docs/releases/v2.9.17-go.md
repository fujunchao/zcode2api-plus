# v2.9.17-go

隔离被上游风控标记的账号（静默期硬闸门 + 恢复护栏 + 请求级判定收窄），根治
2026-10-12 晚的池卫生事故：热账号往复烧伤、污染池误判请求级、批量恢复把上游
标记未过期的账号放回轮转。不修改鉴权、错误分类链、重试预算、冷却阶梯与伪装格式。

## 风控静默期（选号硬闸门）

上游对触发风控的账号打**服务端标记**，标记期内该账号对任何请求都回 405（实测
≥14h），而本地阶梯冷却只有分钟级——冷却到期并不代表标记解除。新增持久化字段
`last_risk_control_at`（每次风控命中盖章），选号第一层直接跳过静默期（默认 24h）
内的账号；池内账号全在静默期时以 `no_available_account` 结束（池状态新增
`risk_silent` 分桶与「N 帳號風控靜默期中（上游標記未解除）」文案），不再把必然
被拒的账号喂给请求、不再让它们污染请求级判定。

- 开关：`ZCODE_RISK_SILENT_HOURS`（默认 24；0 = 关闭闸门与恢复护栏，应急回退）。
- 升级迁移：旧数据无该字段时用 `last_error_at` 回填（仅风控归类），事故当晚已
  被标记的账号部署后即受保护。
- 换凭据=换身份：编辑换凭据 / OAuth 登录（RenewJWT）同步清空该证据，保证
  「换凭据救回」不会被静默期闸门拦住 24h。

## 恢复护栏（手动 / 批量恢复）

静默期内的账号不再直接回 active，而是转入**保护冷却**（冷却截止 = 静默期终点，
期满自动重新参与调度；列表显示为「風控」冷卻并带可读说明）。响应 message 注明
「距上次风控 N 小时（静默期内）…保护冷却至 XX」，前端 toast 透传；批量摘要附
「（N 個帳號進入風控保護冷卻）」。16:31「批量恢复 51 个账号 → 二次烧伤」的路径
被结构性关闭。

## 请求级判定收窄

「≥2 个不同账号同信号 = 请求级」收窄为「≥2 个**命中时不在静默期**的账号」：
热账号的 405 只反映自身标记、与内容无关，不再计入；单干净账号命中不登记重放
封锁（内容未被证伪）。修复污染池里「连抽两个热账号」被误判成请求级、错误停止
换号并封锁同内容的扩散机制。

## 回归与发布门禁

- 新增：模型层判定边界 / 迁移回填 / Clone；store 选号跳过与放行、保护冷却终点、

- 既有 riskproxy 用例补上「静默期已过」的时间证据（冷却到期单独不再足以入池）。
- 继续执行全量测试、竞态检测、SDK/Pi、前端、交叉编译与镜像验证；测试仅使用
  隔离目录、合成凭据和本地测试服务。

## 上线验证建议

- 部署后观察：静默期内的账号在账号列表应显示「風控」冷卻而非可调度；请求打满
  时 `no_available_account` 文案应出现「風控靜默期」成因；同一内容的重试不再
  以「风控拦截」文案快速失败（单干净账号命中不再触发重放封锁）。
- 事故期被标记的账号会在静默期（≤24h）后自然回归，无需也不建议在静默期内手动
  恢复——恢复只会转入保护冷却。
- 如需回退旧行为：`ZCODE_RISK_SILENT_HOURS=0` 重启即可（恢复「冷却到期即再入池」
  的旧行为，风险自负）。
