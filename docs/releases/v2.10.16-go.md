# v2.10.16-go

## 首字节预算：不再等满 5 分钟

线上复盘（2026-10-17 17:50）发现：5.59MB 请求体经默认出口时，上游首字节要到 **283–296 秒**才出现，
另有 3 次直接 524 于 300 秒；用户侧表现为「一直转圈、没有任何输出」。

根因是超时口径漏了一段：Go 的 `ResponseHeaderTimeout` 是「**完整写完请求体之后**」才开始计时。
慢线路上 5MB 上传本身就要几百秒，计时器在那之后才启动——**上传阶段等于没有超时**。

本版给「建连 + 上传 + 收到响应头」整段加预算（默认 90 秒），收到响应头即停表：

- **只覆盖首字节之前**：流式交付继续用同一个 ctx，长回答完全不受影响。
- **超时不冷却账号**：慢的是线路，不是账号。24 个账号共享同一条慢线时，逐个冷却会瞬间清空池子；
  这里只记一次软失败并换线。
- **换号即换线**：超时线路进入本请求的回避集合，下一次选号跳过绑定在它上面的账号；
  回避把候选清空时自动回退（宁可再慢一次，也不报「无可用账号」）。
- 90 秒的依据：实测正常大包首字节 30–65 秒（5.41MB→30.5s、5.42MB→63.6s、5.58MB→42.3s），
  90 秒既不会误杀合法慢请求，也能把最坏等待从 300 秒压到 90 秒。

## 408 / 524 换线重试

这两类状态码是代理或边缘的超时，与具体账号无关。此前走「其余错误」原样透传，用户只能白等。
现在换一条线路重试一次（`attemptBudget` 独立计数，默认 1 次），预算用尽才按原样透传。

## 慢首字节只观察、不判失败

首字节超过 30 秒但最终成功的请求，只记一次 `slow` 样本（`/api/health/summary` 的 `soft` 字段可见），
**不进失败率、不参与隔离**。理由：30–90 秒出首字节的线路仍然可用，记成失败会把仅存的可用线路隔离掉。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZCODE_UPSTREAM_FIRST_BYTE_TIMEOUT` | `90` | 秒；0 = 关闭预算，回到旧行为 |
| `ZCODE_UPSTREAM_TIMEOUT_RETRIES` | `1` | 408/524 换线重试次数；0 = 关闭 |

两个开关独立，可分别回滚。

## 升级与验证

无数据迁移。`Select` 行为在无回避集合时与旧版完全一致；异步工单（`/async/v1/messages`）的选号本版未改。

回归覆盖：预算触发后的换线与「账号不冷却」、收到响应头后长流不被打断、预算为 0 时完全关闭、
524 换线一次成功与预算用尽后透传、回避集合跳过指定线路、候选全被回避时回退、`avoid` 为空时选号不变。
所有自动化验证由 GitHub Actions 执行，分支 CI 与发布工作流复用的完整 CI 均为门禁。
