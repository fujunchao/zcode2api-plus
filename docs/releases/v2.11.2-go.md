# v2.11.2-go

## 巡检的两处归因修正

本版只改巡检，不动业务请求链路、上游协议与数据库结构。两个问题都来自 2026-10-25 的服务日志复盘。

### 1）最近成功免删：24h → 6h

- **背景**：v2.10.27 引入「最近成功免删」——巡检确认线路故障后，若该线路最近 24h 内有上游成功交付
  （账号 `LastUsedAt`），跳过删除。
- **实测（7.52 小时日志）**：94 次免删覆盖 32 条线路，876/1079 次确认故障被放过；**69% 的免删依据是
  ≥3 小时前的成功**；保护期内仍交付真实成功的 9 条线路，首次被保护时成功都在 4.8 小时内；
  4 条持续死亡线路因 24h 保护反复触发「计费请求未完成」观察（占全部观察 64%）。
- **反事实**：窗口 4h 会提前删掉 6 条随后 0.05–1.0h 内又交付真实 200 的线路（高风险）；
  **6h 是零高/中风险误删的最小窗口**；12h 与 24h 在本样本完全等价（最大 `last_ok` 仅 11.9h）。
- **改动**：默认 `24 → 6`；`GET /admin/api/proxies` 顶层下发 `protection_recent_hours`，
  前端按真实值显示，不再硬编码「最近 24 小时」。保护仍只作用于巡检自动删除，
  严格退役、断流熔断、登录清理与手动删除不受影响。

### 2）模型巡检 405：不再冷却执行巡检的账号

- **背景**：screen/target 阶段的 405 只证明「目标线路被拦」，此前会立刻对**执行巡检的账号**
  `ApplyRiskControl`（写冷却、`last_error`、`last_risk_control_at`），即使最终判定
  `route_correlated`（线路责任）也不回滚。健康账号替脏线买单 5–60 分钟，reference 对照还要
  等冷却结束，每轮至少多 5 分钟。
- **改动**：只有 **reference** 阶段失败才惩罚账号；screen/target 只保留 run/proofs 与线路证据。
  真实业务 405 仍由主链路冷却 + 换线；线路证据、两轮对照与退役条件不变。
- **日志**：新增 `model-probe risk run=… target=… role=… account=… penalty=account|skipped`，
  用于灰度与复盘。
- **已知遗留（二期）**：参考线自身脏时 reference 仍可能误罚账号；等上线日志评估后再决定是否加
  「同参考线其他账号成功」的差分门控（触发条件见 `docs/plan-probe-risk-attribution-20261025.md` §8）。

## 配置

| 变量 | 默认 | 说明 |
|---|---|---|
| `ZCODE_PROXY_PROTECT_RECENT_HOURS` | `6` | 巡检「最近成功免删」窗口（小时）；0 = 关闭 |
| `ZCODE_MODEL_PROBE_RISK_PENALTY` | `reference` | 巡检 405 对账号的惩罚范围：`reference` 只罚参考线失败；`all` 回旧行为（筛查/目标/参考全罚）；`off` 巡检不写账号 |

## 升级与回滚

- 无数据库迁移；前端 `frontend/dist` 已重建并提交。
- 回滚：`ZCODE_PROXY_PROTECT_RECENT_HOURS=24`、`ZCODE_MODEL_PROBE_RISK_PENALTY=all`（重启生效）。
- 历史 `last_risk_control_at` 不回填；冷却按其时间自然结束。

## 回归覆盖

- 免删窗口：显式窗口边界（5h 保留 / 7h 删除）、窗口 0 关闭、严格退役/断流不受影响、
  `GET /proxies` 下发真实窗口、前端真实/缺省文案。
- 巡检 405：目标阶段账号零改动但线路仍退役、参考失败只冷却该账号、`all`/`off` 开关、
  既有 route_correlated 用例追加账号零风控守门。
- CI：完整 `ci.yml`（`go test ./...`、`-race`、分组重复回归、frontend lint/test/dist 一致性、
  SDK/NewAPI 兼容、Windows 代理日志、交叉编译、Docker 构建）；发布工作流复用同一套 CI。
