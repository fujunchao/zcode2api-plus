# v2.10.22-go

## 405 脏线清理：隔离之后，把它真正验出来、删出去

v2.10.21 只解决了「别再被脏线打断」——连续 2 次 405 的线路退出选号，但它**仍然留在池子里**。

原因是结构性的：网络探针是**匿名 GET**，脏 IP 对 GET 是通的。2026-10-17 的日志里，
21 条「405 有、成功零」的线路全部通过连通性检查，永远不会被判 `confirmed_failure`；
而严格代理证据要求「同线同内容」逐字节匹配，客户端重试会让 body 漂移 32–96 字节，
本次窗口 `strict-proxy` 一条删除决策都没产生。

要判断「这条线能不能跑模型」，只能用**带凭据的模型请求**去问。本版把隔离接到已有的
定向模型巡检上，让 405 线路走完整条链路：隔离 → 巡检 → 结论 → 删除。

## 行为变化

### 1. 隔离触发定向巡检

- `RecordLine405` 判定隔离后，入队一次 `QueueModelProbe(target=<线路>, source="line405")`。
- **限频**：同线路默认 30 分钟一次；隔离续期（30→60→120→240 分钟）不会重复入队。
- **预算**：全局每小时默认 12 次。免费池里被隔离的线可能一下几十条，不设预算等于
  拿账号额度替脏线买单。超限只记 `line405-probe skipped reason=budget`，**隔离照常生效**。
- 巡检关闭或目标不在覆盖范围时静默跳过，不把隔离回滚。

### 2. 结论回写线路画像

`ApplyLine405ProbeVerdict` 只做两件事：

| 巡检结论 | 动作 |
|---|---|
| `healthy_recent` / `mixed` / `account_correlated` | **提前解封**，连续计数与档位清零 |
| `route_correlated` / `suspect` | 保持隔离，`probe_state=failed` |
| 其他（`inconclusive` 等） | 不动状态 |

**删除仍然只由既有退休链完成**（`retireModelProbeLocked` → `startStrictRetirementLocked`），
本机制不产生任何删除证据，也就绕不过「两轮确认 + target/reference 差分对照 + 保护名单 +
配置代次」四道闸。回写发生在退休之前——线路一旦被删，画像就找不到对应配置了。

### 3. 删除日志可复盘

`stage=confirmed` 行追加 `removed_ids=`：

```
round=… stage=confirmed whole=1 checked=2 candidates=1 removed=1 mode=auto_retire removed_ids=proxy-530c1b47
```

最多 20 个 id，超出折成 `+N`，单字段上限 512 字节；`removed=0` 与 `stage=probe` 不输出。
此前只有 `removed=14` 这种计数，事后既无法核对删了哪条线，也无法复盘误删。

### 4. 观测

- 隔离与巡检：`line405-probe queued id=… source=line405 budget=N/M`、
  `line405-probe verdict=healthy|failed id=…`、
  `line405-probe skipped id=… reason=disabled|cooldown|budget|unavailable`。
- `GET /admin/api/health/summary` 的 `line405[]` 新增 `probe_state`（`queued` / `healthy` /
  `failed`，未巡检时省略）与 `probe_at`。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZCODE_LINE405_PROBE_COOLDOWN_MINUTES` | 30 | 同线路定向巡检最小间隔 |
| `ZCODE_LINE405_PROBE_PER_HOUR` | 12 | 全局每小时定向巡检上限；0 = 只隔离、不巡检 |

## 兼容性

- 无数据迁移；`accounts.data` 键集不变。
- `line_405_state` 新增两个可选字段（`probe_state` / `probe_at`），旧版本读到会忽略。
- 巡检默认关闭时（未启用模型巡检）行为与 v2.10.21 完全一致：只有隔离，没有巡检。

## 回归覆盖

隔离触发一次入队、30 分钟内二次隔离不重复入队、巡检关闭时隔离仍生效且不入队、
超预算只跳过巡检、健康结论提前解封、失败结论保留隔离、未知结论与不存在的 profile 幂等、
`removed_ids` 折叠与长度上限。

所有自动化验证由 GitHub Actions 执行，分支 CI 与发布工作流复用的完整 CI 均为门禁。
