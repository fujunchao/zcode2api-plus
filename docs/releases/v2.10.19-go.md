# v2.10.19-go

## 异步池补齐「首字节预算 + 换线」，诊断行增加会话引用

v2.10.16/17 的预算与换线只落在同步路径（`/v1/messages`、`/v1/responses`、OpenAI 兼容），
异步票（`/async/v1/messages`）仍要白等到 300 秒墙钟才失败——而长任务恰恰最吃慢线。

本版把两条路径拉齐：

- **首字节预算**：与同步同一实现（`gateway.FirstByteWatchdog`），覆盖建连 + 上传 + 收到响应头，
  收到响应头即停表。超时**不冷却账号**，只记软失败并换线。
- **请求级线路回避**：超时线路进入本票的 `avoid` 集合，下一次选号跳过绑在该线路上的账号；
  候选被清空时自动回退不过滤，绝不把「换线」变成「无可用账号」。
- **408/524 有限换线**：此前直接透传终止本票；现在按票据计一次预算（复用
  `ZCODE_UPSTREAM_TIMEOUT_RETRIES`，默认 1），用尽才把上游原文投递给客户端。
- **强制直连分支**：`async_force_direct` 走新增的 `SelectForDirectAvoiding`，行为与普通分支一致。

## 诊断行新增 `session=`

同步与异步的诊断行尾部追加 `session=<12 位十六进制>`：会话 id 的**稳定哈希**前缀，
不是原值，也不是按时间轮换的 HMAC（那样同一会话跨小时会裂成多个组）。

用途只有一个：按会话分组，比较「同一会话的连续请求：账号不变 vs 换了账号」两组的
`cache_r/(in+cache_r)`，为「会话粘性是否值得做」提供数据。**本版不改变选号行为**。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ZCODE_UPSTREAM_FIRST_BYTE_TIMEOUT` | `90` | 异步与同步共用；0 = 关闭 |
| `ZCODE_UPSTREAM_TIMEOUT_RETRIES` | `1` | 408/524 换线次数；同步按请求计、异步按票据计 |

## 兼容性

- 无数据迁移、无接口变更、无前端改动。
- 异步票的总墙钟（`ZCODE_ASYNC_TICKET_TIMEOUT`，默认 300 秒）不变；本版只是让慢线更早让位。
- 408/524 的行为从「立即透传」变为「换线一次后透传」；若需旧行为，把
  `ZCODE_UPSTREAM_TIMEOUT_RETRIES=0`。

## 回归覆盖

异步首字节超时换线且不冷却账号、票据级 408 预算只允许重试一次并透传最后一次错误体、
同步与异步共用同一看门狗实现、诊断行 `session=` 稳定且不泄漏原值。

所有自动化验证由 GitHub Actions 执行，分支 CI 与发布工作流复用的完整 CI 均为门禁。
