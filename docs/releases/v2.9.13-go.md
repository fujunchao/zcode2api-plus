# v2.9.13-go

修复本项目的 metadata 共享写入与流式输入/cache 用量遗漏。
不修改用户已经调整的 New API 重试策略，不扩大网关的换号、重试或风控保护阈值。

## metadata 按尝试隔离

- 注入账号身份前复制已有 metadata 容器，避免入口、先前副本及并行副本被后续身份覆盖。
- 同账号重试、跨账号切换不再因共享写入使内容视图/bodyhash 漂移。
- 保留其它 metadata 扩展字段；不深拷贝整段长历史。
- 保持 user_id 的 JSON 字符串形态、字段顺序、account_uuid 空值，以及设备/会话身份规则。
- 不修改内容指纹算法或重放窗口，已有上下文和本地工具保持原行为。

## 补齐迟到的输入与缓存用量

- 网关现在从 message_start 和后续 message_delta 累积输入、输出、缓存读取与缓存创建用量。
- 累计值取最大，不重复相加；后续零、缺失或无效占位不会抹掉收集器已知值。
- JSON 缺少 type、由合法 SSE event 头声明类型时，也可收集对应的用量字段。
- Chat Completions 与 Responses 不再只保存最后一个 delta，保留早先补报的输入/cache 和较大累计输出。
- 四种入口的账号统计、诊断及兼容响应均有回归覆盖；OpenAI 兼容端仍按原契约将缓存计入总输入。
- 原生 SSE 不重写、不追加估算用量；保留流完整性、最终 usage、取消与中断的不同判据。

这些修复针对可用合成请求重现的代码缺陷，不将其认定为供应商 3012 的确切触发原因，
也不承诺因此消除上游风控。没有完整生产 SSE 的其它用量口径差异仍需后续观测。

## 回归与发布门禁

新增已有 metadata 的真实 HTTP 同账号/跨账号重试、并行副本隔离、四协议迟到用量，
以及中断前后最终用量的回归。定向用例在 CI 重复 20 次，并继续执行全量测试、竞态检测、
SDK/Pi、前端、交叉编译和镜像验证。测试仅使用隔离目录、合成凭据和本地测试服务。

标签发布继续先复用完整 CI，再上传二进制和推送镜像；不绕过发布门禁。

## 升级

- 镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.13-go`，以及滚动标签 `latest`。
- 平台：linux/amd64、linux/arm64；二进制仍提供 Linux/macOS 双架构和 Windows amd64。
- 无数据库迁移、无新增必填环境变量；替换镜像/程序并重启即可。
- 仅改善升级后的新请求统计，**不会回填或改写历史用量**。

已有 New API 响应 ID 关联与诊断字段继续保留，见
[请求诊断说明](https://github.com/fujunchao/zcode2api-plus/blob/v2.9.13-go/docs/request-diagnostics.md)。
