# v2.10.1-go

## 恢复默认阶梯冷却

- `ZCODE_RISK_SILENT_HOURS` 默认由 24 改为 0：不再额外叠加 24 小时静默窗口。
- 保持 5 / 15 / 60 分钟阶梯，到期重新参与选号，超档失效，成功清连续计数；仍保留风控观测历史。
- 代理配置、换线与历史回避、停止换号阈值、重放保护保持；不把本地观察表述为供应商封禁期限或唯一触发原因。
- 显式配置的额外隔离仍兼容。**如果部署仍设置 `ZCODE_RISK_SILENT_HOURS=24`，请改为 `0` 或移除该覆盖。**
- 前端恢复提示移除“默认 24 小时”，并同步内嵌产物。

## 修复 SSE 成帧与用量一致性

- 用量统计和异步转发按完整 SSE 事件解析，多行 `data:`、冒号后无空格、LF/CRLF、event-only 类型及 EOF 无尾空行均可正确处理。
- 原生 `/v1/messages` 仍字节级透传，不重排或改写上游响应。
- 异步不会再静默丢弃合法多行事件；payload 缺少有效 type 时保留 event 字段的语义，原 ticket/chunk/done 与 Unicode 转义格式不变。
- 输入、输出和缓存用量按累计最大值计数，不重复累加；中断只保留已确认的合法终值，不将半截或畸形事件当成功。
- 上游 error 事件仍与线路断流区分；已输出内容的请求不因错误换号重放。

## 修复 API Key 兑换诊断

- 业务登录、机构查询、Key 列表、创建和复制均先检查业务 code，再读取 data；HTTP 200 不再被等同业务成功。
- 数字/字符串 401 返回明确的业务认证失效提示，不再误报“找不到可用的机构”；其他业务错误与真正缺机构、无效 JSON、HTTP 失败仍区分。
- 业务失败立即停止后续步骤；新业务错误不回显上游消息中的令牌或不可信业务码，也不被误归类为代理不可达。
- 主 OAuth code→JWT 流、已保存 JWT 和登录状态不变，不增加全局登出。

## 升级与验证

- 无数据库迁移，不自动清除已记录的 cooling_until、失效、停用、归档或额度状态。
- 关闭额外闸门不会清除独立的冷却记录；需要人工恢复的账号仍通过现有管理入口处理。
- 保留 v2.10.0-go 的账号权益头保护与 ZCode 3.15.1 客户端声明，没有接入 HighSpeed。
- 本地仅为前端产物生成执行构建；全部自动化测试、重复回归、竞态、静态检查和发布构建由 GitHub Actions 执行。
- 所有回归只用合成凭据、隔离目录及本地 HTTP/TLS 服务，不读取运行账号数据。
