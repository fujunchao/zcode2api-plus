# v2.10.7-go

## 修复导入新号未初始化

- 上一版本把文件导入统一当作备份恢复，缺少初始化创建选项与工作者唤醒；本版本将真正新导入的 JWT 接入现有取额轮询和到账固定绑定流程。
- 导入账号、停用模型设置与初始化任务同事务保存，避免账号提前被调度，或后续元数据更新中断任务。
- 重复导入不创建/重置任务，不覆盖已有初始化执行权；API Key 和策略关闭时保留原导入行为。
- 导入提示区分新建、已存在和进入初始化的数量。CLI 导入登记可恢复任务，由后续 `serve` 执行，不隐式联网领取。

## 手动处理已经导入的账号

在账号页勾选记录，点击 **补入初始化 → 确认补入**。

- 只处理明确选择并确认接管代理路由的账号，不自动扫描旧数据。
- 服务端重新检查启用、归档、健康、使用、领取、配额及等待状态；不把已使用、已领取或有额度的老账号当成漏处理新号。
- 已有初始化记录幂等返回，不清零暂停、预算或到账事实；补入成功后仍先核验真实额度，不承诺领取资格。
- 合格项单事务提交账号、任务与代理意图，失败整体回滚；撤销接管前旧请求的回写代次，避免迟到结果覆盖新任务。

## 验证与升级

- 增加导入完整 A→B→固定 C 流程、创建时隔离、重复导入、CLI、手动确认/鉴权、历史资格、SQL 回滚及重启回归；全部自动化在 GitHub Actions 使用隔离目录、合成凭据和本地测试服务执行。
- 发布仍复用完整 CI，不跳过竞态检测、前端产物一致性、SDK、跨平台、Docker 或其他发布门禁。
- 无新增数据库表，沿用 `v2.10.6-go` 的任务表；导出 version 1 不变。仅作备份恢复且不想自动初始化时，导入前关闭新号初始化策略。
- 旧版本已导入的账号不会被升级或重复导入自动补跑，请使用上述手动入口。
