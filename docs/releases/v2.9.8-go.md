# v2.9.8-go

修复回调登录被故障代理锁住、必须退出重新新增的问题。

- 输入回调后，若命名代理连接 OAuth 端点失败、握手失败、超时或传输中断，删除故障线路并继续使用同一份回调自动换线。
- 仍按“空闲优先，否则绑定最少、同负载按列表顺序”选择代理；停用线路和本会话已失败 URL 的别名不参与，故障代理原有绑定账号一并原子改派。
- 代理耗尽时按既有规则尝试直连一次；仍不可达则保留会话，补充代理后可直接重新提交原回调，不必退出对话框。
- 登录只在原会话有效期内重试，支持请求/服务取消。普通 OAuth 业务错误、授权码失效、回调不匹配及无效响应不触发代理删除。
- 同一会话的完成请求互斥；成功回调重复提交返回同一账号，不重复兑换授权码、刷新额度或领取套餐。
- 成功收到的凭据暂存到账号保存成功；保存失败时重试继续使用已兑换结果，并补完尚未完成的新账号初始化。成功后清除临时凭据，只保留账号 ID 与回调摘要至原会话过期。
- 补齐 CONNECT 非 200 响应的结构化故障标记，并保护已经被更新的代理，避免迟到失败误删新配置。
- 新增本地 TLS/CONNECT、并发、取消、事务回滚、会话续用和授权码复用保护测试，远端 CI 重复验证关键链路 20 次。

授权码已被上游消费但成功响应完全丢失时，若后续明确返回授权码失效，仍需重新授权；不会对健康代理循环删除。

不修改数据库结构。更新程序或镜像并重启服务后生效，已有账号的重登指派规则及入池领取/额度检测规则保持不变。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.8-go` 与 `latest`。
