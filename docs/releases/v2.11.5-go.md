# v2.11.5-go

## 回退默认客户端声明到 3.16.3 + 版本化 system 文案 + probe 探针

本版修复 v2.11.4-go 的事故：把默认伪装版本升到 3.17.1 后，上游对每个模型请求返回
`405 / 3012 unusual activity`，网关按阶梯冷却账号，最终表现为池级 503；回退 3.16.3 后恢复。

### 根因（已定位）

3.17.1 **改了官方 system 提示词的首段**：

| | 3.15.x–3.16.x | 3.17.1 |
|---|---|---|
| block 0（CLI Prefix） | `You are ZCode, an interactive coding agent` | `You are ZCode, an interactive agent` |
| 身份段首行 | `You are an interactive ZCode agent that helps users with software engineering tasks.` | `You are an interactive agent that helps users according to their "Output Style", …` |
| Harness 项目符号 | `- …`（无前导空格） | ` - …`（有前导空格） |

而上游**从 system 第 0 字节校验到身份段末尾**，并按 `app_version` 期望对应文案
（该机制此前已用受控实验证明，见 `docs/analysis-riskcontrol-dsh-405-root-cause-20261012.md`）。
只改版本号、不换文案 = 版本与文案各说各话 = 3012。

完整取证与时间线见 [根因分析](../analysis-zcode-3.17.1-405-incident-20261101.md)。

### 本版改动

1. **默认伪装版本回退 `3.16.3`**（`internal/config/config.go`）；`UserAgent` /
   `ModelUserAgent()` / `X-ZCode-App-Version` / `app_version` 仍全部由该常量派生。
2. **版本化 system 文案**：新增 `internal/upstream/zcode_system_3171.json`（block0 35 字符、
   身份段 1355 字符 + 桌面段），按 `ZCODE_CLIENT_VERSION` 选择档案；缓存按档案键控，
   切换版本必须重解析，杜绝「新版本号 + 旧文案」。
3. **新增 `zcode2api probe` 子命令**：只读账号库、单账号、单请求、打完即退，
   输出 HTTP 状态 / 业务码 / 响应前 4KB / system 指纹（block0 原文 + sha16 + 身份段 sha16），
   不写库、不启调度、不含凭证与会话内容。
4. **回归测试**：`TestZcodeSystemProfileFollowsClientVersion`（两个版本的 block0 必须精确匹配）、
   `TestZcodeSystemProfilesDiffer`、`TestZcodeSystemProfileSwitchInvalidatesCache`、
   `TestZcodeSystemProfileFor`；默认版本期望值同步回 3.16.3。

### 兼容性与回滚

- 接口、请求形态、数据库结构、配置项**均未变**；用户无需操作。
- 回滚：本版默认即 3.16.3，无需额外动作；若要显式固定，设 `ZCODE_CLIENT_VERSION=3.16.3`
  （Compose 需在 `environment:` 显式引用）。
- 事故版本 v2.11.4-go 建议尽快替换：它的默认值即 3.17.1，其它部署同样会踩 405。

### 如何验证 3.17.1（不惊动生产）

```bash
# 1) 先看指纹与候选账号（不发请求、不写库）
docker compose run --rm zcode2api probe --list
docker compose run --rm -e ZCODE_CLIENT_VERSION=3.17.1 zcode2api probe --dry-run

# 2) 用池里最久未使用的一个账号发一条探针请求
docker compose run --rm -e ZCODE_CLIENT_VERSION=3.17.1 zcode2api probe
```

判定：`http_status=200` 且 `business_code` 为空 ⇒ 文案方案成立，可考虑后续把默认切到 3.17.1；
`http_status=405 / business_code=3012` ⇒ 还需要真实 3.17.1 客户端的 model-io 抓包做逐字节还原
（桌面上下文段由服务端下发，静态无法完全还原）。

### 已知限制

- 3.17.1 的 `x-zcode-session-features` 模型请求头**未跟进**（继续执行「未知 `x-zcode*` 不透传」）。
- 3.17.1 的桌面上下文段（`# ZCode Desktop Context`，1100 字符）沿用 3.16.x 抓包；动态部分需真实抓包确认。
