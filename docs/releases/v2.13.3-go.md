# v2.13.3-go

修复 v2.13.0～v2.13.2 发布审核发现的五处缺陷：巡检保存阻塞、早期错误帧丢失、未知线路被慢线压制、巡检样本重复计数，以及 OpenAI 兼容接口的工具调用收尾缺口。

- 网络巡检结果与上行带宽状态使用同一数据库事务保存，避免单连接数据库在事务内再次申请连接而等待 5 秒。写入失败整体回滚，不发布未落盘的带宽样本。
- 预缓冲期间收到上游 SSE 错误事件时，在返回前完整发送原始错误帧；交付结束统一清理定时器，防止请求结束后继续写响应。
- 带宽选路采用“已知快线 → 已知中速线 → 未知线路 → 已知慢线”的顺序，未知线路仍可获得采样机会；同组保留原有额度优先和轮询逻辑。
- 巡检样本按轮次及首次探测、复核阶段去重；复核速率独立参与平滑计算，重复保存和重启不会把同一次测量算成多个样本。
- Chat Completions 和 Responses 接口在 graceful（优雅收尾）模式下检查所有工具块；任何工具调用未闭合都降级为可重试错误，避免把半截参数当作成功结果。

回归用例覆盖真实 SQLite 事务与失败回滚、重启后的采样去重、慢线与未知线路竞争、预缓冲定时器生命周期，以及两个公开兼容接口的交错工具调用。自动化验证由 GitHub Actions 执行，包括完整测试、竞态检测和上述用例的重复运行。

默认仍为 retryable（可重试错误）策略，无需新增配置或手工数据库迁移。新增的巡检去重字段保存在内部带宽状态中，旧版本可忽略这些字段。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.13.3-go` 与 `latest`。
