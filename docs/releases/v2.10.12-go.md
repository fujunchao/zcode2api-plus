# v2.10.12-go

## 全节点主动巡检与账号自动择优

- 周期巡检不再要求选择目标、参考或探测账号。默认全部启用且未退役节点自动参与，新增节点自动纳入；高级设置仅保留可选的模型目标排除。
- 修复分批间隔被完整轮转周期重复放大的问题：默认预算下每30分钟推进一批，而不是再等整个轮转周期。实际目标请求完成后才推进复测时间。
- 账号改为派发时选择，过滤已耗尽巡检预算、正在处理业务或其他探测的账号；缺少资源时保留待检，预算／账号恢复后自动继续。无样本账号的最近选择记录不再立即被清掉。
- 业务与主动探测结果分开统计，纳入完整失败与中断；取消单列，线路／平台异常不一律归因账号。评分结合样本量和时间新鲜度，旧凭据或其他模型端点的结果不影响当前排名。
- 近期业务成功单独作为旁证，不再替代自动巡检的主动请求。摘要展示主动覆盖、等待账号／预算及网络异常；未检测、已过期或资源不可用不再显示为正常。

## 升级行为

策略版本升级为3：旧手工巡检配置转换为自动覆盖、自动选号和自动参考，旧探测专用角色解除，账号返回普通业务池。保留原有开关、预算及已用请求计数、观察／自动处置模式、显式排除、出口组声明、直连许可与冷却。**此前关闭的模型巡检不会被自动开启，升级不会额外开启自动退役或直连。**

自动选号仍不借用初始化／固定出口托管账号，不改写普通账号的持久代理绑定。探测实际消耗额度，405冷却仍生效。全量参与不等于每个节点每30分钟都完成：日预算有限时分批轮转，面板给出参考周期及尚未完成原因。

## 保持不变

网络二次复核、两轮可比模型对照、十分钟证据、独立出口、反证、凭据／线路／策略代次和原子退役门禁均保留。新的成功率统计不扩大允许删除节点的证据类型。

全部自动化验收由 GitHub Actions 完成；发布前分支完整 CI 和发布工作流复用的完整 CI 均为门禁，不使用生产账号和运行数据。

操作说明见 [统一巡检指南](../guide-unified-proxy-health.md)，实施及失败回归记录见 [实施方案](../plan-node-health-automatic-20261016.md)。
