# v2.9.10-go

改善现有 JWT / Start Plan 请求的一致性与逐次出站诊断。不新增或扩展官方 API Key 套餐适配，既有密钥转发分支和异步池仅使用 JWT 的边界保持不变。

## 请求一致性

- 默认模型 UA 的 Node 主版本声明从 `22` 更新为 `24`，对应已核实的 ZCode 3.14.5 随包运行时基线。官方客户端版本声明仍为 `3.14.5`，SDK 声明仍为 `4.0.27`；这只是兼容档案维护，不给 Go 网关增加 Node 运行依赖。
- `client/configs` 查询将复合平台转换为查询表示，例如 `win32-x64` 转为 `windows-x86_64`。既有 `ZCODE_CLIENT_PLATFORM` 覆盖入口继续生效，只转换已知平台/架构别名，不把自定义名称替换成默认值；余额与领取查询不改动。
- JWT 请求只前置一份与网关标准块完整相同的 system 内容。不会按关键词删除调用者提示词，不会合并任意重复用户段落；不同缓存策略、附加字段及扩展文本仍保留。相同标准块经 JSON 往返再次提交也不重复注入。
- 异步瞬时限流/平台过载的原地重试，每次实际 HTTP 构造都生成新 `X-Request-Id`。不修改重试模板中的其余字段，会话/追踪/轮次标识和正文保持不变；退避、换号、流开始后不透明重放的规则均不改变。

## 脱敏诊断

同步和异步共用的 `[attempt]` 日志追加以下字段，原有字段顺序保留：

| 字段 | 含义 |
| --- | --- |
| `account_mode` | 所选账号模式，与既有表示出口方式的 `mode` 区分 |
| `target_origin` | 请求目标的协议、主机和可选端口，不包含用户信息、路径、查询参数或片段 |
| `upstream_request_id` | 实际 HTTP 请求中的 UUID；异常格式记为未知，不输出原值 |
| `session_ref / trace_ref / query_ref` | 相应归因值的 12 位十六进制短哈希，只用于诊断关联，不用于认证或会话调度 |

新摘要不读取请求正文，也不输出认证头、原始设备信息或调用者会话标识。开始与响应头/连接错误事件使用同一份摘要；HTTP 200 仍不等同于完整成功交付。

## 验证与升级

新增回归覆盖默认运行时声明、配置查询平台与覆盖值、标准提示词去重和用户内容保留、真实 HTTP 边界的混合重试归因，以及两个入口的诊断脱敏。测试仅使用合成凭据、隔离存储和模拟上游，自动化验证统一由 GitHub Actions Ubuntu 环境执行；发布继续经过完整 CI 门禁。

没有复制官方私人会话上下文或工具表，不新增自动标题/模型调用，不修改输出上限、签名策略、账号调度或并发限额。

无需数据库迁移。替换程序或镜像并重启即可；若已显式设置 `ZCODE_CLIENT_NODE_MAJOR`，请检查覆盖值，升级不会自动改写环境配置。独立 `zcode-switch` 仓库不包含在本次发布中。

二进制：Linux amd64/arm64、macOS amd64/arm64、Windows amd64。
镜像：`ghcr.io/fujunchao/zcode2api-plus:2.9.10-go` 与 `latest`。
