# v2.3.1-go

一次线上事故（2026-09-20 晚）引出的三项加固。当晚上游连环返回 HTTP 503，网关按旧逻辑
对每个命中账号**固定冷却 300s**，个位数账号池在约 35 秒内被整池清空，客户端收到 116 次
`503 no_available_account`；而该错误的文案是静态的「帳號未提供此模型或額度已用完」，把一次
上游抖动误读成了绑定/额度问题。完整复盘见
`docs/analysis-503-no-available-account-20260920.md`。

## 一、上游 503：固定 300s 冷却 → 递进阶梯

503 是**上游健康信号**而非账号问题，换号救不了「上游真的挂了」。原先一刀切 300s 的问题
在于：上游只要抖动几十秒，整池账号就会被依次冷却清空——事故里 68 次 503 就是这么来的。

现在按账号**连续**收到 503 的次数递进冷却：

- 默认阶梯 `30,60,120`（秒），连续次数超过档位数后封顶于 `ZCODE_COOLING_SECONDS`（默认
  300s）——最重也只与连接失败持平；
- **不升级为 invalid**（与风控阶梯的关键差异：503 不是账号的错，不判死刑）；
- 任意一次成功调用后计数归零，下次抖动从最低档重新起算；
- 阶梯可在后台「系統設定 → 上游 503 冷卻」调整（键 `upstream_503_cooling_steps`，非法值
  400 拒收），环境变量 `ZCODE_UPSTREAM_503_COOLING_STEPS` 仅作默认值。

效果：事故场景下首次 503 只冷却 30s，池子不会被清空；若上游真的持续不可用，账号也会在
数分钟内逐级退到 300s，不会持续撞墙。

同步补齐的日志缺口：503 分支此前只记状态码、不记 body，1305/风控这类「关键信息在 body
里」的失败在日志里不可见。现在 `last_error` 与日志均带 200 字符的 body 预览。

## 二、503 错误体携带池状态分解

`no_available_account` 不再是静态文案。错误体现在如实回答「此刻池子里每个账号为什么
不可选」，文本与结构化字段并存（OpenAI 兼容层原样透传）：

```json
{
  "error": {
    "message": "模型 glm-5.3-flash 目前無可用帳號（4 帳號冷卻中（3 上游503、1 風控），最早 23:36:48 恢復；1 帳號此模型額度已用完），請在後台檢查帳號狀態",
    "type": "no_available_account",
    "details": {
      "total_accounts": 6, "active": 0, "cooling": 4,
      "cooling_earliest": 1758380208,
      "cooling_by_kind": {"upstream_unavailable": 3, "risk_control": 1},
      "model_unavailable": {"exhausted": 1}
    }
  }
}
```

- `message` 保留原句式前缀并内联繁体分解，含**最早恢复时间**——中转层可据此决定退避
  而非立刻重试轰击；
- `error.details` 为蛇形键的结构化字段，供程序化判读；
- 分解只含**计数与成因，不含账号名**——错误体会下发到 API 客户端（可能经中转层对外），
  账号名常为邮箱，不该外泄；
- async 路径的 `no_account` 事件同样携带（与 sync 同一 `PoolStats` 数据源，两路不会各说
  各话）；`store.PoolStats` 聚合与 `Select` 第一层同口径。

## 三、后台可见性：已耗尽模型的额度行标注

额度行对 `exhausted_models` 命中的模型显示「每日已用完」小字标注（悬停可见完整说明），
区分「每日额度用完、额度刷新后自动恢复」与「就是没了」。事故当晚 22:44 起 GLM-5.3 在某
账号上真实日限耗尽（业务码 1005），这一状态此前只能从日志反推。

附带钉死一条既有语义的回归测试：**单模型额度耗尽只标记该模型，账号保持 active、其他模型
选号不受影响**（`TestModelExhaustionDoesNotAffectOtherModels`）——模型级隔离本就是现状，
避免后续被误改。

## 升级建议

直接替换二进制即可；无数据迁移、无配置不兼容。若你此前调大过 `ZCODE_COOLING_SECONDS`
以缓解 503 风暴，升级后可改回默认——503 已有自己的秒级阶梯，`CoolingSeconds` 回归只兜
底「连接失败等硬故障」与 503 阶梯封顶。
