# v2.0.4-go

修复 v2.0.3-go 在网关内错误拒绝 GLM-5.3-Flash / GLM-5.3 的 `max` 推理档位。

## 修复内容

- 官方原生档位是 `low / high / max`，默认且推荐 `max`；两种模型均为强制思考。
- 按官方 Coding Plan 兼容规则归一化：`none/minimal/low → low`、`medium/high → high`、`xhigh/max → max`。
- Chat Completions 的 `reasoning_effort` 和 Responses 的 `reasoning.effort` 统一转为内部 Anthropic 请求的 `output_config.effort`。
- 不再用自定义固定 `budget_tokens` 代替模型原生 effort，也不再要求输出上限至少 2048；调用方的输出总上限保持不变。
- Pi 的 ZAI 开关式请求保留原生 effort；配置示例增加 Flash 模型并开放 `max`。
- Python SDK 和 Pi 适配器回归覆盖 high/max、两种模型及两种请求格式，检查真实上行字段。

## 使用说明

```json
{
  "model": "glm-5.3-flash",
  "messages": [{"role": "user", "content": "你好"}],
  "reasoning_effort": "max",
  "max_tokens": 8192
}
```

GLM-5.3 系列不能关闭思考，`thinking.type=disabled` 会明确返回 400；需要更低开销时选择 `low`。
兼容别名 `none` 在 Coding Plan 中映射到 `low`，并不表示关闭。Pi 示例隐藏 off，直接提供 low/high/max。
显式 Anthropic `thinking.budget_tokens` 仍作为独立字段校验，不覆盖同时请求的原生 effort。
