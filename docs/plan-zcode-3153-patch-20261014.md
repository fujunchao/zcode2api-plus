# ZCode 3.15.3 兼容修复与补丁发布计划

日期：2026-10-14。基线：`4551b264316ff996f127e794950925a07c0d31c6`。
目标发布：`v2.10.4-go`；工作分支：`codex/zcode-3153-patch`。

## 范围

1. OAuth 转换：只有 Z.ai `getCustomerInfo` 使用裸业务 token，个人 API Key 列表/创建/copy 保持 Bearer；普通模型双头保持。
2. 请求结果回写：使用出站凭据快照，在存储锁内核对账号 ID、provider、模式与实际凭据；旧身份结果不得污染新身份的状态、错误、额度与连续失败计数。
3. 已完成的请求用量仍按原账号 ID 累计，不因同账号换凭据丢失已消费用量；管理员停用/归档不被上游结果解除。
4. 对齐默认客户端声明 `3.15.3`，保持显式环境覆盖；应用补丁版本改为 `2.10.4-go`。

不引入官方 CLI 签名器、桌面退出/引导逻辑；不调整并发、重试预算、风控阶梯、代理订阅规则或数据库格式。

## 已确认的回归边界

- `ExchangeAPIKey` 经隔离 TLS 服务：逐端点检查业务 token 的认证格式，保留失败终止和无凭据泄漏断言。
- 真实 `POST /v1/messages` 与 `POST /async/v1/messages`：固定旧请求在途，重新登录相同身份后释放旧响应，检查公开账号快照。
- `FetchQuotaFresh` 经隔离 HTTP 服务：旧认证失败及旧成功余额均不得覆盖新身份。
- 对照：凭据未变化时 401/403 仍应失效；新凭据请求可继续成功；已交付用量不丢失；管理员操作保持。

全部使用合成 token、临时目录和环回服务；不读取或上传账号运行数据。

## 执行与门禁

1. 测试先行推送，检查对应 GitHub Actions 失败日志，确认命中具体缺陷。
2. 最小修复，格式化和差异检查；推送后执行完整 CI，并增加身份回写回归的重复运行。
3. 更新版本、说明及默认声明断言，检查未跟踪分析资料未混入提交。
4. 工作分支完整 CI 通过后合入默认分支；再次等待当前 SHA 对应的完整 CI。
5. 标签 `v2.10.4-go` 触发 release；其复用的完整 CI 必须通过后才允许发布任务运行。
6. 核对五个平台二进制、Release 正文、版本镜像和 latest 的多架构 manifest 与提交 SHA。

所有自动化测试、Go 构建/静态检查/竞态检测都在 GitHub Actions 执行。本机仅阅读、修改、格式化和差异检查。不修改或绕过发布门禁。
