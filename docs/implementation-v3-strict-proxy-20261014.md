# v3 实施说明与验收边界

日期：2026-10-14（Asia/Shanghai）。设计基线为 `3af1971`，实施分支为 `codex/v3-strict-proxy`。

本文区分仓库实现、固定版本消费端兼容与生产部署。代码具备回归并不等于已验证上线；验收只认相应提交的完整 GitHub Actions，发布另外复用同一套 CI。未操作生产服务器或真实账号，不读取运行 `data/`。

## 1. 原会话交接状态

原会话完成了设计与首批提交，但在模型请求派发接线、严格事务、归因和回归实现中中断。远端 `3b80f38` 的测试存在真实 HTTP 对照未闭合、归因占位、错误正文被新增字段改写及代理别名回退等失败，不是可发布状态。`4b043ef` 接入第一轮实现后，构建、前端、SDK、交叉编译通过，但完整测试仍失败，因此没有据此发布。

本轮继续按失败日志修复，同时用独立审读补充错误体截断、重定向伪成功、缺失消息 ID、证据容量、线路/凭据 A→B→A 及直连快照等边界；不删除断言换取绿灯。

## 2. 严格代理规则与执行

规则版本 `proxy-3012-v3.2`，观察窗口十分钟。只有真实模型端点的 HTTP 405 且业务码 3012 进入失败证据。每次 HTTP 请求有独立 request ID；一个入口的重试不算多个独立入口。内容采用独立 SHA-256 语义摘要，不改变原有重放键。

- **线路对照**：同一凭据版本、设备、session、模型、内容和协议档案，在目标路由至少两个独立入口失败，在替代路由完整成功。
- **共享异常**：至少三个凭据版本、三个入口、两种内容；至少两个失败账号在替代路由成功，且至少一个失败账号的相同内容有成功对照。
- 同一目标/模型/协议下，目标路由存在完整成功则不自动删除。替代线路后来也失败时，不用它更早的成功排除整体故障。
- 只有失败而无对照的线路是待核查候选，不冒称供应商已确认根因；自动新增绑定避开它，已有账号冷却和重放预算不放宽。
- 超时、取消、CONNECT 拒绝、普通 405、3009、截断错误体、缺消息 ID、无 SSE 终帧、错误目标、3xx、鉴权/头体不一致都不能补足删除证据。注入客户端记为 `custom_client`，不冒称真实直连。
- 证据容量上限 4,096 条。有效窗口被截断后，暂停新删除判定至丢弃证据过期；不能通过挤出矛盾成功再宣称没有矛盾。

规则成立后立即进入 `retiring`，不再发放新许可，然后以事务提交禁止记录、配置删除、账号改派、直连等待和订阅状态。删除失败明确保留阻断并有界重试；意图日志与 SQLite 支持恢复，不把失败操作报告为删除成功。已取得许可的在途流不因删配置而重放。

规范化身份合并同一路由别名，但保留代理认证分区。代理配置、账号凭据及绑定分别有代次；旧探测/旧 HTTP/旧登录回调不能删除或惩罚新版本。巡检、断流、计费端点及新号双次空额度保留各自判据，不混作模型 3012。

## 3. 全入口和直连

后台新增/导入/批量、CLI、OAuth 预选/补线/收尾、模型同步/异步、额度/领取、手工删除后的改派、巡检、断流、新号空额度清理及订阅提交，共用 Store 准入与事务接口。非模型客户端逐次真实派发复核；模型单次许可不自动跟随重定向。

- 无合格代理时允许自动直连，明确记录 `direct_fallback` 与等待自动补绑状态。
- 新代理新增或启用时，只给仍在等待集合且身份/人工意图未变的账号补绑。
- 人工直连、手工代理和异步强制直连不被自动补绑覆盖；旧版本空绑定不猜测人工意图。
- 手工无效/退役裸 URL 明确返回路由不可用，不能悄悄换代理或直连；未取得许可不记账号故障。
- 严格禁止记录独立持久化，不在 24 小时后自动复活。改名称、配置 ID、订阅来源或重启都不能绕过。
- 只支持单进程独占数据库的部署边界；没有实现多副本共享许可或集群即时删除。

## 4. 协议与归因

| 项目 | 实现与保留条件 |
| --- | --- |
| `query-source` | 大小写不敏感读取；合法单值可选，缺失不造 `main_turn`，未知 `x-zcode-*` 仍过滤 |
| desktop fallback | 首个固定前缀不加缓存；后续稳定块保留缓存；只对网关生成部分追加真实的无 Gen UI 能力说明 |
| 调用者上下文 | 官方完整 system、显式空值、消息内 system/MCS 及调用者工具仍保留；并发副本互不污染 |
| 透明 ID 生命周期 | 合法 session/trace/query 依既有规范保留；缺失按契约生成，每次真实尝试刷新 request ID；不全局重写用户身份 |
| 异步 | 入队冻结版本化的五字段逻辑归因，旧内存票据惰性兼容；不存 Authorization/Cookie/整份头；终态不再次派发 |
| OpenAI/Responses | 只允许合法正文 session 来源，不自动转发任意 metadata；缺消息 ID 的响应不算完整成功 |
| 诊断 | 入站存在性与限时 HMAC、出站归因及派发代次分开；诊断密钥不进入上游/磁盘；私有判定引用不复用到期日志密钥 |
| 非模型 | 按接口区分来源头、目标及认证；详见[接口契约](analysis-nonmodel-contract-v3-20261014.md) |

异步队列原本就是进程内队列；本次没有新增跨重启持久化队列，也不把序列化快照回归称为已实现持久队列恢复。没有用清空运行队列或真实数据规避兼容测试。

## 5. 跨层重试与 New API

同步首次耗尽风险预算的 405、后续本地 `risk_control_cooldown` 503：保留原始错误正文及状态，以 `Retry-After` 和 `X-Zcode2api-Retry-Policy: wait_same_gateway` 表达真实剩余等待。查询等待不续期，其他普通 503/3009 不继承该限制。

异步接受后保持 HTTP 200，通过错误事件的 `details.retry_policy` / `retry_after_seconds` 表达，不回写已经发送的 HTTP 状态。

New API **不是网关加字段就自动兼容**。本仓库提供固定 rc.41 SHA 的默认关闭兼容补丁、五字段 HeaderOverride 配置与真实包合成回归，见[消费端说明](analysis-newapi-retry-contract-v3-20261014.md)。实际生产版本、渠道配置和部署还需另行核对；本项目 Release 不会自动升级 New API。

## 6. 运维与回滚

以下均由既有管理员鉴权保护；前端现有配置/账号管理保持兼容。请求示例只使用占位变量，不包含实际密钥。

- `GET /admin/api/proxies/strict`：规则、禁止记录、证据计数、等待数、在途许可、恢复/容量状态及审计摘要。
- `PUT /admin/api/settings`，正文 `{"strict_proxy_enabled":false}`：仅停止新判定，不取消既有禁止记录、退役流程、账号冷却或重放保护。
- `POST /admin/api/proxies/strict/recover`：尝试恢复未提交的删除事务，不重新创建代理。
- `POST /admin/api/proxies/strict/blocks/{identity}/unblock`：提供当前 `decision_id` 和 `revalidated:true`，表示管理员已经完成独立复核。陈旧决定拒绝；接口本身不发真实模型探测，也不自动重建代理/旧绑定。

解除不是整库回滚。不能直接回退到无法识别新禁止状态的老版本并重新导入已淘汰路由；应使用保留准入保护的修复版本，或仅关闭新判定。

## 7. 验收与有意保留的门槛

所有自动化只在 GitHub Actions：工作流检查、前端检查/测试/产物一致性、Go build/vet/全量测试/重复回归/race、真实 SDK、多平台交叉编译、Docker、固定 New API 原版/补丁合同，以及 Windows 日志替换专项。发布继续复用完整 CI，全部通过后才生成附件和双架构镜像。

以下仍是设计明确要求另行取证或决策的事项，不标作“已上线修复”：

1. 可信 CallerScope 未建立前，不默认启用托管身份或跨客户端软粘号；不以共享 GatewayKey/IP/UA/正文摘要冒充用户范围。
2. 没有真实 TLS/头顺序/压缩协商/出口 IP 全链路证据，不盲改传输栈，不声称可保证供应商接受请求。
3. 输出上限、工具数量、媒体能力及其他 provider 签名属于独立能力边界，不统一伪造。
4. 生产 New API 版本与配置、严格策略部署和实际服务器镜像验收另行执行；本次未操作生产环境。

这些是显式边界，不以旧 CI、单一通过任务或本文代替最终提交验收。
