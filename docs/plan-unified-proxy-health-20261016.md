# 统一代理健康巡检实施计划

日期：2026-10-16（Asia/Shanghai）。基线：`2a739a6` / `v2.10.8-go`。用户已批准计划制定、实施、推送和补丁发布。

## 目标与统一契约

以同一个巡检管理器和代理页配置入口承接原网络巡检与账号模型巡检。保留两个独立预算层：网络层无需账号、无模型 token 消耗、并发最多 8；模型层仍为 5.3f、专用账号、并发 1–2、已有冷却和请求预算。

网络首次异常只能成为待复核，不删除；延迟独立复测仍异常且健康参考／无凭据直连成功，才能按策略处理。复测恢复则保留；参考也异常则保留全部相关线路。此结论不等于供应商确认封禁 IP。

## 范围与默认值

- 网络周期扫描动态读取全部启用代理，新增、启用及订阅补充的线路自动进入后续轮次。
- 网络检查沿用主模型域、备用模型域和计费域的 origin 去重、六秒单目标时限、CDN/WAF 标记及逐目标耗时；同源网络探针也供原手动检测使用。
- 网络首轮失败后默认 10 秒再复核，间隔可配置 1–300 秒；一批最长五分钟，超时／取消不提交删除。
- 第二轮复测失败目标，并刷新至少一个其他代理参考；无合格成功参考时使用无凭据直连。已知同出口组不能互为独立参考；网络直连不带账号，不继承模型直连开关的凭据许可。
- 初次检查通过可进入模型层；模型连接失败、超时或读体失败触发网络复核，而不是直接把账号失败等同代理故障。
- 没有合格账号只跳过模型层。网络与模型的周期可分别设置，仍属于同一管理器与同一动作模式。
- 旧单条／全部连通性测试保留只读语义，手动点击检测不悄悄升级成删除命令。新增统一“立即健康检查”入口用于完整策略流程。

## 模式与迁移

- 动作统一使用 `observe` / `auto_retire`：仅观察不因任一巡检层删除或改派；自动模式分别使用网络复核规则与原 405 严格规则。
- 保留 `enabled` 表示模型层开关；增加网络开关、网络周期、复核间隔和迁移版本。旧网络启用／周期保留为新设置的兼容别名，不再启动旧调度器。
- 原来只有网络自动巡检启用：迁移后保留网络自动处理，新增二次复核保护，不开启模型请求。
- 原模型层已启用“仅观察”而网络自动巡检开启：统一选择仅观察，后台明确提示已保守迁移。不得把模型层从观察暗改自动处置。
- 新旧管理写入口均更新同一策略代次；修改配置、线路地址／启停、账号身份、关停或重启后，旧轮次不能处理新状态。

## 执行与持久化

1. 新网络探测 Module（模块）封装无凭据 GET、重定向、拦截页和多目标汇总。Interface（调用契约）返回结构化结果，不自行删除。
2. 统一管理器维护首轮／待复核／复测／完成状态，网络时钟与 HTTP 是可替换的内部 Seam（接入位置）。测试使用本地 HTTP Adapter（接入实现）和可推进时钟。
3. Store 是配置代次、真实出站许可和删除的权威；网络确认通过后复用现有原子删除与改派事务，保留其订阅恢复策略，不冒充永久 3012 禁止。
4. 普通自动账号改派；固定业务节点受损时托管账号仍等待，不能改到取额池或直连；在途业务流不因删除配置而重放。
5. 网络摘要、首轮／复核／参考结果与决定原因可查询，记录只含去敏端点和错误类型，不保留凭据或正文。重启不复用半轮删除证据。
6. 同一线路不重复启动网络诊断；自动网络轮次与模型失败触发合并，模型预算与网络请求计数分开。

## 测试与推进

沿用已经确认的测试接入位置：管理 HTTP、统一管理器的单步执行、Store 的公开结果与路由行为、前端用户交互；不通过查询私有数组冒充真实网络验收。

1. 首次失败／复核恢复不得删除；同一线路两轮失败但参考健康才删除；真实本地 HTTP 代理回归先在远端变红。
2. 全部代理和直连都失败、WAF、不同入口、普通 401/403 可达、模型超时但浅请求成功、取消和预算超时反例。
3. 无账号／账号冷却／无额度仍能维护网络；后续新增代理自动纳入；网络通过不冒充模型成功。
4. 观察模式、兼容设置写入、配置／代理 ABA、持久化失败、重启半轮、重复触发和固定节点等待。
5. 既有模型 405、角色、预算与完整性回归全部保留；原网络测试迁移到二次复核流程，保留删除／不删除等原断言并增加首轮不删除断言。
6. 统一界面与旧端点兼容、故障层级和等待原因、输入草稿及产物一致性。
