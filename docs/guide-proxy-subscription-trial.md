# 代理订阅试运行指南

本功能将独立 proxy-checker 的合格候选接入网关，流程为“读取 JSON → 筛选 → 本机复检 → 增量入池”。它不是公共代理爬虫，也不保证模型业务成功或消除 405。

## 1. 试运行前提

- 本功能从 `v2.10.2-go` 提供，可使用对应 Release 二进制或 `ghcr.io/fujunchao/zcode2api-plus:2.10.2-go` 镜像。更早版本不会因为保存订阅地址就拥有本功能。
- 建议先在服务器上使用独立容器名、端口和空数据卷，不挂载生产账号库，不向测试实例导入账号。
- 本机开发环境不运行自动化测试。所有测试使用合成数据和本地模拟服务，在 GitHub Actions 执行。
- 真实订阅地址只保存在部署实例的管理配置中，不放进源码、文档、CI 变量或公开日志。

下面是**服务器上**隔离部署的示例，使用固定版本镜像，不覆盖生产容器或数据：

```bash
docker pull ghcr.io/fujunchao/zcode2api-plus:2.10.2-go
docker run -d --name zcode-proxy-trial --init \
  -p 127.0.0.1:3301:3000 \
  -v zcode-proxy-trial-data:/data \
  -e ZCODE_CAPTCHA_BROWSER=false \
  -e ZCODE_QUOTA_REFRESH_INTERVAL=0 \
  -e ZCODE_PROXY_HEALTH_ENABLED=false \
  ghcr.io/fujunchao/zcode2api-plus:2.10.2-go
```

通过受控隧道或管理反向代理访问该实例后台。首次生成的管理凭据只在服务器本地查看。此示例关闭已有巡检，避免观察阶段自动删除测试池中的线路；准备业务使用时再按需求开启。不要直接在生产 Compose 目录执行覆盖部署命令。

若自行构建，检出对应版本标签后可使用仓库 Dockerfile；不要用旧版镜像测试新功能。

## 2. 配置 proxy-checker

建议先使用已经修复跨浏览器仓库身份问题的版本，并确认管理页面中看到的仓库与订阅属于同一身份。

- 目标档位：`zai`。
- 自动任务检测方式：`force`，定期复测已知代理。
- 入库策略：`target_only`。
- 全局检测轮次：2。
- 检测并发初始 10～20；全量任务可能持续较久，间隔需按实际耗时调整，不重叠执行。
- 配置环境变量 `ZAI_AUX_DEEP=1`，重启后使用 ZCode 配置接口探针。Docker 用户须在服务的 `environment` 中显式传入，不能只写宿主机 .env。

需要 **JSON 订阅**，不是 TXT。路径格式示例：

```text
/api/repo/<你的仓库标识>.json?usable=1&stable=1&limit=500
```

如果目前复制的是 `.txt` 链接，可从仓库页面获取同身份的 JSON 链接；同名 `.json` 路径是否存在须以实际部署为准。原有 `exclude_socks4`、`exclude_shared_ip` 参数可以保留，但过滤过多可能没有候选。

`stable=1` 需要至少两次连续成功的入库记录，不是单次任务检测两轮便立刻满足。刚启用时订阅为空不一定是故障。

当前参考版本的 `last_ok` 在成功结果入库时写入，未必是长任务中每条线路实际被探测的精确时刻，因此接收端还会复检；不能只凭外部时间戳宣称线路此刻业务可用。

订阅输出应至少包含：

```json
[
  {
    "proxy": "http://8.8.8.8:8080",
    "target_profile": "zai",
    "usable": true,
    "aux_reachable": { "zcode": true },
    "pass_streak": 2,
    "last_ok": 1791892313000
  }
]
```

以上仅是结构示例，地址不表示真实可用代理，时间也不能拿来实际导入。实际记录必须未过期。

## 3. 网关后台操作

1. 打开“代理设置”页，展开 **配置自动补充**。
2. 输入 JSON 订阅地址并保存。完整地址不会回显；以后留空保存表示保留，勾选“清空地址”才删除。
3. 保持 **自动同步关闭**、**新增线路自动启用关闭**。
4. 点击 **预览并复检（不导入）**，检查收到、拒绝、过期、已有、暂缓、复检通过等数量和原因。
5. 预览满足预期后，点击 **立即导入** 并确认；默认最多新增 10 条，全部保持停用，不改派现有账号。
6. 在代理列表核对来源和复检时间。需要业务使用时显式启用；不要把“入库复检通过”当作完整模型/长流测试。
7. 多轮观察稳定后，才考虑开启自动同步、提高资源参数；“新增线路自动启用”只影响未来新增，不批量启用旧线路。

任务运行在后端，关闭页面不取消任务；重新展开可恢复查看。修改配置会取消旧任务。取消与提交同时发生时，以最终任务结果为准：已经提交成功的导入不会自动撤回。

## 4. 试运行默认值与扩容

| 参数 | 试运行默认值 | 后续常规配置示例 |
| --- | --- | --- |
| 同步间隔 | 10 分钟 | 15 分钟 |
| 每轮复检上限 | 50 | 200 |
| 每轮新增上限 | 10 | 50 |
| 来源线路池容量 | 50 | 200 |
| 复检并发 | 4 | 8 |
| 总任务预算 | 180 秒 | 360 秒 |
| 外部记录有效期 | 120 分钟 | 根据外部任务间隔和耗时评估，不无限延长 |

池容量包括停用的来源线路；达到容量后不再探测新候选。已收集够本轮所需数量时停止派发新探测，少量在途探测会完成。订阅任务总预算耗尽时，在提交前不会部分导入。

调整容量不会删除已有线路。源为空、超时、输出变化均不清空现有代理池。候选只接受无认证的公网 IP 字面量端点；手工管理的私人代理不受这一导入限制影响。

## 5. 禁止、暂缓与存量线路

- 人工停用、删除、改地址会保护原端点，不让订阅直接恢复；可在“管理禁止／暂缓重入”中明确解除。
- 来源自有线路被现有巡检、端点故障、断流熔断或新号规则淘汰时，暂缓 24 小时。到期仍需有效外部记录和本机复检。
- 单个账号 405 换线不会被本功能升级为全局线路封禁，原有阶梯冷却不变。
- 禁止记录到达预算时功能闭锁新增，而非静默遗忘人工操作。该极端状态需人工检查持久化状态和容量策略，不建议盲目清理有效记录。
- 存量线路继续由现有巡检和故障机制管理。本次不是全量镜像同步，不删除“订阅暂时不再出现”的线路。

## 6. 故障排查与退出

| 现象 | 检查项 |
| --- | --- |
| 不是 JSON 数组 | 是否用了 TXT 地址、登录页或中间重定向 |
| 收到 0 条 | 仓库身份是否一致、连续成功是否达到两次、过滤参数是否过严 |
| 大量门槛拒绝 | 是否使用 zai 档位、是否有 zcode 附加探测结果 |
| 大量过期 | 毫秒时间戳、服务器时钟、外部任务完成间隔 |
| 配置入口不通过 | 目标返回状态、连接超时、配置响应契约变化；查看脱敏原因 |
| 不能启动自定义上游 | 当前 origin 不匹配默认 ZCode 探针，不能用默认站点的成功代替自定义上游 |
| 通过却新增 0 条 | 是否预览、容量已满、已有重复、暂缓或提交期间发生人工变更 |
| 配置版本冲突 | 刷新页面后重试，避免覆盖另一管理员的修改 |

停止补给时关闭自动同步，必要时取消当前手动任务。删除隔离实例前先保存需要的试运行结果；不要删除或挂载生产卷。若后续不采用该功能，关闭配置即可，检测端不是网关业务请求的必需依赖。
