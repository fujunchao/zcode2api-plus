# 代理自动分配与风控换代理方案

## 目标与行为

- 新账号自动分配：仅选择启用的代理，优先空闲，否则选择绑定账号数最少的代理。同负载时按代理列表顺序选择，批量分配后立即更新计数。
- 风控换代理：沿用现有 `HTTP 405 + model.IsRiskControlBody` 判定，同步网关与异步任务共用处理入口。被拦截账号改派到其他启用代理，同样空闲优先、最少绑定兜底。
- 换代理时排除原代理 ID 和相同 URL；无其他候选时保留原绑定，不退回直连，不删除或停用原代理，不影响其余绑定账号。原本直连或使用手工代理的账号也可在风控时改派到命名代理。
- 保留风控冷却、连续命中升级失效、请求级判定和重放防护。换代理不清零风控计数，也不立即在原账号上重试。
- 新增时显式指定代理、直连或手工 URL 的行为不变；重复添加、重复导入不修改旧账号。
- 绑定数统计包含停用、失效、冷却及归档账号；只按 `ProxyID` 计数，手工 URL 不占用命名代理。

## 实施步骤

1. **Store 选线策略**：抽取最少绑定选择器，自动新增、自动登录预选和风控换代理共用。只有无启用候选或持久化失败时，新增才报告 `direct_fallback`。
2. **并发与持久化**：分配在同一 Store 锁内计算并以 SQLite 事务提交，成功后发布内存绑定。风控使用本次上游请求的账号快照比对当前代理 ID/URL，若已被其他请求或管理员改派则不覆盖。
3. **接入**：普通新增、批量新增、导入、CLI 新号使用 `AutoAssignProxies`；后台自动登录在会话创建时选定出口并保持整条登录链路一致。登录预选不预占代理，最终绑定保持该会话出口。
4. **风控入口**：统一 `MarkRiskControl` 接受账号快照，先执行原冷却逻辑，再尝试改派；改派失败不影响冷却，日志记录成功或持久化失败，不输出代理凭据。
5. **界面与文档**：更新自动分配选项和直连提示，区分“无空闲但可共享”与“无可用代理”；空闲计数包含归档账号的绑定。
6. **验证**：覆盖最少绑定、批量均衡、停用代理、持久化、并发与旧快照保护、无候选、同步/异步风控和新增/导入/登录入口；执行 Go 与前端测试、构建及静态检查。

## 兼容性

- 不修改数据库结构、账号 JSON 或管理 API 响应字段；`assigned` 包含共享分配。
- 手动删除代理的现有“空闲不足则直连”语义不变；健康检查/断流熔断的既有策略不变。
- 不增加配置开关，默认启用本次新增行为。

后续调整（2026-10-08，`v2.9.5-go`）：手动删除也统一为“空闲优先、最少绑定”，不再保留上述“空闲不足则直连”约定；只有无启用代理时才直连。详见 [删除代理重分配修复计划](plan-proxy-delete-reassignment-20261008.md)。
