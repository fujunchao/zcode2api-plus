# 新账号初始化与默认业务代理

## 设置入口

在后台 **代理 → 新账号初始化** 配置，无需编辑配置文件：

1. 先将远端服务器能够连接的本地代理节点添加到代理列表。
2. 在“默认业务代理”下拉框选择该节点。
3. 选择“全部启用节点”或自选取额节点；默认业务代理及其规范化路由别名不参与取额。
4. 按需要调整每轮节点数、单节点时限和整轮时限，然后开启并保存。
5. 确认设置页的“入池自动领取”已开启。

新策略默认关闭。默认预算为 32 个候选、单节点 120 秒、整轮 900 秒；到达任一上限后等待，不无限重试。没有取额节点时显示等待，不使用直连兜底。

## 适用账号

- 后台 OAuth 登录、粘贴 Token、批量新增中，真正首次入库且选择“自动”代理的 JWT 账号。
- CLI 新 JWT 登录共用初始化步骤；`add-account` 只登记任务，由后续 `serve` 接管，不增加隐式联网领取。
- 已有账号重登、重复添加、备份导入、纯 API Key，以及显式直连/手工指定代理的新增账号不自动接管。

“首次入库”是本系统的识别口径，不代表能验证平台账号的注册年龄。首次入库已经有可用额度时，跳过领取，直接固定绑定；既有配额明确耗尽时不作为未激活新号轮询。查询失败、余额未知或仅有套餐信息都不等于确认到账。

## 执行和进度

账号创建时即进入初始化保护，不参与正常模型调度。后台按候选执行额度查询、激活、资格预览、必要的领取与真实额度补查；确认当前可用额度后，原子绑定默认业务代理并开放正常调用。

账号页提供“初始化”筛选、当前阶段、尝试计数、目标节点和等待原因：

- **重试初始化**：启动受控的新一轮，仍遵守上游等待时间和资格限制。
- **暂停**：暂停任务，不会把临时取额出口自动当成业务出口。
- **重试绑定**：已经到账时只重试固定绑定，不再领取。
- **改用当前默认代理**：明确将等待任务的目标改为目前配置的默认节点。

领取接口成功、1003 已领过或响应丢失后，必须先复查额度。重启恢复也先核验，不能把“没收到成功响应”当成未领取。任务、尝试、到账事实和绑定保存在同一 SQLite 数据库中。

## 代理用途与人工操作

- 新号空额度不再删除共享代理，该修正不依赖新功能开关。
- 初始化请求遇到失败只记录任务结果，不因此删除共享代理或改派其他账号。
- 模型风控、真正连接故障、巡检和严格退役保持各自判据，不因开启功能而放宽。
- 固定节点失效时，托管账号等待；不会换到取额池，也不会被异步强制直连覆盖。
- 更换全局默认代理只影响后续任务，不自动迁移已有账号。
- 手动编辑账号出口会解除托管；停用、归档或修改身份会撤销旧任务执行权，迟到结果不能覆盖人工操作。
- 关闭策略或自动领取开关会暂停执行，不清零已消耗预算，也不自动恢复人工暂停的任务。

## 升级和能力范围

- 账号导出 version 1 不包含初始化任务；需要保留任务进度时备份完整数据库。
- 旧版本不认识初始化状态。回退之前先使用新版本管理入口暂停并停用未完成账号，避免旧程序把临时代理账号放入正常调度。
- 激活与计费请求固定在本次候选出口；现有验证码浏览器池不按账号代理隔离，本功能不改变该能力。
- 代理配置数量不等于独立公网 IP 数量；客户端状态和回归测试不能保证供应商发放配额，也不保证特定出口永久避免 405。
